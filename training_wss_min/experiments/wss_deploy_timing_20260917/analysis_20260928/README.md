## 2. 第一优先级：组合任务共享计算的时序漏洞

**证据非常直接。** `jobs.py:2354-2358` 只有在源任务预计算没有运行时，才把 geometry_cache 复制到新任务。B 的体场任务于 **17:36:36** 创建，此时父任务预计算直到 **17:36:44** 才结束，所以子任务没有拿到缓存。后来体场 B 段开始时仍只查自己的目录，于是重做 10.77 s 重采样和 4.97 s 形态测量。

A 的确认发生在预计算完成后，子任务则成功命中缓存。这与代码条件、两组事件及缓存命中记录一致。

本次额外读取 B 的两个缓存目录：mesh、resample、7 份 morph 和 morphvol 共 **10 个同键条目，解码后所有数组的 dtype、shape 与字节完全相同**（[对比记录](cache_comparison.json)），证实这例重算产生的是相同可复用中间结果。

推荐最小实现：子任务开始 B 段前，在源任务不再写缓存后进行一次延迟接入；只接入已原子提交、键完全一致的不可变条目。进一步可用按内容寻址的病例公共几何存储，让父/子任务读取同一个计算 future，避免复制目录和重复算。不能为等待缓存持有 `JobManager.lock`。

**收益规模**：B 例存在约 **15.7 s 的重复工作预算**，这是原耗时的量级，不是已测改动收益；实际节省取决于缓存键（特别是 atlas 端半径）、读取开销与调度。重采样可共享；壁面与体场的 atlas/法向规则不完全相同，pointgeom 和 morphology 只能在现有键一致时复用，不能强制通用。

重复上传复用中心线、另一发布包重跑和组合任务 A 段复用已经存在（`jobs.py:1738`、`:2323`）。应先完善上述路径，不要重复造一套中心线缓存并把已实现功能算作新收益。全新大网格的 35 s VMTK 才是剩余尾部；优化它要单独检查工具内部计时，不应先抽稀中心线或减平滑迭代。

## 3. 模型算子：先消除重复和同步

当前已有：eval 模式、no_grad、每模型只编码一次 support、query 分块；跨 seed 的 CPU 输入/patch memo、GPU kNN 索引 memo；发布包常驻/预加载/预热；CPU 推理线程上限 32。下面是这些优化之后的增量。

### 3.1 用病例级 GPU 输入对象代替反复搬运（P0）

`evaluate.py:54-87` 每 seed 都把相同 support/query/patch 从 numpy 再搬到设备；`input_memo.py:109-120` 命中仍复制 numpy 数组。建议部署专用 `PreparedInferenceCase`：一次构造规范化输入、支持点、query chunks、patch 和 geometry，所有同合同成员只读复用。

缓存键至少包括坐标与排序、support seed/indices、特征列表和统计、frame、patch 配置、dtype/device；不能只看病例 ID。当前 M1/X5D 特征统计文件一致，PF6/VF6 之间也一致，但两组特征合同不同，不能跨组共用规范化值。学习得到的编码特征和 FiLM/context 仍逐模型计算。

90,000 点 × 16 邻居 × (27 特征 + 3 偏移) × 4 字节约 **173 MB**，说明完整 patch 的设备复用有现实可行性，同时应提供显存预算与分块回退。不能为了缓存耗尽显存后触发整段 CPU 回退。

### 3.2 把诊断和重复校验移出 GPU 热循环（P0）

以下在 forward 中把 GPU 值转成 Python/CPU：

- `baseline_models.py:403-404,425,430-433`：残差分支 norm 和 drop-path 诊断。
- `:643`：每 SA 层 center counts；`:487`：局部 attention 邻域大小。
- `local_refinement.py:159-161`：定向邻域保留比例。
- `local_refinement.py:320-321`：每 chunk/seed 对同一 patch 做 finite 扫描并转布尔值；`:47-52` 对 geometry 重复检查。

增加部署 diagnostics 开关，只关闭不被预测使用的记录；输入 finite/shape 在 prepared case 创建时验证一次，最终输出 finite 检查保留。`last_indices` 等被后续网络消费的状态不可删除。每次同步可能很小，但多 seed × 多层 × 多 chunk 会反复打断 GPU 提交。

`evaluate.py:87` 每 chunk `.cpu()` 也会等待 GPU。输出量比 patch 小得多，可在 GPU 预分配整例输出，结束后一次回传；或用 pinned buffer 异步复制并在读取前等待对应 event。**仅加 non_blocking=True 而不管理 buffer 生命周期/同步，不构成正确实现。** 默认 FP32 的 `.float()` 通常只是 no-op，不能将删除它算成有效加速。

### 3.3 从 kNN 索引 memo 升级为几何计算计划（P0/P1）

现有 `knn_memo` 未覆盖所有重复计算：

- 固定 eval FPS（`baseline_models.py:594-613`）在每 seed 重算；各层 ball/radius 图（`:298-306`）也重算。
- local branch 反复做距离、切向架、扇区筛选、相对位置（`local_refinement.py:70-124`）。这些由几何决定。
- 插值只共享 kNN 索引，距离平方、倒数权重和归一化仍每次计算。PF6/VF6 的 QAD 在 `baseline_models.py:1802,1815-1821` 对学习特征、输入特征和坐标做三次插值。
- `knn_memo.py:39-44,69-72` 每命中要 `torch.equal` 比较，GPU 上会同步，之后还 clone 索引。

建议缓存 **FPS indices、分组 row/col、边几何、query 插值计划**。按几何合同分组，支持 PF6/VF6 只共享实际相同的部分；固定半径、nsample、排序、版本都要入键。prepared tensors 在严格只读、生命周期受控时可用已验证 identity/key，避免热路径扫描；不能对可原地变更的 tensor 仅凭 data_ptr 判等。

插值缓存保存与原程序相同的未归一化权重及分母，保持原乘加/除法次序。先把权重归一化再 scatter 在实数上相同，浮点上未必；直接缓存静态输入/坐标的插值结果也需测原 GPU scatter 抖动。FPS/radius 的跨运行确定性必须在当前 PyG/CUDA 版本验证，不能假设所有后端都逐位确定。学习特征、attention 权重、MLP 输出不能跨 seed 缓存。

### 3.4 真正值得试的算子代数优化：query-patch FiLM（P1）

M1/X5D 冻结配置是 K=16、hidden=64、mean pooling、radius_k=0。`local_refinement.py:322-326` 在邻居维度执行 FiLM 再均值：

`mean_k(h_k * (1 + gamma) + beta) = mean_k(h_k) * (1 + gamma) + beta`

gamma/beta 每个 query 共用，且 FiLM 与 pooling 之间没有非线性。因此可先归约再调制，把这一段调制的元素数降低 **16 倍**。注意 gamma/beta 的线性投影原本就按 query 计算，省的是邻居维度上的逐元素读写，并非投影也省 16 倍；整个网络也不会因此快 16 倍。

首个 Linear 输入为 `[邻居27维, query27维, 相对几何4维]`，可拆成 `Wn*n + Wq*q + Wr*r + b`。query 投影从每邻居一次降为每 query 一次，约减少首层 **43.6% MAC**（27/58 × 15/16），但更碎 GEMM/加法的实际速度须测。LayerNorm/GELU 仍必须在三项相加之后，第二层不能跨非线性随意合并。

这两项均改变浮点运算顺序，归入数值回归候选，不能声称逐位一致。只用于满足条件的 mean 单尺度分支，attention pooling 不可直接套用。

### 3.5 编译、混合精度和 ensemble 并行（P2）

- `torch.inference_mode()` 可先做低成本 A/B，但移除诊断与输入准备通常更有针对性。
- `torch.compile` 优先编译稳定的 MLP/LayerNorm/GELU 子图；kNN/radius/scatter、动态边数和 Python 布尔判断容易断图。首例编译时间、不同点数重编译、常驻内存必须计入，不只报告热运行。
- query chunk 从 16,384 试 32,768/65,536，不减点数；这不改变 query 的数学依赖，但可能改变 GEMM/归约实现、显存峰值。用固定几档和 OOM 回退，不能假定 chunk 越大越快。
- 选择性 TF32/BF16/FP16 放在上述优化之后。MLP 可以尝试低精度；邻居查询、距离、归约、坐标变换和物理量反归一化先保留现有精度。训练配置用过 AMP 不证明部署全链路低精度已验收。
- 多 seed 轴 batched GEMM/vmap 可能减少 kernel 启动，但 PyG 图算子、不同模型结构、显存以及吞吐/单例延迟必须单独处理。优先共享图与输入，再考虑并行权重计算。
- 局部 attention 已 `need_weights=False`（`baseline_models.py:480-483`），无需再把“关闭 attention 权重”当新优化。邻域仅 16/64、粗层约 32 点，不宜先假定 FlashAttention 是主收益。

## 4. 几何冷路径与体场：缓存和算子要分开看

### 4.1 隔离 CPU 微基准已确认的优化

[可复现脚本](cpu_microbench.py) 与 [原始结果](cpu_microbench.json)：master、NumPy 1.26.4、SciPy 1.15.2，同一真实 57,952 点云，warm-up 后各 3 次，读取原 float64 缓存，无模型推理。

| 算子 | 原实现中位 | 候选中位 | 数值核对 |
|---|---:|---:|---|
| 只需 caps 却构建完整 oriented cloud | 0.2077 s | **0.0911 s**（仍重算 spacing） | 全部 caps 记录完全相同 |
| 上项再复用已有 spacing | 0.2077 s | **0.0217 s** | 完全相同 |
| 只需最近 atlas row，却 map_points 全套特征 | 0.0895 s | **0.0436 s** | 本例 row 无差异 |
| k=129 查询的前 16 项 vs 独立 k=16 | — | — | 本例所有邻居索引完全一致 |

`geometry.py:74` 的完整 cloud 返回值被丢弃，实际只用 caps。`cloud.py:277-299` 却仍做全云局部面积查询、cap 拼接和新 KDTree。先直接用相同参数 `virtual_caps` 替换不必要工作，收益虽小但明确；不要将 2.28 倍的局部加速宣传成整例 2.28 倍。

PCA 需要 **包含 self 的 16 个邻居**，曲率需要 **排除 self 的 128 个邻居**（`geometry.py:39-45`、`cloud.py:58-61`）。若合并，查询 k=129，PCA 用 `[:, :16]`、曲率用 `[:, 1:129]`，避免 off-by-one。等距邻居顺序可能受 k/实现影响，本例零差异不能替代重复点/对称点的测试；保序不满足时回退原查询。

仅需 segment label 的体场候选分配可走 nearest-only（`volume_geometry.py:343` 等），最终特征仍走 k=6 原映射，保留分支歧义诊断。k=1 与 k=6 最近项在 ties 上也需保守处理。

### 4.2 补齐 volume geometry 缓存与预计算（P0）

`pipeline.precompute_geometry_cache:309` 只给壁面计算 point geometry；`volume_pipeline.py:96` 每次调用 `build_volume_case`。体场每次重复：法向、封口面、管腔候选点/精确接受、分支补样、最终坐标和映射、到壁面三角形的距离。

建议分两层：

1. 与命名独立、由网格和 atlas 几何确定的中间结果，提前计算并保留原 dtype；
2. 依赖确认映射的解剖坐标架、语义和输入特征，确认后生成并按完整 key 缓存。

整个 `build_volume_case` 目前检查已确认命名（`:381-384`），**不能直接在确认前调用并伪造已确认状态**。先拆清依赖；组合请求可在 M1 推理/导出期间计算体场几何，缩短用户关键路径。缓存要含网格、wall 点顺序、atlas table/frames/semantics、采样 seed、n_internal、几何算法版本及常数。float64 中间数组必须仍存 float64，不能为了缓存改成 float32 后再宣称精确复用。

A 例 6.0 s、B 例 12.32 s 表示这部分的当前优化预算。缓存只消除相同输入重跑的重复工作，预计算只把新病例工作提前/重叠；它们不自动降低全新病例的冷计算量。

### 4.3 真正冷启动算子候选（P1/P2）

- `make_inside_test`（`volume_geometry.py:147`）以 Python 循环逐点调用 VTK，可试 VTK 批量输入/原生循环。必须比较接受布尔数组、最终点集合和顺序；VTK 容差、射线退化和内部状态可能令“批量”与“逐点”不同，不能直接替换。
- winding 已经有线程池、预分配 float32 缓冲和严格求和顺序（`cloud.py:326`）；先 profile 当前 inside_vote/winding/exact_ray/branch_supplement 各自占比。层次 winding/近似最近邻属于分布会变的算法候选，不能再把历史 41 s 当成改写后可省的时间。
- 平滑构图和 CSR SpMM：当前 Taubin 的 W 已只建一次，20 轮双步保持原语义。可测 CSR 后端/线程与内存分配，但融合成多项式或减少迭代会改变浮点/几何，不能算无损。
- 重采样当前已有 VoxelSearch 占用计数缓存，不应再建议同一优化；热点应拆成高密度原始候选、k=2 距离、体素统计、最终排序与校准。减少六倍候选或调整 0.5 mm 会改变输入分布。
- ingest 多次计算面片面积/连通性可复用中间值，主要帮助大 STL（B 为 3.98 s），普通小例仅 0.11 s，不宜优先大改。
- 限制 NumPy/BLAS/KDTree/几何线程池的总线程预算。`workers=-1` 与后台任务并行可能超订阅；更多线程不是无条件更快。不要给每个阶段都拉满 192 核。

## 5. 流线、导出、调度：还有无模型精度代价的空间

### 流线端点重复采样（P1，新的算子机会）

流线已有向量化种子和 `ball_certified_inside`，原来避免大量 VTK 调用的优化已上线。仍可从 `streamlines.py:103-118` 看到：每步采样 current、midpoint、candidate；candidate 是下一步的 current，但其方向结果当场丢弃，下一步重新查询同一位置。

可携带 candidate 的 direction/speed/valid 到下一步，使稳定推进时 **3 次空间采样变 2 次**（理论减少约三分之一采样调用，非承诺流线整体快三分之一）。保持点的 float64 精度、active 顺序、停止判据和输出拼接；特别核查 VTK 内判的状态/退化边界，逐条逐点回归通过再启用。每点 Python list append 也可改为预分配路径数组和长度索引，但需先衡量内存和收益。

体场特征的 wall distance 排除人工端盖；流线安全球的 clearance 必须针对**含端盖的封闭表面**。这两个距离不同，不能为了复用直接互换。closed-surface locator/clearance 可在同一体场几何缓存中分别保存。

### 导出与报告（P2）

当前导出 0.4–1.2 s，优先级低于几何和推理。多字段到顶点的 KDTree/权重已经共享（`pipeline.VertexInterpolation`）；CSV 格式化已有优化，HTML 内嵌二进制数组并有 gzip/ETag，不要重复建议这些既有功能。

可测 `savez_compressed` 的压缩 CPU 时间 vs 磁盘 I/O，在缓存内部优先考虑不压缩/低压缩级别且保持 dtype 和文件内容语义；几何缓存已有可选不压缩路径。报告在线首屏与离线完整包可分阶段生成，但会改变“报告完成”产品定义，应分别报告首屏和全部导出时长；仅推迟文件输出不是计算加速。

### 调度（P1/P2）

`jobs.py:2710` 的 stage-B 锁覆盖几何、推理及导出，所以体场 CPU 几何也可能等待另一个任务的非 GPU 段。可先做组合请求的明确依赖调度：一次共用几何 → 两族输入准备 → GPU 推理串行 → CPU 导出适度并行。比简单增加所有 B 段并发更容易控制内存、CPU 超订阅和尾延迟。

推理仍需保护发布包 resident/cache、thread-local memo、进程全局 torch 线程数以及取消/原子输出。目标是单病例两份报告更早齐备，不把吞吐提高误写成单病例变快。

## 6. 精度约束与收益边界

建议先保留原发布包、点集、支持点、K、seed 数和 FP32。历史文档对几何要求逐位相同；本次用户允许“不要损失太多精度”，可将有损方案作为另一个可回退档，但当前并没有经过确认或验证的可接受误差预算。

验收分三层：

1. **精确复用/删除无用工作**：缓存读写 dtype/order/array_equal；caps/邻居/封口/accepted-mask 的严格对比；不能只看最终 R²。
2. **浮点重排**：先在同设备建立多次基线的自然 scatter 抖动，再比较优化差异；几何/采样仍保持不变。输出误差、p95/p99、峰位、各分支统计、低/高 WSS 面积和 OSI 阈值区域都要看。
3. **低精度/模型压缩**：另列误差预算；在预先固定的验证病例与尾部病例上评估，不能用反复挑 seed 的测试集结果选择快版本。与原模型一致性不能证明真实 CFD 精度，后者需要同协议真值评估。

RRT = 1/[TAWSS·(1−2OSI)] 的相对敏感度约为 `−δTAWSS/TAWSS + 2δOSI/(1−2OSI)`，OSI 接近 0.5 时会放大误差。速度还需检查方向/截面流量；相对压力接近零时不用单纯逐点相对误差作唯一指标。减 seed 同时改变 ensemble 方差和质量提示，不能只看均值 R²。

**Amdahl 边界**：A·M1 已计时 B 段 5.05 s 中推理 3.26 s，即使推理快一倍，也只节省约 1.63 s（该 B 段约 32%）。A·体场 B 段 12.54 s 中推理 3.55 s，快一倍只省约 1.78 s（14%）。B·体场完整记录 78.08 s 中推理仅 4.12 s，快一倍在这个累计口径只省 2.6%。这说明不能只追求网络吞吐。

## 7. 建议实施顺序与最小验证

| 顺序 | 工作 | 主要受益场景 | 精度属性 / 当前证据 |
|---|---|---|---|
| P0-1 | 补真实墙钟、缓存状态、GPU/CPU 分项 | 所有请求 | 计量完善；源码/事件确认当前口径差异 |
| P0-2 | 子任务开始时延迟接入父任务已完成缓存 | 三头 + 体场 | 精确复用；B 例重复耗时约 15.7 s |
| P0-3 | 去诊断同步、一次校验、共享 device inputs/输出缓冲 | 新病例和重跑推理 | 候选；需要 GPU profiler + 输出回归 |
| P0-4 | 体场几何缓存与安全的前移/重叠 | 体场重跑、组合请求 | 6–12 s 当前特征预算；不能混同冷路径收益 |
| P1-1 | FPS/radius/边几何/插值计划 | 多 seed | 候选；保留图/归约合同和后端确定性验证 |
| P1-2 | caps 精简、KD 查询复用 | 壁面几何 | caps 单例已实测 0.208→0.091 s；邻居单例无差异 |
| P1-3 | 流线端点结果复用、必要时批量 VTK | 体场 | 新候选；逐点流线/accepted-mask 验收 |
| P1-4 | FiLM 均值前移、首层 query 投影拆分 | M1/X5D | 数学等价、浮点不保证相同 |
| P2 | selective compile、chunk 调整、TF32/BF16、压缩/蒸馏 | 前述优化后仍受限的场景 | 必须测冷/热收益与任务精度 |

最小验证使用固定的部署副本：普通小网格、大网格、瘤囊/窄支/近壁极端，各族均覆盖；不改源 job。先控制 GPU 负载/线程、预热，再每方案重复至少 5 次给中位/P95/峰值内存；冷缓存、预计算未完成即确认、预计算已完成、同例重跑、两族组合分别报告。算子 profiler 另跑一次，不拿 profiler 时长作正式性能数值。每项有开关，逐项验证后再叠加，避免无法归因。

本次只完成审计及一例几何 CPU 微基准。P0/P1/P2 表中的生产实现、模型输出回归和整例收益均仍待实施验证；无需为得到这些建议先重训模型。
