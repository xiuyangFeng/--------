# 实验结果分析

目标是从真实产物得出可追溯的结论，并说明结论能支持什么下一步。**先按 run/config 判路线，不默认 V3，也不因代码位于 `training_wss_min/` 就判定为旧数据线。**

## 1. 锁定实验与最少上下文

先读用户给出的 run/config/实验目录；没有明确对象时，读仓库 `README.md` 和 `docs/README.md` 的当前入口，再定位对应实验跟踪。当前状态以这些入口及实际产物核实，不将本技能中的示例视作最新结论。

| 实际线索 | 路线及按需参考 |
| --- | --- |
| `training_wss_min`，配置 `data_root` 指向 `data_wss_v5/` | V5 直接 WSS 或体场；读 [v5-analysis.md](v5-analysis.md)，并用 `data.target` 区分目标 |
| `training_wss_min`，配置 `data_root` 指向 `data_wss_min/` | 旧 WSS-min；读 [v5-analysis.md](v5-analysis.md) 的产物/指标说明，再按实际配置定位历史协议；不能套 V5 split 与基线 |
| `meta.exp_id` 为 `V3P-` / `V3D-`，`outputs/field/` | V3 历史线；读 [v3-analysis.md](v3-analysis.md) |
| `outputs/wss_pinn/`，`volume_uvwp_*` | 体域 PINN 历史版本；按 run 的版本读 `wss_pinn/README.md` 与 `docs/02-推进与变更/_archive/WSS_PINN/README.md` 对应历史段落，不套 V5 或 V3 指标 |
| `outputs/wss_mri_calculator/` 或冻结算法实验目录 | velocity→WSS；读 `wss_mri_calculator/experiments/README.md` 对应版本 |
| `external_baselines/`、V1/V2 或其他路线 | 读对应目录 README、配置和实验记录，只使用其自己的协议 |

锁定一个**比较合同**：run 与对照路径、任务/目标域、数据版本与病例集合、分区、seed、checkpoint 及选择规则、采样/评估协议、单位与聚合方式。基线从本轮设计/manifest/记录确定；目录名和历史摘要中的数字只能帮助定位。

通常只读路线 README 当前段、跟踪记录相关实验块、配置和小型结果文件。需要历史因果链时再定向搜索旧记录；不要默认通读日志、整本规划或所有参考文件。

多个独立 run 或复杂诊断可并行分工：配置/数据合同核查、曲线诊断、病例与尾部分析分别产出带原始路径的证据。主 agent 统一比较协议、处理矛盾并形成结论；共享报告/跟踪表只由一个写者更新。简单单 run 问题直接处理。

## 2. 先核实，再比较

1. **状态与完整性**：检查 history 的末轮、连续性与有限值，现有训练总结/验收文件、评估病例数和 checkpoint 身份。作业退出或文件存在不等于训练/评估全部完成；远端未核实的状态要标明观察时间。
2. **真实结果**：逐 run 读取 JSON/CSV；缺字段记为缺失，不用旧文档补值，不把缺失当零。已有汇总表用于导航和交叉检查，正式结论可追溯到原始指标路径。
3. **可比性**：配置 diff 与数据/统计来源一起查。跨 split、数据重建、seed、采样、目标空间、checkpoint 规则的差异必须列为混杂；不能只凭模型名相同就宣称单变量。
4. **结果层次**：主指标 + 必要的 MAE/尾部/病例组指标；同时看整体改善是否由少数病例驱动。病例等权场 R²、病例 R² 均值、pooled R² 分开写；拟合 R² 必须连同斜率、截距和原始 R² 报告。
5. **原因链**：配置/实现差异 → 曲线或病例证据 → 机制假设 → 可验证下一步。把实测事实、支持的推断、尚待验证的解释分开。

已有评估/预测文件的读取、汇总与低成本绘图可在分析任务范围内直接完成；缺少预测、需重新访问测试集或启动耗时计算时，先完成现有证据分析，再按用户已授权范围和该路线门禁处理。不要把“分析结果”扩展成新训练、批量推理或冻结算法调参。

## 3. 曲线、统计与判定

- 优先复用实际路线的绘图/汇总脚本；先核实其参数和输入 schema。V3 的 `summary.json/history.csv` 脚本不能直接读取 WSS-min 的 `metrics.json/history.jsonl`。
- 只画有助于判断的问题：收敛/异常看 loss 与实际选择信号；比较病例改善看配对差值；诊断尾部看高 WSS、校准和最差病例。原始点云指标与插值可视化指标保持区分。
- 只有预注册判据存在时才按它写 Go/No-Go；缺少判据时给出“当前证据支持/未支持”的结论，不事后编阈值。开发暴露集、单 seed 和自适应挑选产生的限制随结论一起报告。
- 存在多 seed 时按相同协议比较分布；单 seed 的病例配对统计只描述病例差异，不能代替训练随机性验证。
- 选模依据是已冻结的训练/验证协议；不能从 best/last 的 test 读数重新选 checkpoint。历史对照与同期控制分别展示，解释控制漂移后再估计增益。

下一步来自用户目标、该轮未关闭问题与本次证据。可提出清单外的合理假设，并标明验证成本与关键区分证据；历史冻结方案不会自动获得执行授权。

## 4. 交付与回填

回答先给结论与适用范围，随后给必要的指标对照、曲线/病例证据、原因与下一步；附原始指标和报告/图件路径。简单单 run 分析不强制套完整长模板。

| 路线 | 回填责任 |
| --- | --- |
| V5 | 对应 `training_wss_min/experiments/<批次>/` 报告及 所属块的实验跟踪或矩阵（导航 `docs/02-推进与变更/README.md`；§0–§32 在 `00-V5设计与历史跟踪/` 历史卷）对应章节；有新结论/产物时在 WSS 专用推进记录文首记一条 |
| 旧 WSS-min / PINN / velocity→WSS | 对应路线的活动记录 + `docs/02-推进与变更/WSS最小化_代码修改与实验推进记录.md`；冻结历史表不续写成当前计划 |
| V3 | 见 [v3-analysis.md](v3-analysis.md) 的历史回填边界 |
| 外部 baseline / 其他 | 该路线专用记录；不混入 V3 母版实验表 |

同一结果已有完整记录时补充实质性变化，避免重复追加；用户明确只读/不落盘时按用户要求。路线结论变化才更新上层 README，工作簿只在用户要求正式入账或既定交付范围包含时更新。

结束前核对：主表数字能回到原始字段；分区/单位/聚合/checkpoint 无混用；图件确实存在；缺失与未完成部分已说明；记录未将开发筛选写成独立确认。
