## 0. 结论先行

V3P 当前不是“还差一个小超参”的状态，而是进入了**表示与信息瓶颈平台期**。截至 2026-06-30，I6-diag、I6-a、E-J、G4-c 的证据共同指向：

1. `wss_r2_wss` 稳定平台在 **0.42-0.45**，I6-diag 为 **0.429**，I6-a 最高 **0.446** 但未过 Go。
2. 压力仍然可学，I6-diag `r2_p=0.930`，E-J `r2_p=0.935`，但“压力梯度 oracle 有信号”未能迁移成真实网络收益。
3. 当前 WSS R2 主要仍由轴向/主分量贡献；横向/周向分量仍接近 0，I2-PC local intrinsic 也没有真正打开 circ 分量。
4. G4-c 已证明 patch 内可拟合，但 **2D patch -> merged 3D** 在 CHEN fast 病例不稳定，不能继续写成全量训练方向。
5. M-N 论文/汇报叙事可以收口；M-E 工程部署还没有可信路线，不能再用 AsymW / loss / 小 head / G4-c 全量长训硬冲。
6. 数据少与病例差异大可能是平台期的重要原因，但不能简单把 V3D 全量混入长训；必须先区分“补覆盖”与“引入域噪声”。

**后续调整原则**：先做 0 重训 oracles 和标签/目标审计，确认“还能从哪里拿信息”；只有 oracle 同时解释 L1 点级、L2 hotspot、L3 病例下限中的至少两层，才开 GPU probe。

## 2. 为什么目前精度升不上去

### 2.1 不是单一 loss 权重问题

从 AsymW、WSS-only、PWeak、MagCons、Rank loss 到 EMA/SWA/ensemble，结果都没有稳定越过平台。I6-a 的 +0.017 说明训练动力学有边际空间，但幅度太小，无法解释 M-E 目标所需的巨大缺口。

### 2.2 当前输入缺少决定横向 WSS 的条件

`wss_x/y` 或 local circ 分量长期接近 0，说明网络不是简单“学得不够久”，而是缺少能稳定决定二次流、分叉旋涡、上游几何历史和入口剖面扰动的信息。继续在同一局部 kNN 点云上加权，会更像记忆低频轴向分量。

### 2.3 oracle 高不等于网络可用

E-J 说明 GT `|grad p|` 与 WSS 空间结构相关，但真实训练时网络没有拿到收益。这类方向后续必须拆成两步：先确认预测态特征是否仍有信号，再决定是否接入 head；不能直接把 GT oracle 写成 GPU Go。

### 2.4 G4-c 的真实瓶颈是缝合与低 occupancy 病例

G4-c 在 GUO 上能把 merged 拉到 0.633，但 CHEN fast 只到 0.406，差 Go 线 0.007。这个结果很重要：它说明 2D/patch 不是完全错，但当前 patch sampling、overlap merging、fast 病例 coverage 还不足以成为全量路线。

### 2.5 数据覆盖不足与域异质性可能同时存在

V3P AG-only 的训练病例覆盖有限，而 WSS 对分叉、曲率、入口剖面、流量尺度和局部高频结构都敏感，因此“数据少”确实可能压低上限。另一方面，V3D 引入 AAA/AG/ILO 后不是单纯增加样本，而是引入更强域差异；过去 V3D val15 和 domain norm 没有抬升 WSS，说明全量混训可能把差异压成噪声，导致训练更慢且指标更差。

后续数据路线应先回答：V3D 是在补 AG-only 的几何/流态覆盖，还是在引入与 AG 测试集不一致的域偏移？

## 3. 下一轮更值得做的想法

### Idea A：标签与目标地板审计

**要回答的问题**：M-E 里 `R2_wss >= 0.85` 是否被标签噪声、壁面映射、单位/粘度、法向、时间步自一致性允许？

**先做 0 重训**：

- 壁面 mask、法向连续性、WSS 单位/粘度、fast/slow 分布、case-level p95 长尾审计。
- 同一病例相邻时间步或不同插值/回插链的 WSS self-consistency proxy。
- 对 `tau`、`log(tau+eps)`、`Cf`、per-case percentile target 做低秩重构与误差结构比较。

**Go 判据**：若 target 变换或剔除/修复异常病例后，oracle 重构上限明显提高且 hotspot 不丢，才进入新训练目标；否则先降低 M-E 目标表述，转 G5/可信区间。

### Idea B：流向-跨流向物理坐标 + normal-ray 管算子

**要回答的问题**：不是预测 global xyz，也不是泛化 local PCA，而是预测物理可解释的 `streamwise / cross-stream` WSS 分量，能不能打开横向分量？

**先做 0 重训**：

- 用中心线切向投影到壁面切平面，定义 `t_stream` 与 `t_cross`。
- 把 GT WSS 转成 stream/cross 分量，跑线性/GBDT probe 与低秩重构。
- 若有近壁速度，沿内法向 ray 采样固定 `delta`，计算 `mu * u_t(delta) / delta` proxy 与 GT WSS 的 Spearman/R2。

**Go 判据**：stream/cross 的 cross 分量 R2 比 global x/y 或 local circ 高 **>=0.10**，或 normal-ray proxy Spearman **>0.65**，再立项新 target/head。

### Idea C：分支 circuit latent 与上游历史 token

**要回答的问题**：CHEN/fast 和高 WSS hotspot 失败，是否来自模型缺少上游几何历史、分支流量分配和局部阻力信息？

**先做 0 重训**：

- 以 centerline branch 为单位，统计 `R_branch`、曲率积分、分叉角、入口/出口 BC proxy、branch mean/p95 WSS。
- 做 `per-case`、`per-branch` 去尺度：比较原始 WSS、病例尺度、分支尺度后的 pooled/L3 R2。
- 训练或拟合一个 branch-level error predictor，检查当前高误差是否集中在特定 `Q/R^3`、分叉角或上游曲率簇。

**Go 判据**：per-branch 去尺度显著减少病例间方差，或 branch-level 特征解释 **>30%** WSS 平方误差，才上 centerline token / branch circuit latent。

### Idea D：模式-尺度拆分，而不是直接回归绝对 WSS

**要回答的问题**：当前模型是否已经学到相对分布/排序，但幅值标定失败？

**先做 0 重训**：

- 把 `WSS(x,t)` 拆成 `S_case` 或 `S_branch` 乘以无量纲模式 `w_hat(x,t)`。
- 用 val 拟合单调校准器，test 只评一次，确认是幅值问题还是空间模式问题。
- 对 `w_hat` 做 top-k Dice、p95 Spearman、ROI RMSE，避免只看 pooled R2。

**Go 判据**：模式指标明显优于绝对值指标，且 `S_case/S_branch` 能被 BC/几何稳定预测，再做 mode-scale 双头；否则不要用后处理校准冒充模型突破。

### Idea E：曲面谱 / 局部 patch 的混合表示

**要回答的问题**：G4-c 的 patch 成功能否保留，但避免 merged 3D 缝合不稳？

**先做 0 重训**：

- 对每个 case 壁面图做 Laplace-Beltrami 或图 Laplacian 谱重构，报 20/50/100 模态的 R2、top-k Dice、hotspot 保真。
- 对 CHEN/FAN 等低 occupancy 或 fast 病例单独看谱重构上限，判断是采样/缝合问题还是目标本身高频不可重构。
- 若谱重构上限高，把谱正则或 peak-preserving merge 作为 G4-c 的后续，而不是直接重启全量 PatchConvWSS。

**Go 判据**：50 模态重构 R2 **>0.65** 且 top-k hotspot 不丢，才做谱正则/peak-preserving merge；否则 G4-c 保持封口。

### Idea F：主动选数与不确定性

**要回答的问题**：如果表示、目标、标签都审计过仍卡住，是不是训练集覆盖不足？

**先做 0 重训**：

- 用三 seed、dropout 或小 ensemble 估 uncertainty，并和真实 absolute error 做校准曲线。
- 按几何簇、Re/Wo、branch scale、fast/slow、hotspot residual 找最能解释误差的病例类型。
- 给 TODO-1 数据扩池一个主动选数清单，而不是盲目补全。

**Go 判据**：uncertainty 能召回 **>70%** 高误差区域，或 top residual 几何簇解释 **>30%** 误差，才推动新 CFD / 新数据。

### Idea G：V3D-lite 数据补充与域异质性控制

**要回答的问题**：V3P 平台期是否来自 AG-only 覆盖不足？如果用 V3D 补数据，哪些病例是在补有效覆盖，哪些病例只会增加域噪声与训练成本？

**先做 0 重训 / 低成本审计**：

- 对 AAA/AG/ILO 分别统计 WSS p50/p95/p99、压力范围、入口 BC / 流量 proxy、半径、曲率、分叉数、中心线长度、fast/slow 或时间相位覆盖。
- 用现有 I6-diag / post5463 预测误差，把 AG 失败病例（如 CHEN/fast、高 WSS hotspot 低估病例）映射到上述几何-流态空间，检查 V3D 中是否存在相近病例。
- 构建三个候选数据池：`AG-only`、`AG + near-domain V3D-lite`、`full V3D`。其中 V3D-lite 只选与 AG 失败簇相近、标签质量通过 QA、WSS 分布不极端偏移的病例。
- 先做数据统计与小模型/线性 probe，不直接全量训练；若要训练，只跑 seed1 短训或较少时间步，目标是判断“加数据方向”，不是刷最终分。

**训练成本控制**：

- 第一轮只跑 `V3D-lite`，不要直接 full V3D。
- 优先减少时间步或病例数，固定同一 test 口径；必要时用 `AG-only -> AG+near-domain -> full V3D` 三档短训。
- 若 V3D-lite 有正信号，再考虑 `V3D pretrain -> AG fine-tune`，而不是从头混合长训。
- full V3D 只有在 V3D-lite 证明有效且训练成本可控后才进入队列。

**Go 判据**：

- V3D-lite 相对 AG-only 在 CHEN/fast/high-WSS hotspot 至少一类失败病例上改善，且 AG test 不退化。
- 分域指标不能出现某一域 Strong No-Go；若全局 R2 小涨但 AG 或 fast 子集退化，不升路线。
- 若 V3D-lite 无收益，优先判定平台期不是“盲目扩数据”能解决的问题，回到 target / 坐标系 / branch condition。

## 5. 后续你该怎么调整

1. **先把目标说清楚**：如果是论文/阶段汇报，按 G5 收口；如果是工程替代 CFD，必须接受先做审计/oracle，短期不要期待训练 R2 大涨。
2. **把每个新想法写成一个可证伪问题**：不再写“可能有物理意义”，而是写“它解决 L1/L2/L3 哪一层，过线阈值是多少”。
3. **优先看横向分量和 hotspot**：只看 pooled `wss_r2_wss` 会被轴向低频分量掩盖。
4. **对 CHEN/FAN/fast 病例单独建失败档案**：G4-c 暴露的 merged instability 很可能也是整体精度平台的缩影。
5. **把数据扩池变成主动选数**：先用 error/uncertainty/branch-scale 选最有信息量的病例，再决定补 CFD，而不是平均扩。
6. **V3D 先做 lite，不要全量硬训**：先用分布审计挑 near-domain 病例，证明它能改善 AG 失败簇，再考虑预训练或 full V3D。

## 6. 本轮文档判读

当前最像“真瓶颈”的不是模型容量，而是：

- 目标坐标系没有对齐流体物理本征方向；
- 缺少上游/分支/入口剖面对横向 WSS 的决定性条件；
- 绝对幅值、空间模式、hotspot 定位被混在同一个回归目标里；
- 部分高频 WSS 可能受标签/插值/采样自一致性限制。
- AG-only 数据覆盖可能不足，但 V3D 域异质性也可能带来训练噪声和成本膨胀。

因此下一轮不应再从训练脚本开刀，而应从 **target、坐标系、branch condition、标签地板、主动选数、V3D-lite 数据审计** 六件事开刀。
