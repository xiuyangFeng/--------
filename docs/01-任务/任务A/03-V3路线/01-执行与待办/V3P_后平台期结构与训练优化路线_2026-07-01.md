## 0. 本版修订原则

上一版把 K1/K3/K4/K5/K6/K7 都写成后续候选，但复核历史文档后可以确认：其中很多方向并不是新方向，而是已经在路径 A-F、路径 G、路径 I、M-E oracle、平台期 Idea A-G 中被验证过，部分已经有 GPU No-Go。

因此本文改成 **证据优先路线图**：

1. 先列“已经做过、不能换名重跑”的方向。
2. 再列“有弱信号但不能直接开 GPU”的方向。
3. 最后只保留“当前真正可执行”的下一步。

**当前唯一可执行主线**：K1-lite branch/topology 特征探针已经由 CPU error predictor 放行，并已提交 Job **5886**。但它与历史 `dist_to_bifurcation + branch_id` No-Go 很近，因此只能当作 **短训验证**，不能自动升级为 full dual-graph。

## 2. 为什么精度没有上去

### 2.1 不是“模型还没调好”

路径 A-F、G、I 和 M-E oracle 已经覆盖了 loss 权重、local frame、mag target、近壁梯度、多 k、压力耦合、预训练、2D 展开、标定、时间谐波、WSS-only、冻结训练等主要方向。多数结果落在 **0.40-0.45** 或更低，说明当前瓶颈不是一个未调到的超参。

### 2.2 不是单纯“数据再补一点”

J4 near-domain +1 和 J5 +6 AAA 都没有破平台。J5 对 fast/CHEN 有局部改善，但全 test 只有 **+0.004**，不足以支撑 J6 或 full V3D。数据扩充仍可做 CPU 采购和 QA，但不能作为当前精度突破主线。

### 2.3 最大问题是“当前输入条件下的 WSS 信息不可充分恢复”

WSS 的难点集中在横向/周向、hotspot、fast/CHEN、merged 3D 稳定性。压力和低频轴向趋势可学，但横向剪切依赖上游流量分配、分支拓扑、局部二次流、近壁梯度和边界条件细节。当前 FieldPointNeXt + kNN + direct WSS head 没有稳定通道把这些信息转成点级 WSS。

### 2.4 许多 oracle 是“GT 相关”，不是“推理可用”

E-J、POD、时间谐波、G4 patch 都出现过 oracle 或单 case 正信号，但 followup 或 GPU 证明不能稳定迁移。这是后续路线最重要的纪律：**任何新方向必须证明推理时可用，不接受只看 GT oracle 的 GPU Go。**

## 3. 当前唯一主线：K1-lite 分支/拓扑探针

### 3.1 为什么 K1 仍可尝试

2026-07-01 CPU 探针显示：

| 探针 | 判读 | 关键数 |
| --- | --- | --- |
| K1 branch/topology error | Go | `branch_error_explained_frac=0.683` |
| K3 mode-scale audit | No-Go | Δmode-abs **-0.065** |
| K5 temporal/BC | No-Go | BC explained **-0.43** |

这说明当前误差和分支/拓扑特征存在较强关系，而不是简单幅值标定或时间相位问题。

### 3.2 为什么不能把 K1 写成 full dual-graph 主线

历史上 `dist_to_bifurcation + branch_id + dist_to_wall` 已经跑过 G01+G04 / GeomB1，结果 **0.396**，Pa p95 还退化。因此 K1-lite 不是“第一次加 branch 特征”，它只是用新的 CPU error predictor 给了一个更具体的重试理由。

**结论**：

- 当前只允许跑已提交的 `V3P-K1-BranchFeat-MixedProbe-post5463_seed1`（Job **5886**）。
- 若 5886 不过 Go，不直接升级 full dual-graph。
- 若 5886 过 Go，full dual-graph 仍需单独立项，且必须说明它比 GeomB1 / G01+G04 新在哪里。

### 3.3 5886 判读门禁

| 层 | Go | No-Go |
| --- | --- | --- |
| pooled WSS | `wss_r2_wss ≥ 0.459`（I6-diag 0.429 + 0.03） | <0.459 |
| L3 | CHEN/fast 不退化，最好有明确改善 | pooled 小涨但 CHEN/fast 退化 |
| hotspot | top-k / p95 至少不退 | hotspot 继续系统性偏低 |
| 压力 | `r2_p` 不明显退化 | WSS 小涨靠牺牲压力 |
| 归因 | branch/topology 特征贡献可解释 | 与旧 GeomB1 无法区分 |

## 4. 5886 之后的分支

### 4.1 如果 5886 Go

只允许进入 **K1-2：真正结构化分支模型设计**，不是直接全量长训。

K1-2 必须满足：

| 要求 | 说明 |
| --- | --- |
| 与旧 GeomB1 区分 | 不能只是 `branch_id/dist_to_bifurcation` concat |
| 显式拓扑 | branch graph 有上下游边、分叉角、半径、路径长度或阻力 proxy |
| 跨图交互 | wall point 读取 branch token，或 branch token 调制 WSS head |
| 推理可得 | 不使用 GT WSS / GT pressure gradient |
| 先短训 | seed1 40ep；过 L1/L2/L3 才扩 seed |

可考虑的结构：

- branch-token FiLM：branch token 调制 wall head 的最后几层；
- wall-branch cross-attention：wall query 读取最近 branch/upstream token；
- branch-scale auxiliary：只预测 branch mean/p95 WSS，不直接改逐点 head，先验证统计任务。

### 4.2 如果 5886 弱 No-Go

不扩 seed。保留 K1 为“误差解释成立但简单特征注入失败”。下一步只做低成本诊断：

1. 对 5886 做 L3 / CHEN / hotspot error decomposition。
2. 比较 K1 特征对 train/val/test 的贡献，排除 val 假阳性。
3. 若只有 fast/CHEN 改善但 pooled 不升，可转 G5 失败病例叙事，不写成 M-E 突破。

### 4.3 如果 5886 强 No-Go

关闭 K1-lite；full dual-graph 默认不立项。后续 M-E 内部训练暂停，转外部 mesh/operator baseline 或数据 QA。

## 6. 可以保留为低成本工作的事项

### 6.1 QA / target 地板复核

适合 CPU，不适合 GPU：

- 13 例 basis invalid 个案复核；
- WSS 全零 / local frame 异常 denylist 复核；
- 修复后重跑 Idea A target audit；
- 若 target 变换仍只在 QA 未过情况下有信号，不立项训练。

### 6.2 G4-c stitching 失败归因

适合后处理，不适合全量训练：

- CHEN patch grid 高但 merged 不稳，优先查 patch overlap、权重融合、low occupancy 区域；
- 若能用纯后处理把 CHEN merged 稳定推过门禁，再考虑新 G4-c 设计；
- 不在当前结果下直接 full probe。

### 6.3 外部 mesh/operator baseline

这是后续较有价值的“换家族”方向，但必须与 V3 内部优化分表：

- MeshGraphNet / mesh-aware processor：真实表面/体网格拓扑，不等同于 MultiK；
- surface operator / GNO / GINO：壁面连续算子，不等同于 point head；
- Point Transformer v3：只有在长程注意力和层次结构明确不同于当前 PointNeXt 时才值得试。

外部 baseline 的目的先是确认“是否有别的模型家族能过 0.43”，不是马上替代 V3 母版。

## 8. 一句话结论

当前不是“还有一堆新模型可以试”的阶段，而是“绝大多数直觉方向已经被证据压缩掉”的阶段。后续内部训练只剩 **K1-lite 5886** 这一条短训验证；它若不能把 branch/topology 的 CPU 解释力迁移成 test WSS/L3/hotspot 收益，就应该停止在 FieldPointNeXt 体系里继续硬冲，转向 QA、stitching 归因或外部 mesh/operator baseline。
