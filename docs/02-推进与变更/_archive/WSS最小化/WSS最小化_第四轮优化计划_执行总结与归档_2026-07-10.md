## 0. 审核后的执行结论

第四轮不应直接跳到“高斯 NLL + 新几何特征 + 6000 点”的大矩阵。当前最优顺序是：

1. **P0：先修实验协议、split 完整性和确定性实现问题。** 当前 checkpoint 指标不稳定，开发阶段仍会自动评估 test；`resample_each_epoch` 在持久 worker 下也可能没有真正生效；缺失 bundle 还会被静默跳过。若不先修，后续差异仍无法可信归因。
2. **P1：先做低风险训练信号修复。** 把 target-weight 从 batch 分位改为 train-only 固定阈值，修复 worker-safe 重采样，再比较固定 FPS 2000、多起点 FPS 2000 和 FPS 4000。
3. **P2：把“log 目标导致峰值压缩”降级为待验证假设。** 先做残差/后处理校准 Gate-0，再决定是否做 raw-space 辅助损失；高斯 NLL 只保留为条件触发的探索项，不作为默认主线。
4. **P3：局部几何走内在标量，不直接塞全局法向分量。** PointNeXt 已通过相对坐标学习局部形状；新增特征必须证明提供了增量信息，并处理法向符号、局部坐标系扭转和分支不连续问题。
5. **P4：最终做多 seed、重复开发划分和病例级 bootstrap。** 当前 `test16` 已被 27 个实验反复查看，只能称为“历史比较集”，不能再宣称是完全未触碰的确认性测试集。

第四轮最值得解决的问题不是模型容量，而是：

- 开发/选模协议是否稳定；
- 训练点与高 WSS 标签是否被充分覆盖；
- 尾部欠估来自目标表示、缺失信息还是普通的回归均值化；
- 新特征是否真的超出 PointNeXt 从 `xyz` 相对邻域已经能学到的内容。

## 2. 数据与证据边界

### 2.1 已确认的数据事实

- split：train 53 / val 8 / test 16 / excluded 9 / pending 1，共 77 个 included bundle。
- 非有限坐标/WSS/curvature：0；peak WSS 零值率：0；`local_radius<=0`：0。
- 坐标逐病例保形归一化，77 例 `max|coord|=1`。
- WSS stats：train-only、peak-only，53 例 / 711412 点；log mean/std=`1.1595/1.0907`，raw p99/max=`32.60/220.80`。
- 第三轮 target-weight 三 seed：test `R²_field=0.225±0.034`、`R²_casemean=0.212±0.027`、high-WSS `R²=-1.531±0.167`、top10 比 `0.357±0.037`。
- 固定 2000 点约覆盖每个训练病例壁面点的 `15.35%`（病例均值；范围约 `9.32%–20.61%`）。当前尚未证明被选点对 high-WSS 区域的覆盖是否足够。

### 2.2 val 分布：需要重构开发协议，但不能据此修改 test

val 的病例 mean WSS 与 mean log-z 均偏低，足以说明单个 8 例 val 对模型排序很脆弱；但不应把 test 标签拿来反向设计新 val。

第四轮开发集只使用原 train+val 的 61 例：

- 建立版本化 `split_AG_wss_min_v2_dev*.json`；
- 按 fast/slow、病例 mean log-WSS、p99 WSS 和点数/尺度分层；
- 至少准备 3 个固定 repeated-holdout 开发划分；
- 每个划分的 WSS stats 必须只由该划分 train 部分重算，不能继续复用原 53 例全局 stats；
- feature stats 已由 `train.py` 按训练病例计算，WSS stats 也应改为配置化/按 fold 生成并随 run 快照保存。

### 2.3 inlet-flow 与 `coord_scale`

- `vf-in` 在当前 77 例中几乎不变，因此从第四轮主矩阵移除。
- `coord_scale` 与 train 病例 mean/p99 WSS 的相关性约 `-0.12/+0.11`，且 `local_radius` 已保留物理尺度信息，预期增量有限。
- `coord_scale` 最多保留一个低成本单变量 Gate-0；若无 val 稳定增益，立即 No-Go。
- 只有未来数据包含真实可变的流量、血压、黏度或个体边界条件时，BC 分支才重新升为主线。

### 2.4 审计资产本身的工程问题

`assets_第四轮/audit_bundles.py` 当前把仓库根和 CSV 输出路径写死，其中输出仍指向一次性 `/tmp/claude-.../scratchpad/`。因此它是本轮证据脚本快照，但还不能称为“任意后续智能体可直接复跑”。第四轮正式执行前应：

- 用命令行参数或相对路径指定 root/output；
- 默认写回 `docs/02-推进与变更/assets_第四轮/audit_bundles.csv`；
- 在 CSV/日志记录 split、stats 文件和生成时间；
- 禁止读取 excluded/pending bundle 参与正式统计。

## 3. 必须先修的代码与协议问题（P0）

### 3.1 sampler 的 epoch 状态没有可靠传入 worker

现状：

- `WSSMinDataset.set_epoch(epoch)` 只修改主进程对象；
- DataLoader 默认 `num_workers=4` 且 `persistent_workers=True`；
- 持久 worker 持有独立 dataset 副本，不能假设主进程的 `epoch` 更新自动同步；
- FPS 分支还显式忽略 `resample_each_epoch` 并缓存 `_fps_order`。

因此第四轮不能只“给 FPS 加随机起点”，而应先建立 worker-safe 采样协议：

1. 最小可靠实现：开发阶段先设 `persistent_workers=False`，让每个 epoch 的 worker 读取更新后的 epoch；或使用共享 epoch 状态/自定义 sampler。
2. 对 FPS 使用确定性的 multi-start FPS pool：seed 由 `(run_seed, epoch, case_index)` 派生，避免不可复现。
3. 每个 run 记录采样配置、每 10 epoch 的 union coverage，以及 train-only high-WSS 点覆盖率诊断。
4. 单元测试必须满足：同 seed+epoch 完全复现；不同 epoch 索引确实变化；val/test 始终使用完整点云。

### 3.2 target-weight 随 batch 分位漂移

`compute_loss()` 当前通过 `_q01(y)` 在每个 batch 内计算 2%/98% 分位。病例 shuffle 后，同一 WSS 值会因 batch 构成不同获得不同权重，增加无意义梯度噪声。

修订方案：

- 只用当前 fold 的 train 标签计算固定 `y_norm_q02/q98`，写入 run config 或 stats 快照；
- 权重统一为 `1 + α·clip((y-q02)/(q98-q02),0,1)`；
- 不使用 val/test 分位；
- 单元测试验证同一 y 在不同 batch 组合下权重一致；
- α=2 先作为第三轮锚点，只有固定阈值版本稳定后才扫 α。

### 3.3 checkpoint 选择与 early stopping

原计划建议用连续 2–3 次 eval 指标滑窗选当前 checkpoint，这并不严谨：滑窗中的指标属于不同权重状态，均值不等于当前模型的真实性能。

第四轮采用以下协议：

1. 每次 eval 对当前 checkpoint 计算并保存完整 val 指标。
2. 使用**预先写死**的复合 score 或 Pareto 规则，不在看到 test 后调权重。推荐第一版：整体 `R²_casemean/R²_field` 为主，top10/p99 校准只作惩罚或硬约束，避免单靠 ratio 被整体抬高预测“投机”。
3. 保存 val score 前 3 个候选 checkpoint，不只保留单一尖峰；候选之间的最终选择仍只看 val。
4. early stopping 按 eval 次数计：`eval_every=10`、max 160 epoch、patience=6 次 eval、min epoch=40。若 MSE 控制组显示 160 不足，再单独调整，不能为 target-weight 无条件跑 240。
5. 删除未使用的 `metric_key` 死代码；将 selection rule、top-k、early-stop 参数配置化并写入 `config.json`。

### 3.4 第四轮开发阶段禁止自动跑 test

当前 `run_train.slurm` 默认 `EVAL_PARTS=val,test`，提交脚本也没有显式传开发口径。第四轮应拆分为：

- 开发作业：训练 + val-only 完整点云评估；
- 最终作业：配置和 seed 全部锁定后，显式运行一次 test；
- `test16` 在报告中称为 legacy test/历史比较集；若要做严格确认性结论，需要新增未参与前三轮决策的病例或外部队列。

## 4. 指标体系修正

当前 `top10_pred_true_ratio` 是在**真值 top10% mask** 上比较预测/真值均值，只衡量幅值，不衡量模型是否把热点放对位置。high-WSS R² 又是在截断后的窄方差区间内计算，容易出现大负值，不宜单独作为选模依据。

第四轮补充以下病例级指标：

- `high_wss_mae` / `high_wss_nrmse_mean`；
- true/pred top10% mask 的 IoU、precision、recall；
- Spearman rank correlation（全壁面及 high-WSS 邻域）；
- hotspot centroid/peak-point 的归一化欧氏距离；若后续已有表面图，再升级为测地距离；
- 继续保留 top10/p95/p99/max ratio，监控欠估和爆峰。

主指标分层：

| 层级 | 指标 | 用途 |
| --- | --- | --- |
| 主性能 | `R²_casemean`、`R²_field`、MAE | 保证整体回归质量 |
| 尾部幅值 | top10/p99 ratio、high-WSS MAE | 判断峰值是否恢复 |
| 热点定位 | top10 IoU/recall、Spearman、peak distance | 区分“幅值低但位置对”与“热点位置错误” |
| 安全护栏 | max ratio、最差病例列表 | 防止少数病例爆峰 |

## 5. “log 目标导致峰值低估”的正确验证顺序（P2）

### 5.1 理论边界

log-MSE 学习 `E[log(y+eps)|x]`；若条件分布近似 log-normal，`exp(μ)` 对条件算术均值确实偏低。但当前每个几何点只有一个确定性 CFD 标签，预测方差可能混合：

- 未输入的信息；
- 模型容量/优化误差；
- 局部几何编码不足；
- 真正的数据噪声。

所以不能直接把 `exp(μ+σ²/2)` 当作无偏真值，也不能承诺 top10 比必然升到 0.6。

### 5.2 Gate-0：不训练新模型，先验证残差结构

对第三轮 3 个 target-weight checkpoint 重新导出 val 逐点预测，仅在 train+val 开发体系内做：

1. 按真值 WSS decile 统计 log/raw residual 的均值、方差和欠估率；
2. 检查欠估是否随真值分位单调增强，且 3 个 seed 方向一致；
3. 用病例 leave-one-out 的方式拟合全局 log-bias / smearing correction，验证它能否改善留出病例 top10/p99，而不明显损伤 R²/MAE；
4. 若简单校准已能稳定改善，优先考虑可解释的校准层；若无效，NLL 的“Jensen 修正”依据不足。

### 5.3 损失候选的优先级

1. **主线候选：log-space 主损失 + 小权重 raw-space Huber。**
   - `L = L_log + λ·Huber((y_raw_pred-y_raw)/p90_train)`；
   - `p90_train` 只由当前 fold train 统计；
   - 反归一化/`exp` 分支用 FP32 计算并记录数值安全裁剪比例，不能靠静默 clip 掩盖爆峰；
   - 先试 `λ=0.05`，Go 后再比较 `0.02/0.10`，避免一开始扩大矩阵。
2. **保留 target-weight α=2 固定阈值版**作为控制；α=1/4 只在固定阈值版本优于原 batch 权重后再扫。
3. **高斯 NLL 仅在 Gate-0 支持时做单 seed probe。**
   - 需要修改 model output 解析、loss、evaluate、checkpoint 和 config 校验；不是只改 `out_dim=2`；
   - `logvar` 必须有上下界/正则和 warmup；
   - 同时报 `exp(μ)` 与 `exp(μ+0.5σ²)`，若后者只靠整体抬高获得 ratio 改善则 No-Go。
4. **expectile/quantile 不进入默认主矩阵。** 它改变预测目标，适合“保守风险上界”而非逐点条件均值；只有任务明确改为风险预测时再单独立项。

## 6. 采样与点数实验（P1）

### 6.1 先做 CPU 覆盖审计

在任何 GPU 重跑前，对 train-only 计算：

- 固定 FPS 2000 的总点覆盖率；
- true high-WSS top10 点的选中率和各病例最差值；
- multi-start FPS 在 10/40 epoch 的 union coverage；
- fixed FPS 2000/4000 的局部密度和 ball-query 空邻域比例。

若固定 FPS 已无明显 high-WSS 欠覆盖，则“峰值没被采到”不能作为主要解释；multi-start 的价值只剩正则化和更广监督覆盖。

### 6.2 最小比较顺序

1. fixed FPS 2000（行为对照）；
2. multi-start FPS 2000（只改重采样）；
3. fixed FPS 4000（只改点数）；
4. 只有 4000 明确 Go，才跑 6000。

不要把重采样和点数同时改；PointNeXt 的固定 ball radius 在点密度变化后可能改变邻域统计，点数收益不能简单解释为“更多标签”。

## 7. 局部几何特征路线（P3）

### 7.1 对原提案的修正

不建议直接输入全局 `(nx,ny,nz)`：

- 法向存在符号问题；
- 全局分量依赖 canonical 坐标；
- PointNeXt 已从相对坐标隐式学习局部切平面，raw normal 的增量可能有限。

优先考虑旋转不变或局部系标量：

1. `radius_gradient`：中心线半径沿 abscissa 的一阶变化，标记收缩入口/出口；
2. `radial_ratio`：壁面点到最近中心线点距离 / `local_radius`，表达偏心与截面非圆性；
3. `normal_radial_dot`、`normal_tangent_absdot`：先把表面法向朝远离中心线方向统一，再取与局部径向/切向的内积；
4. 表面主曲率或局部 shape index/curvedness 标量。

本轮不把 `dist_to_throat` 或 `stenosis_ratio` 放入首批特征 probe：当前中心线特征是“最近中心线点”的无分支拓扑映射，不能可靠定义每例、每分支的喉部和近端参考段；把局部半径最小值直接解释为狭窄会引入端点、分支和噪声伪影。它们先进入特征定义/QA 设计项，完成 branch-aware 定义和病例级可视化验收后才可立项。

角向 `sinθ/cosθ` 只有在局部中心线 frame 通过 parallel transport、分支连接和符号连续性 QA 后才允许进入；否则 frame twist 会制造伪特征。

### 7.2 实现要求

- 在完整壁面点云上预计算，再随 bundle 版本化落盘；不能只在 2000 个训练点上估法向；
- 所有统计/clip 只由当前 fold train 计算；
- 增加非有限值、法向符号、分支交界连续性和旋转不变性测试；
- 一次只加一个特征族：先 `radius_gradient`，再 radial/surface 组；
- 先做便宜的 MLP/树模型增量 probe，若新特征对当前特征没有交叉验证增量，不进入 PointNeXt GPU 矩阵。

## 9. 统一 Go/No-Go 标准

所有增量都相对同 fold、同 seed 的第四轮 control 比较，不与第三轮 test 单点直接混比。

### Gate-1：单 seed / 主 dev split

满足以下任一收益路径，且通过安全护栏：

- 整体收益：`ΔR²_field >= +0.02` 且 `ΔR²_casemean >= 0`；或
- 尾部收益：top10 ratio `Δ>=+0.10` 或 top10 IoU `Δ>=+0.05`，同时 `ΔR²_field>=-0.01`、MAE 不恶化超过 3%。

安全护栏：

- max ratio 不得 >1.5；
- 不出现单病例极端爆值；
- 改善不能只来自一个 val 病例；
- 训练无 NaN/Inf，采样与 stats 口径可复现。

### Gate-2：三 seed

- 至少 2/3 seed 同方向；
- 均值达到 Gate-1 的主要收益阈值；
- seed 标准差不高于 control 的 1.25 倍；
- 若只有单 seed 大幅改善，其余持平/退化，判为不稳定 No-Go。

### Gate-3：重复开发划分

- 至少 2/3 dev 划分为正收益；
- 病例级 bootstrap 95% CI 不显示明显整体劣化；
- 通过后才能进入最终 legacy test。

## 10. 明确不建议做的事项

- 不重新改变坐标、单位、split exclusion 或 WSS clean stats 口径，除非 QA 出现新 fatal 证据。
- 不在每个第四轮配置完成后查看 test，再据此修改计划。
- 不把相邻 checkpoint 指标做滑窗平均后直接当作“当前权重”的性能。
- 不宣称高斯 NLL/Jensen 修正一定恢复峰值；先过残差与校准 Gate-0。
- 不把 expectile/quantile 与条件均值回归混为同一任务。
- 不直接输入未经符号/旋转/分支连续性 QA 的全局法向或角度。
- 不同时改 loss、sampling、点数和特征；否则即使提升也无法归因。
- 不在同一轮顺手把 BatchNorm 全换成 GroupNorm/LayerNorm；若采样密度修复后仍有 train/eval gap，再做独立归一化消融。
- 不重启已出现极端爆峰的“激进几何加权采样 + 强 target-weight”组合。
- 不优先堆大模型；4.4M 参数对应 53 个训练病例，当前更像协议、覆盖和信息问题。

### 12.2 模型侧补充

1. **train/eval 点密度敏感性已获首个实测证据，优先诊断、暂不改结构。** SA 按 `ratio=0.25` 下采样：训练 2000 点时约为 500/125/31/8，评估全量时随输入点数增长；FP 插值、BatchNorm running stats 和半径查询的邻域占用都会随之变化。`radius(..., max_num_neighbors=16)` 的邻居数被上限截断；当前实现和 PyG API 都没有给出“必为最近 16 个”的承诺，因此不能写成“先找到的 16 个”。
   - **已完成的 A5 预检（只读，不是新训练；终审已复现并补齐三 seed）**：`r3_clean_xyzgeom_tgtw_s1234` 在 8 个 val 病例（9850–17682 点）上，针对同一批每例 FPS-2000 点，比较“仅这 2000 点推理”与“全量推理后取同一索引”的标准化输出：平均 MAE=`0.1645`、RMSE=`0.2278`、Pearson=`0.9381`——该组数字已由独立脚本逐位复现。三 seed 汇总（MAE/RMSE/Pearson/mean-shift）：s1234 `0.1645/0.2278/0.9381/-0.050`、s7 `0.1413/0.1884/0.9605/-0.033`、s2025 `0.1191/0.1638/0.9717/-0.066`。方向一致：24 个病例-seed 对中 20 个为负 shift，即**全量推理系统性高于训练密度推理约 0.03–0.07σ**；点数最多的病例（17682 点）在三 seed 中漂移均最大，支持漂移随密度差增大。证据：`assets_第四轮/a5_density_probe.{py,csv}` 与 `_meta.json`。两种密度会实质改变预测；但它不说明全量评估错误，也不能用不同点集的 R²/top10 直接当作纯密度 gap。
   - **A5 正式口径（剩余部分）**：三 seed 标准化口径已完成；还需补同索引 raw-space top10 mask/幅值差和各层邻域达到 16 上限的比例（cap 比例需 hook radius 调用，脚本注释已注明）。三 seed 方向已一致且幅度超过普通 seed 波动，架构实验（C7 等）的启动条件在密度证据侧已满足，但仍须等 B 组行为控制完成后按 §12.2-1 候选顺序单变量推进。
   - **候选的正确顺序**：下采样预测 + 插值回全量只作诊断基线，不能直接替代部署评估；随后才可单独比较固定层级点数/体素方案、`nsample`，或 kNN 邻域。每项都会改变局部统计或输出分辨率，均需独立 Go/No-Go。
2. **rel 坐标未按半径归一化是代码事实，不是已证实的 bug。** SA/InvResMLP 确实拼接原始 `pos[col]-pos[row]`；但不同层使用不同物理尺度也可能是有意保留尺度信息。把它除以 radius 会同时改变尺度表达，不能仅以“原论文”概括为必修复。C7 仅在 A5 三 seed 明确、且 B 组仍有密度问题时，比较“归一化 rel + 显式尺度编码”与原实现；不进入当前主矩阵。
3. **AdamW 对 BN/bias 也施加 weight_decay**（`train.py:151`）：标准做法是 norm/bias 参数组 decay=0。低优先级，仅在 B 组稳定后作为搭载消融。
4. NLL 的 `out_dim=2` 会绕过 `out.squeeze(-1)` 返回 `(N,2)`（`pointnext.py:158`），train/evaluate 全部下游按标量假设——从代码上再次证实 §5.3“绝非只改 out_dim”的结论。

### 12.3 训练侧补充

1. **EMA/SWA 可作为后续候选，不是 B0 的“免费搭载”。** 权重平均比指标滑窗更可解释，但 raw/EMA 同时评估仍会增加候选数与 val 选择自由度；SWA 还依赖收敛末期和学习率轨迹。先保留 raw B0 作为可比锚点；若 B0 稳定，再以预先固定 decay/start、只选一种权重口径的 B0-EMA 单独记录。它不能替代 repeated-holdout。
2. **early stopping 与 cosine 退火的相互作用**：lr 周期绑定 `cfg.epochs`（`train.py:55-62`）。§3.3 将 max epoch 改为 160 时，cosine 周期必须同步改 160；patience 触发停止后不取停止点权重，仍从已保存的 top-3 val checkpoint 中选。
3. **rot_aug 本轮维持 No-Go，不列 C8，但证据表述按实测修正。** 它并非零成本（需要完整重训）。历史数据核实（`runs/_summary/summary.csv`）：`r2_xyzgeom_rotaug` 单 seed test `R²_field=0.186` 确为第二轮矩阵最低，但与 mse 控制组（0.189）仅差 0.004，在第三轮实测 seed 波动（±0.018–0.034）之内；且其 **val** `R²_field=0.281` 反而高于 mse 控制组（0.236）。因此正确结论是“**无正收益证据、单 seed 不可判**”，而不是“已证明有害”。No-Go 的真实依据是优先级与矩阵预算：canonical flow-divider 坐标可能携带有效先验，且本轮变量额度应留给 P0–P2。只有未来移除绝对 xyz 依赖、或有新的跨朝向数据证据时，才重新提出独立假设。
4. grad_clip 与 AMP 的 `unscale_` 顺序正确（`train.py:173-177`），无需改动。

### 12.4 采样侧补充

1. **multi-start FPS 应预计算“多个 k 点子集”，但不能声称自动解决 worker 同步。** `farthest_point_sample` 是 O(n·k) numpy 循环；每 epoch 重算 53 例会成为 worker 瓶颈。可离线预计算每例 S=8–16 个不同起点的 FPS-2000 子集并用带版本/点数/seed 元数据的 sidecar 保存。当前实现只缓存长度 k 的顺序，预计算“全 FPS order”会变为不必要的 O(n²)。pool id 仍取决于 epoch，因此仍需 P0 的 `persistent_workers=False`、共享 epoch，或主进程 custom sampler 之一；三者必须选定并单测，不能把它称为无状态修复。
2. **混合采样候选（B2'）**：预注册为“1600 FPS core + 400 个从非 core 点均匀无放回抽样”；它是一个采样策略，但 core/tail 比例本身是新超参数，不能称为没有额外自由度。与 B2 二选一，均以 B0/B1 胜者为共同对照；首轮只跑预注册的 1600/400，不再扫比例。
3. §6.1 覆盖审计补一个量：per-case true-top10 点在**全训练期 union** 的被采次数分布（而非仅单 epoch 覆盖率）——决定“重采样能否补覆盖”的是 union，单 epoch 指标会系统性低估 random/multi-start 的价值。
4. eval 恒用全量点云（`dataset.py:291-303`），与训练密度差 5–100 倍——与 12.2-1 是同一问题的两面；覆盖审计时把“训练密度推理”加入对照口径。

### 12.5 几何特征侧补充

1. **`dist_to_throat` / `stenosis_ratio` 暂不进入 C5。** 它们并非零成本：需要 branch-aware 中心线拓扑、稳定的近端/远端方向、可解释的参考段及病例级 QA。当前“最近中心线点 + local radius”不足以区分分支、端点和真实局部狭窄；把每例 radius 局部极小值叫作 throat 会制造伪标签。先在 A0 的几何定义文档中规定失败处理、参考段和可视化验收，完成后再决定是否开独立特征项。
2. **`radial_ratio` 依赖的“壁面点到最近中心线点的距离”当前 bundle 里没有**（`wall_dist_to_wall≡0` 不是它，见 `preprocess.py:284`）；需在预处理新增最近中心线投影。把该数据依赖写入 C6 的启动条件，避免误认为现成可用。
3. 法向类特征（`normal_radial_dot` 等）依赖表面法向，bundle 当前无法向数据，需在全量点云上做 local PCA + 朝向统一；PCA 邻域不能机械等同最浅层 `ball radius=0.05`，而应按点间距/局部尺度选取并做敏感性、翻转率和分支连续性检查。

- 第一轮的 `1000/1500/2000/3000/6000` 点数曲线是旧口径的纯 `xyz` 实验，不是当前 `xyz+基础几何` 主线的点数曲线。
