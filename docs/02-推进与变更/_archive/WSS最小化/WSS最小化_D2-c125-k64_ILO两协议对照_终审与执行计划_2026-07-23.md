> 日期：2026-07-23
> 状态：**ARCHIVED（2026-07-24）；9 个筛选 run 与 M1/S2/S3×{7,2025} 的 6 个确认 run 均已完训、审计与回填；S3-GEOPE 通过三种子确认**
> 当前执行入口：[S3-GEOPE 锚定正则化与架构优化执行计划](../../WSS最小化_S3-GEOPE锚定_正则化与架构优化执行计划_2026-07-24.md)

> 目标：并行回答 ILO-before41 的数据迁移效应，并在统一 AG/AAA/ILO 混合划分上继续推进结构优化

## 1. 终审结论

### 1.1 对原算法路线稿的评级

对 `WSS最小化_PointNet++下一轮算法优化路线_第一性原理与前沿研究讨论稿_2026-07-22.md` 的终审评级为：

**可作为算法研究讨论稿分享，但不能直接作为本轮 ILO GPU 执行单。**

原因不是原路线错误，而是本轮问题属于“数据队列与划分协议”轴，且用户指定的父模板是 `D2 c125×k64`；原路线稿的主要 D2 证据和下一轮架构父候选是 `c125×k128`。两者必须分开命名，禁止继续只写“D2”而省略 k。

### 1.2 本轮必须修正的四个方法学问题

1. **“两个协议”不等于“两个孤立训练任务”。**
   固定 test27 协议可以与原父模型配对；混合 test36 协议若只训练一个 AG/AAA/ILO 混合模型，将无法区分收益来自 ILO 入训还是来自病例重划分。因此混合协议必须同时包含一个相同 test36、但 ILO32 不参与训练的匹配控制臂。

2. **划分种子与训练种子必须分离。**
   本轮只使用一个训练 seed，但仍必须冻结病例 split。以后补三种子时也不能为每个训练 seed 重新划分 train/test，否则 seed 方差会混入病例组成差异。

3. **归一化统计必须在每一配对内冻结。**
   如果“加入 ILO”同时重算 target/feature stats，就不再是单变量数据对照。历史 Q2V/ILO 实验也已显示 refit stats 可能产生较大额外影响。因此主分析中同一配对的两臂共享控制臂统计；重算统计只能作为未来独立实验，不能并入本轮。

4. **两个测试集都已经被历史实验访问。**
   test27 被多轮模型选择使用，pool2025 test36 也已有 Q2V/ILO 结果；本轮因此属于“同协议工程确认和数据归因”，不能包装成全新的独立外部确认。模型选择仍固定使用 train-loss，不允许根据 test 指标挑 checkpoint。若后续需要论文级确认，应另行冻结从未访问的新 holdout 或采用预注册的嵌套交叉验证。

## 3. 父模型口径

本轮父模板明确命名为 **D2-K64**：

```text
support/query: random5000, SAME
SA centers:    125 → 125 → 32
SA grouping:   knn_cover(k=64) → ball16 → ball16
width:         32
dropout:       0
loss:          MSE
epoch:         400
selection:     ckpt_best(train_loss)
```

历史 `seed=1234`、AG/AAA `106/0/27` 结果为：

- physical `R²_cb = 0.262795`；
- case-mean `R² = 0.190715`；
- MAE `=2.9260 Pa`，case-balanced RMSE `=6.4475 Pa`；
- high-WSS `R²=-0.526595`；
- top10 IoU `=0.163402`，Spearman `=0.728741`。

该历史 run 只作为 `seed=1234` 的固定协议父控制复用。它低于 `c125×k128` 的单种子总体结果，但用户本轮明确选择 K64；本实验只回答数据队列问题，不重新比较 K64/K128。

## 4. 两个问题、四个实验臂

### 4.1 协议 F：ILO41 只进入训练，原 AG/AAA test27 固定

该协议回答：**ILO 数据加入训练后，对既有 AG/AAA 域是正迁移、无害还是负迁移？**

| Arm | Train/Val/Test | 训练组成 | 测试组成 | 作用 |
|---|---:|---|---|---|
| `F0-D2K64-BASE` | `106/0/27` | AG61 + AAA45 | AG15 + AAA12 | 配对父控制；seed1234 可复用 |
| `F1-D2K64-ILO41` | `147/0/27` | F0 + ILO41 | 与 F0 完全相同 | 唯一变量为加入 ILO41 训练 |

限制：F1 的测试集没有 ILO，因此它**不能证明 ILO 泛化变好**；它只测量 ILO 增训对 AG/AAA 的迁移效应。

### 4.2 协议 M：AG/AAA/ILO 五层分层混合划分

该协议回答：**在同一个包含 ILO 的 test36 上，ILO32 入训是否比 ILO zero-shot 控制更好，同时不损害 AG/AAA？**

固定 pool2025 split seed=`2025`，test36 组成是：AG15、AAA rupture6、AAA unrupture6、ILO-0 6、ILO-1 3。

| Arm | Train/Val/Test | 训练组成 | 测试组成 | 作用 |
|---|---:|---|---|---|
| `M0-D2K64-ZEROSHOT` | `106/0/36` | AG61 + AAA45；ILO32 标记 unused | 相同 mixed test36 | ILO zero-shot 匹配控制 |
| `M1-D2K64-MIXED` | `138/0/36` | M0 + ILO-0 22 + ILO-1 10 | 与 M0 完全相同 | 唯一变量为加入 ILO32 训练 |

M0 与 M1 必须一起训练和分析。M1 不能直接与历史 F0 的 test27 数字比较，因为病例划分和测试人口均不同。

## 5. 配置冻结规则

除 split、训练病例集合、run 名称和训练 seed 外，下列字段必须逐项一致：

| 类别 | 冻结值 |
|---|---|
| 数据 | `wall_n_points=5000`，`support_n_points=5000`，random，`resample_each_epoch=true` |
| 查询 | `query_mode=same`，`query_n_points=5000`；不得误继承 Q2V/ILO 的 independent SEP |
| 输入 | xyz + `abscissa_norm` + `local_radius` + `curvature`，共 6D |
| 模型 | PointNet++，width32，`sa_blocks=[0,0,0]`，head64，dropout0 |
| SA | centers `[125,125,32]`；nsample `[64,16,16]`；grouping `[knn_cover,ball,ball]` |
| FP/评估 | `fp_knn=3`，fixed support，full-cloud query，`legacy_vertex` |
| 训练 | 400 epochs，batch_cases8，Adam 路径和原 D2-K64 一致，lr `1e-3`，weight decay `1e-4` |
| loss/选模 | MSE；`ckpt_best(train_loss)` 为预注册主 checkpoint；同时报告 last 敏感性 |

### 5.1 归一化冻结

- F0/F1：共享原 D2-K64 的 AG/AAA train106 target stats 与历史 parent `feature_stats.json`。
- M0/M1：共享 pool2025 control106 的 target stats 与 feature stats。
- 本轮不创建 refit arm，不使用 cohort-balanced stats，不加 cohort one-hot。

这样每一对中唯一的数据变量才是 ILO 是否进入训练。若以后要研究统计口径，应另开正交矩阵。

## 6. 单种子与并行训练计划

### 6.1 固定 split seed

- 协议 F：沿用历史 AG/AAA seed1234 split；F1 只是把全部 ILO41 加入训练。
- 协议 M：固定使用已存在的 pool2025 seed2025 mixed split。
- 三个训练 seed **不得重新生成 split**。

### 6.2 本轮训练 seed

本轮所有新训练统一使用：

```text
train seed = 1234
```

每个比较都在同一个训练 seed 下配对。评估 `support_seed` 固定为 1234。`2025` 和 `7` 暂不训练，等结构、数据协议和实现稳定后，再作为最终三种子确认补跑。

### 6.3 GPU 任务预算

数据对照矩阵本轮有 `4 arms × 1 seed = 4` 个 run cell：

- `F0-seed1234` 已有历史结果，可复用；
- 需要新增 3 个数据训练任务：F1、M0、M1。

结构优化第一批再新增 2 个训练任务：`S1-MFEAT` 与 `S2-PNXR`。因此批准后的**第一批共新增 5 个 GPU 训练任务**，全部单种子并行：

```text
F1-D2K64-ILO41
M0-D2K64-ZEROSHOT
M1-D2K64-MIXED
S1-D2K64-MFEAT-MIXED
S2-D2K64-PNXR-MIXED
```

提交方式：

1. 先为五个任务分别完成 CPU/短 GPU preflight 和 1–2 step smoke；
2. 全部通过后，用一个 5-task Slurm array 并行训练；
3. 不根据某一个任务的早期性能取消其他已预注册任务；
4. 训练完成后统一触发 best/last 全云评估和审计。

### 6.4 结构优化统一使用混合划分

从本轮开始，所有新的结构、模块、特征和正则化实验统一使用：

```text
split: split_AG_AAA_ILO_q2v_pool2025_train138_test36.json
train/val/test: 138/0/36
split seed: 2025（固定）
train seed: 1234（本轮）
test: AG15 + AAA rupture6 + AAA unrupture6 + ILO-0 6 + ILO-1 3
```

`M1-D2K64-MIXED` 同时承担后续结构实验的公共父控制 `S0`。结构实验不得再切回只含 AG/AAA 的历史 test27，也不得各自重新随机划分。

### 6.5 结构优化分两批推进，批内训练并行

#### 第一批：与数据对照同时训练

| Arm | 父模板 | 唯一结构/输入变化 | Split | Seed |
|---|---|---|---|---:|
| `S0-D2K64-MIXED` | D2-K64 | 无；直接复用 M1 | mixed `138/0/36` | 1234 |
| `S1-D2K64-MFEAT-MIXED` | S0 | 增加已备 `radius_gradient`、`coord_scale` | 同 S0 | 1234 |
| `S2-D2K64-PNXR-MIXED` | S0 | PointNeXt-R core，`sa_blocks=(1,1,0)`，无 Drop | 同 S0 | 1234 |

S1 和 S2 是两个独立单变量臂，不相互继承。S1 的新增特征需要基于 mixed train138 生成对应 feature stats；这是该输入实验本身的一部分。S2 必须与 S0 共享原 6D mixed stats。

#### 第二批：核心实现稳定后并行

第二批仍全部使用相同 mixed split 和 `seed=1234`。代码单测与 smoke 通过后，以下实验可以并行训练，但每个实验只增加一个模块：

| Arm | 父模板 | 唯一变化 |
|---|---|---|
| `S3-PNXR-GEO-MIXED` | S2 | LocalGeoPE v1 |
| `S4-PNXR-ATTN-MIXED` | S2 | 只在 SA3 约32 centers 加1个粗层注意力块 |
| `S5-PNXR-SEP-MIXED` | S2 | Conservative SEP-Kernel |

这里“核心实现稳定”指 PointNeXt-R 已通过数值等价、forward trace、参数量、checkpoint 重载和短跑有限性测试，不要求先看到 S2 的最终性能。第二批训练可以在 S2 正式长跑的同时准备代码，但必须在对应模块 smoke 通过后才提交。

Dropout、DropPath、NeighborDrop 不进入前两批。只有出现明确 train-loss/测试差距、残差路径种子敏感或特征过平滑证据后，才单独开第三批正则化实验；该批也必须使用 mixed split。

## 7. 预注册比较与指标

### 7.1 两个主估计量

```text
ΔF = F1-D2K64-ILO41 − F0-D2K64-BASE
ΔM = M1-D2K64-MIXED − M0-D2K64-ZEROSHOT
```

- `ΔF` 只在固定 AG/AAA test27 上计算。
- `ΔM` 只在固定 mixed test36 上计算，并分别报告 AG、AAA、ILO。
- 不计算 F 与 M 之间的直接性能差作为因果证据。

### 7.2 指标层级

主指标：

- physical case-balanced `R²_cb`。

安全护栏：

- case-balanced MAE、RMSE；
- 负 `R²` 病例数；
- AG、AAA、AAA rupture、AAA unrupture 分域指标；
- mixed 协议下的 ILO、ILO-0、ILO-1 指标。

高值区与空间质量：

- high-WSS `R²`；
- p99 predicted/true ratio；
- top10 IoU；
- case-mean Spearman。

ILO-0 只有 6 个测试病例、ILO-1 只有 3 个测试病例，二者只能作探索性分层，不允许单独作为确认性结论。

### 7.3 统计方式

- 本轮在 `seed=1234` 下做同病例配对差。
- 对病例做 paired bootstrap 95% CI，并同时报告病例胜负数和效应量分布。
- Wilcoxon 只作补充，不以单个 p 值代替效应量和置信区间。
- best/last 都评估，但结论以预注册 `ckpt_best(train_loss)` 为主；last 仅做敏感性分析。
- 单种子结果只能标记“screening candidate / 暂不支持 / 明显退化”，不能写成跨种子稳定结论。待结构和协议稳定后，再用 `[1234,2025,7]` 做最终确认。

## 8. 结果判定

### 8.1 协议 F

- **单种子正向候选**：`ΔF physical R²_cb > 0`，病例级 bootstrap CI 下界 `>0`，且 RMSE/高 WSS 无系统退化。
- **暂视为安全但未确证**：置信区间跨 0，但 `ΔR²_cb ≥ -0.01`、RMSE 恶化不超过 1%，且主要分域无明显退化。
- **单种子 No-Go 信号**：`ΔR²_cb < -0.01`，或 RMSE 恶化超过 1%，或 AAA rupture/high-WSS 出现明显退化。

协议 F 即使正迁移，也只能说明 ILO 数据帮助 AG/AAA；不能说明模型已具备 ILO 测试能力。

### 8.2 协议 M

- **单种子晋级候选**：M1 相对 M0 的 overall 与 ILO 指标改善，AG/AAA 同时满足非劣（`ΔR²_cb ≥ -0.01`、RMSE ≤ +1%）。
- **条件候选**：ILO 改善、overall 近中性、AG/AAA 不退化；可以保留为通用模型候选，但必须标注 ILO9 小样本和单种子不确定性。
- **单种子 No-Go 信号**：ILO 未改善，或改善以 AG/AAA、AAA rupture、高 WSS 的明显退化为代价。

## 9. 实施前硬门

批准后，正式训练前必须自动检查：

1. 三个 split 的 SHA256 与 §2.2 一致。
2. ILO 活动集合严格等于最终 before41 白名单；after=0；20 个排除病例=0。
3. train/test/unused 互斥，病例计数和五层分布完全匹配计划。
4. 所有 bundle 存在，`transform_frame_version=stl_landmarks_v4`。
5. F0/F1 与 M0/M1 分别共享同一 target/feature stats 哈希。
6. 每个配对配置做结构化 diff，允许差异仅限 run 名称、split/train 病例集合和 train seed。
7. 模型运行时 trace 确认为 `[125,125,32]`、`[64,16,16]`、`knn_cover/ball/ball`、SAME query。
8. coverage 审计无零邻居；张量和 loss 无 NaN/Inf。
9. 1–2 step smoke 能保存并重新加载 checkpoint，chunk/full 推理在容差内一致。
10. Slurm manifest 记录 config SHA、split SHA、stats SHA、代码 commit 与 parent run。

任一硬门失败则不提交正式 array。

## 10. 用户批准后的实施范围

收到批准后，建议按以下顺序执行：

1. 新建专用配置目录，例如 `training_wss_min/configs/pointnetpp_d2_k64_ilo_20260723/`。
2. 编写/复用准备脚本，克隆 D2-K64、固定 split/stats，并生成单种子数据与结构实验 manifest。
3. 第一批生成 5 个新训练配置；历史 F0-seed1234 只登记为复用，M1 同时登记为结构公共父控制 S0。
4. 新增配对结果分析脚本或扩展现有 ILO 分域分析，使其输出 per-case delta、paired bootstrap CI 和分域表。
5. 运行配置、数据和 1–2 step smoke 审计。
6. 生成第一批 Slurm array，正式并行提交 5 个 GPU 训练任务。
7. 第一批长跑期间继续实现并 smoke `S3/S4/S5`。其中 SEP 在 SAME 下会被 identity 短路，无法形成有效模块检验，因此第二批增加 `S5C = S2 + independent query + 原 3-NN interpolate` 作为必要匹配控制，再与 `S5 = S5C + Conservative SEP-Kernel` 配对；实现门禁通过后用第二个 4-task array 并行提交，不必等待第一批最终性能。
8. 各批训练完成后自动提交 best/last 全云评估与完整性审计。
9. 将结果回填实验矩阵、训练跟踪、代码推进记录和结果汇总表。

现有模型代码已经支持 D2-K64 的 `knn_cover` 和固定 center，本轮原则上**不需要修改 PointNet++ 主干**；主要改动应是配置生成、manifest/preflight、结果分析和 Slurm 提交路径。若实施时发现必须改主干，需先停下说明原因，不能把代码修复悄悄混入数据对照。
