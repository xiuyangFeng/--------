## 0. 最终结论

第一/二轮结果差不是单一模型结构问题，而是以下问题叠加：

1. **第一/二轮训练统计被 `AG/slow/ZHANG_HUAN_LI` 严重污染**。该病例在旧口径中仍在 train，但 peak/all-time WSS 约 91.66% 为 0，壁面点数极端大，且同时触发单位、覆盖、裁剪、主干二次居中和曲率异常；第三轮已将其移入 excluded。
2. **当前 WSS log_z 统计尺度不适合 peak 单步任务**。当前 all-time train log std 约 `5.582`，把 raw WSS `20-200` 压到 log_z 约 `1.10-1.52`，峰值差异被严重压扁。
3. **模型确实在系统性低估高 WSS 区域**。第一轮 best 模型在 test top10% high-WSS 区，预测均值只有真值的约 `22%-23%`。
4. **训练设计放大了小样本和选模噪声**。峰值单步只有 54 个训练病例，FPS 采样下每 epoch 实际没有重采样，400 epoch 容易过拟合；val 只有 8 例，`val_r2_casemean` 选 ckpt 噪声很大。
5. **仍需保留若干 P0 排雷项**，尤其是跨时间步 `nodenumber` 行序对齐守卫。该问题很可能不是 high-WSS 全负的主因，但必须在 clean-data 第三轮前补上，防止静默标签错位。

第二轮收官（2026-07-09，全部 9 config 跑完并完成分位校准复核）已量化确认上述判断：目标幅值加权方向有效（tgtw 家族 R²_field 0.235–0.249 全面领先 mse 0.189），但 top10% 高 WSS 校准仅从 21.1% 提到 22.1%（唯一能推到 52.7% 的 `geomwsamp_tgtw` 伴随 max 溢出 22 倍，不可用）——**旧 stats 口径的上限已探明：R²_field≈0.25、真峰值校准≈22%，loss 加权修不动，继续调参无收益**。

因此，第三轮应视作**数据口径修正版重新起跑**。第一/二轮可以作为方向性证据，不能作为最终可发表指标。

## 1. 已观察到的训练症状

以第一轮和第二轮已有结果综合判断：

- 第一轮 `feat_xyzgeom_fps_w2000_peak`：test `R2_field=0.200`，`R2_casemean=0.188`，`stenosis=-0.196`，`high_wss=-1.634`。
- 第一轮 `feat_geomonly_fps_w2000_peak`：test `R2_field=0.191`，`R2_casemean=0.189`，`stenosis=-0.263`，`high_wss=-1.712`。
- 纯 `xyz` 组明显弱于几何特征组；增加点数不能解决 high-WSS 和 stenosis 全负。
- 第二轮收官（9 config 全部完成）：tgtw 家族全面领先——`geomw_tgtw` R²_field **0.249**、`tgtwloss` **0.246**（R²_casemean 0.233 / stenosis −0.068 / high_wss −1.377 均为全场最优），对比 mse 参考 0.189、huber 0.203（无收益）、rotaug 0.186（全场最差）。stenosis 从 −0.19 回拉到 −0.07~−0.13，high_wss 从 −1.63 回拉到 −1.38~−1.52，但仍全负。
- 第二轮 seed 方差：`tgtwloss` 三种子（1234/7/2025）R²_field = 0.246/0.217/0.203，极差 0.043，吞掉 tgtw 家族内部配置排序；只有"tgtw 家族 > 非加权"这一档间隔可信。

指标 signature：

- `R2_field` 明显好于局部区域 R²，说明模型主要学到平滑低频背景。
- `high_wss_r2` 全线为负，说明峰值被压低或空间定位失败。
- 完整推理分位统计显示是**峰值系统性压低**：
  `feat_xyzgeom_fps_w2000_peak` 在 test 上真值 p99/max = `26.98 / 126.74`，预测 p99/max = `9.37 / 16.71`；top10% high-WSS 均值真值/预测 = `18.51 / 4.08`，比例约 `22%`。
  `feat_geomonly_fps_w2000_peak` top10% 比例约 `23%`。
- 第二轮分位校准探针（test 全场 pool，ckpt_best 完整推理）进一步确认：目标加权的尾部 R² 回拉**主要来自中段，真峰值几乎没恢复**——top10% 校准 mse 21.1% → tgtwloss 仅 22.1%（p99/max 比持平或更低）；`geomw_tgtw` 26.2% 但 max 溢出至 138%；`geomwsamp_tgtw` 可推到 52.7% 但 max 爆到 2849（22 倍），不可用。

## 2. P0：必须先处理的数据污染与完整性问题

### 2.1 `AG/slow/ZHANG_HUAN_LI` 必须从 train 移入 excluded

该病例是当前 included 数据中唯一发现的同等级重大污染源。

证据：

- 当前仍在 `train_cases`。
- peak/all-time WSS 零值比例均为 `0.9166`。
- peak `p90=0`，peak mean `0.45`。
- 壁面点数 `209299`；剔除该例后 included 正常壁面点数范围约为 `9338-21452`。
- 审计字段同时触发：
  - `unit_anomaly=True`
  - `unit_extent_mismatch=True`
  - `wall_crop_frac=0.324`
  - `trunk_centering_offset_frac=0.0999`
- curvature 99 分位约 `3.13e6`，显著高于其它训练病例。

判断：

- 该例“坐标视觉回正”不等于“WSS 标签和几何统计可用”。
- 它污染了 `wss_global_stats.json`、`feature_stats.json` 和训练 loss。
- 第三轮前必须进入 excluded，并在理由中写明：`WSS 标签近全零 + n_wall 极端 + unit/coverage/crop/trunk 多重异常，污染训练统计`。

### 2.2 `AG/slow/WANG_BAO_SHAN` 仍需防误纳入

该例已在 `excluded_cases`，但磁盘上仍有历史 bundle。

证据：

- peak/all-time WSS 零值比例同样约 `0.9166`。
- `n_wall=238116`。

要求：

- 后续所有 stats、build-samples、train 都必须严格按 split 读取。
- 禁止直接 glob `data_wss_min/AG/*/*/bundle.npz` 参与统计或训练。

### 2.3 其它 included 病例未发现同等级 WSS 标签污染

排查结论：

- 除 `ZHANG_HUAN_LI` 外，train/val/test 的 peak_zero_frac 与 all_zero_frac 均为 0。
- 未见 peak `p90=0`、非有限值、坐标超界、半径非正等致命问题。
- `LI_ZHI_LIN`、`MA_TIAN_YI`、`SUN_ZONG_GE`、`LIU_ZONG_YANG`、`SHEN_ZHI_GANG` 等 peak 高值属于真实长尾高 WSS 样本，不应按高值剔除。

### 2.4 `nodenumber` 行序对齐仍是 P0 排雷项

联合审查中的第 1 条成立：若几何读自 `steps[0]`、WSS 读自峰值步，且只按行号配对，则跨步行序不一致会静默污染标签。

当前判断：

- 该问题很可能不是 high-WSS 全负的主因。理由是 train loss 能降到约 `0.026`，说明训练集中坐标和标签仍有稳定可学关系。
- 但它属于廉价且必须补的完整性守卫，不能留到第三轮之后。

第三轮前要求：

- `raw_io.read_wall_fields` 补读 `nodenumber`。
- `preprocess.py` 堆叠 `wss_ts` 前，逐时间步按 `nodenumber` 对齐。
- 若集合或长度不一致，直接报错并写审计。
- 附加自检：抽查相邻时间步坐标列或 `nodenumber` 是否逐行一致。

## 3. P1：目标统计与 loss 口径导致峰值压扁

### 3.1 当前 log_z 统计被全时序和坏病例共同压扁

当前 `wss_global_stats.json`：

- log mean/std = `-3.161 / 5.582`
- train all-time zero_frac = `0.208`

若从 train 中排除 `ZHANG_HUAN_LI`：

- all-time log mean/std 约 `-0.353 / 1.270`
- zero_frac 变为 0

若只用 clean train peak 统计：

- log mean/std 约 `1.159 / 1.091`

影响：

- 当前 stats 会把 raw WSS `20-200` 压到 log_z 约 `1.10-1.52`。
- 训练空间里高峰值差异太小，MSE 很容易优先优化平滑低值背景。

### 3.2 训练 loss 与评估空间不一致

现状：

- 训练 loss 在归一化 log 空间。
- 评估指标在 denormalize 后的原始 WSS 空间。

影响：

- log-MSE 偏向相对误差，天然不重视高 WSS 线性幅值。
- 与当前过大的 log std 叠加后，模型系统性低估峰值。

第三轮要求：

- 排除 `ZHANG_HUAN_LI` 后重跑 `global-stats`。
- peak 单步任务优先使用 clean train peak 的 log stats。
- 至少不能继续使用当前 `std≈5.58` 的 all-time stats。
- 保留目标幅值加权 loss 作为 clean-data 第三轮主候选，但第二轮旧 stats 结果只作为方向性旁证。
- 第二轮收官证据支持本节判断：在旧 stats 下，loss 加权只能把 top10% 校准从 21.1% 推到 22.1%（温和加权）或 52.7%（激进加权但 max 爆炸 22 倍）——**峰值压扁是 stats 口径问题，loss 侧修不了**。

## 4. P1：输入表征与几何特征问题

### 4.1 绝对尺度被 xyz 归一化抹掉

逐病例 `max_abs` 归一化到 `[-1,1]` 后，绝对管径/长度尺度被抹掉。`coord_scale` 在 bundle 中存在，但 xyz-only 模型没有使用。

判断：

- 这不一定解释所有 high-WSS 负值，但会伤害跨病例量级、stenosis 和 casemean。
- 第一轮显示几何特征远强于纯 xyz，说明模型需要局部半径、曲率、轴向位置等几何信息。

第三轮候选：

- `xyz+geom` 作为主线默认。
- 加入 `coord_scale` 或 per-case 全局尺度 token/特征。
- 做 `xyz+geom`、`xyz+geom+coord_scale`、`geom-only+coord_scale` 的小矩阵，不再优先扫纯 xyz 点数。

### 4.2 curvature 需要 robust 处理

`ZHANG_HUAN_LI` 把第一轮 curvature clip 拉到约 `3.13e6`。剔除该例后，训练集 curvature 99% clip 约降到 `1.0e5` 量级。

要求：

- 所有 run 的 `feature_stats.json` 必须重算，不能复用旧值。
- curvature 建议改为 `sign(x)*log1p(abs(x))` 后再分位裁剪和 z-score，或至少在 clean train 上做 robust p99/p99.5 clip。

### 4.3 `dist_to_wall` 在壁面任务中是常数列

壁面点上 `dist_to_wall` 恒为 0，作为输入只浪费一维，非主因。

建议：

- 第三轮可以从输入特征中移除，或保留但明确它不是有效特征。

## 5. P1/P2：训练设计和选模噪声

### 5.1 峰值单步样本太少，FPS 下没有有效重采样

现状：

- peak 单步训练只有 54 个 train case。
- 配置跑 400 epoch。
- FPS 采样下 `resample_each_epoch=True` 实际无效，因为代码仅对 `sampling!="fps"` 才每 epoch 重采样。

影响：

- 模型容易记住训练集平均低频热力图。
- val/test gap 与 val 曲线震荡会被放大。
- 第二轮收官证据：best epoch 集中在 59–159（仅 huber 339 / geomwloss 279 例外），400 epoch 后期都是过拟合区；val(8例)→test 落差 R²_field 约 0.05–0.11。

第三轮建议：

- clean-data 第三轮先缩短训练或加 early stopping。
- 多 seed 复核，不把单 seed 差异当结构收益。
- 后续若转 all-phase，必须给网络加 `phase` 或 `inlet_flow` 等时间/边界条件特征，否则同坐标多标签不可辨识。

### 5.2 ckpt 选择指标噪声大

现状：

- best 按 `val_r2_casemean`。
- val 只有 8 例，case-level R² 噪声高。
- 第二轮收官证据：`tgtwloss` 三种子 R²_field 极差 0.043，与多数配置间差异同量级——单 seed 的配置排序不可作数。

建议：

- 引入复合选模指标：`val_r2_casemean` + stenosis/high-WSS 指标，或物理 RMSE/MAE。
- 每个 eval 额外记录：
  - top10% high-WSS `mean_pred/mean_true`
  - p95/p99 预测/真值比
  - max 预测/真值比
  - 分位校准斜率

## 6. P2：坐标和增强风险

### 6.1 方向/配准 fallback 需要复核，但不是当前主因

复核清单：

- `LI_SHI_QIANG`：`bifurcation_fallback`
- `ZHANG_HAO`、`ZHANG_QING_WANG`、`RAN_QING_BO`、`CHENG_LU_LI`、`GUAN_TONG_XIANG`：`wall_pca_fallback`
- `ZHANG_XIU_WEN`、`CHENG_GUANG_SEN`、`CHEN_SHI_MING`：roll sign 置信较弱

判断：

- 这些病例没有同等级 WSS 零值污染。
- 75/78 方向置信可靠，残留方向问题不足以单独解释 high-WSS 全线为负。
- 建议补一页 QA 图并检查 per-case 指标，不作为第三轮默认剔除名单。

### 6.2 rot_aug 不应与 canonical xyz 主线混用

随机旋转增强会破坏 flow-divider canonical frame。若输入包含 xyz，rot_aug 与“统一坐标框架”假设冲突。

第二轮收官证据：`r2_xyzgeom_rotaug` R²_field 0.186，全场最差（低于 mse 参考 0.189），实证了该冲突。

建议：

- rot_aug 只用于 geom-only 或明确旋转不变的实验。
- `xyz+geom` 主线第三轮先不启用 rot_aug。

## 7. 第三轮 clean-data 最小执行矩阵

第三轮目标不是继续扩模型，而是先验证 clean-data 口径下主因是否消失。

### 7.1 必做前置

1. `split_AG_wss_min_v1.json`：将 `slow/ZHANG_HUAN_LI` 从 train 移入 excluded。
2. 增加 QA gate：
   - `peak_zero_frac>0.01`
   - `all_zero_frac>0.01`
   - `peak_p90<=0`
   - `n_wall>50000`
   - `unit_anomaly=True`
   - `unit_extent_mismatch=True`
   - `wall_crop_frac>0.05`
   - `trunk_centering_offset_frac>0.05`
   - 非有限值
3. `nodenumber` 对齐守卫。
4. 重算 WSS stats，并确保训练/评估使用同一份新 stats。
5. 重算 feature stats，尤其 curvature。
6. 严格按 split 读取，不 glob 全部 bundle。

### 7.2 必跑 baseline

1. **KNN / voxel / average-template 基线**
   - 目的：判断 `R2_field≈0.2` 是否只是统一坐标平均热力图。
   - 输出同样的 full-cloud test 指标和 high-WSS 分位校准。
2. **clean-data `xyz+geom / fps2000 / mse`**
   - 作为第三轮 reference。
3. **clean-data `xyz+geom / fps2000 / target-weight loss`**
   - 验证第二轮方向在 clean stats 下是否仍有效。
4. 每个主要配置至少 3 个 seed。

### 7.3 可选消融

- `xyz+geom+coord_scale`
- `geom-only+coord_scale`
- curvature log transform vs 原始 curvature clip
- Huber / raw-space auxiliary loss
