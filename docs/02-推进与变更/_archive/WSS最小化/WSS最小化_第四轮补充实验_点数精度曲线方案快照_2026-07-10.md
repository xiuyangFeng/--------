## 1. 为什么需要补这组实验

现有实验还不能回答“当前 `xyz+基础几何` 单头模型的最佳训练点数是多少”：

1. 第一轮 `1000/1500/2000/3000/6000` 点数横扫的输入是**纯 `xyz`**，而 `xyz+几何` 只有 2000 点一个配置。
2. 第一轮使用旧 WSS stats、旧 checkpoint 选择协议，并且使用已暴露的 legacy test，不能和第四轮 dev 协议混成同一条曲线。
3. 第四轮只有同配方的 2000 点 B1 与 4000 点 B3。B3 显著退化证明“4000 点在 dev1/seed1234 下不优于 2000 点”，但不能证明 2000 是最佳点数。
4. 原计划的“4000 Go 后才开 6000”是节省算力的递进 Gate，不是建立完整点数—精度曲线的设计。它不应被扩大解释为“已确定 2000 点最优”。

## 2. 补充实验要回答的问题

本组实验只回答三个问题：

1. 在当前 B1 单头配方下，验证集 `R²_field` 和 `R²_casemean` 随训练点数如何变化？
2. 哪个点数获得最高的开发集精度，以及哪个更小点数已达到近似精度平台？
3. 点数变化带来的差异，更像是有效信息量变化，还是 PointNeXt ball-query 的邻域密度/cap 变化？

本轮**不回答**辅助头、NLL、新几何特征、新采样器或更大模型是否有效，避免变量混杂。

## 3. 冻结的实验口径

除 `wall_n_points` 外，其他条件完全沿用 B1：

| 项目 | 冻结值 |
| --- | --- |
| split | `split_AG_wss_min_v2_dev1.json` |
| WSS stats | `data_wss_min/fold_stats/wss_stats_v2_dev1.json` |
| 输入 | `x,y,z,abscissa_norm,local_radius,curvature` |
| 曲率处理 | `signed_log1p` |
| 模型 | PointNeXt-S，约 4.39M 参数 |
| 输出 | **单个 WSS 标量头** |
| 采样 | fixed FPS，不使用 multi-start/random/几何加权 |
| loss | B1 固定 train-only 分位 target-weight，`alpha=2` |
| 旋转增广 | 关闭 |
| raw-Huber/辅助头 | 关闭 |
| seed | 首轮 `1234` |
| 训练 | max 160 epoch，`eval_every=10` |
| 选模 | `r4_composite_v1`，top-3 checkpoint |
| early stop | min epoch 40，patience 6 次 eval |
| 开发评估 | **val-only，完整点云推理** |
| legacy test | 不运行 |

target-weight 是单头回归的固定加权损失，不是辅助头。本设计保留它是为了复用当前协议锚点 B1，并保证点数是唯一自变量。

## 5. 执行前必须补的审计

现有 `coverage_audit.json` 记录的是旧 `split_AG_wss_min_v1.json` 和旧全局 stats，与本组的 `v2_dev1 + fold stats` 不同。训练前应：

1. 使用 `v2_dev1` 的 53 个 train case 重跑点数覆盖审计；
2. 至少输出每个点数的总覆盖率、true-top10 命中率和最差病例；
3. 记录 split、fold stats、点数、FPS seed 和生成时间；
4. 将旧 `10%/34%` 数字保留为 v1 方向性证据，不再写成 dev1 精确配套指标。

固定 FPS 在 `persistent_workers=False` 下可能重复计算子集，影响运行时间。若要预计算/缓存 FPS 索引，必须先用 focused test 确认与现有 B1/B3 的确定性索引完全一致，否则不能复用旧点作为同曲线锚点。

## 7. 预注册的判读方式

不只报一个“最高点”，同时报告两个结论：

1. **精度峰值**：预注册 `r4_composite_v1` 最高的点数，并同时列出两个 `R²` 主指标。
2. **简化拐点**：在主指标都没有明显退化、且尾部护栏没有恶化时，优先推荐更小的点数。

首轮可以用以下工程阈值定义“近似平台”：

- 相对当前单 seed 曲线最大值，`R²_field` 与 `R²_casemean` 均在 `0.01` 以内；
- top10 比和 IoU 不比曲线峰值点低 `0.03` 以上；
- 无 max ratio 爆峰或个别病例灾难性退化。

这些阈值只用于筛选确认对象，不用来代替多 seed/多 split 确认。

## 8. 第二阶段：多 seed 确认

单 seed 曲线完成后：

1. 选择“精度峰值点数”与 2000 点 B1 锚点；
2. 若峰值就是 2000，则选择曲线次优或更小的简化拐点作对照；
3. 两个点数补 seed `7/2025`；
4. 输出三 seed 均值 ± sample std 误差棒；
5. 只有差异超过 seed 方差并且方向一致，才能称为稳定点数收益。

## 9. 第三阶段：开发划分确认

若需要对“最佳点数”作稳健结论，将第二阶段保留的两个点数在 `v2_dev2/v2_dev3` 上各跑 seed1234：

- 每个 dev split 使用自己的 fold-specific WSS stats；
- 不使用 test 调整点数；
- 报告点数效应是否在 3 个 dev split 上方向一致；
- 如果不同 split 的峰值不同，优先选择更小、更稳定的平台点，不按 dev1 的偶然峰值决策。

## 10. 关于辅助头的决策

本补充实验明确**不加辅助头**。原因是：

- 当前还没有完成最基础的单头点数曲线；
- 辅助头会新增 loss 权重、负迁移和 val 选择自由度；
- 在 53 个训练病例上，先确定简单单头模型的容量/采样平台更容易归因；
- 只有点数曲线、多 seed 和多 split 均表明单头进入稳定平台，且热点定位被明确证实为剩余瓶颈时，才可另立独立辅助头消融。

## 12. 当前结论边界

在上述任务完成前，统一使用以下表述：

> 4000 点在 `v2_dev1/seed1234` 下相对 2000 点明确退化；2000 点是当前协议锚点，但 `xyz+基础几何` 的完整点数—精度曲线尚未建立，因此尚未验证 2000 点为最佳点数。

**第一阶段完成后的表述（2026-07-10）**：

> 在 B1 配方 / `v2_dev1` / seed1234 上，`xyz+基础几何` 点数曲线已建立：composite 峰值在 1000，2000 的 R²_field 持平但 casemean/top10 更低；曲线非单调（4000 谷、6000 回升）。单 seed 不得写成最终最优点数；下一步对 1000 vs 2000 做多 seed 确认。

**第二阶段完成后的表述（2026-07-10）**：

> 三 seed（1234/7/2025）确认后：R²_field 上 1000 与 2000 持平（0.337±0.017 vs 0.339±0.020）；仅 R²_casemean 稳定偏向 1000。默认训练点数仍用 **2000** 作协议锚点；1000 可作为更稀采样候选。若需稳健「最佳点数」声明，再上 dev2/dev3。
