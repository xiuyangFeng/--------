## 0. 一句话方案

新 V4 不再把 CFD 求解后才能得到的出口压力作为输入；入口名义波形分子全库统一，但 6 例 UDF 除数与网格面积不一致使实际入口流量并非常量，因此条件输入为入口/出口网格面积、`Q_actual_peak` 与每出口 `R1/R2/C`；入口以 UDF 实际施加的 `Q_nom/A_udf` 速度 Dirichlet 残差、出口以质量流量口径的 RCR 一致性残差（瞬态）进入物理项，物理子项按 BC/PDE 分组无量纲化；训练模式为 DATA、DATA+BC、BC+PDE-fixed、BC+PDE-EMA 四臂，以分离边界监督与 PDE 残差的贡献；数据只划分 train138/test35，train138 内部可做交叉验证（test35 永不进入 fold），训练由 train-only 原始分量 loss 的稳定性停止；物理模式通过配置切换为单峰值准稳态残差或多时相、显式包含 `du/dt` 的瞬态残差。

## 1. 为什么必须重构

旧 V3 的出口压力来自 Fluent 求解过程中输出的 `p-out*-rfile.out` monitor 时序。它依赖已经完成的 CFD 求解，不是新病例推理前天然可得的条件；旧 monitor 也不能与 UDF 在真实 pressure-outlet face 上递推的 RCR profile 或 `P_ave_out*` 面积平均压力混写。

因此，新 V4 明确取消以下设计：

- 不输入旧 `BC_O1..O4` monitor pressure；
- 不输入 CFD 求解后的 outlet-face pressure 或重建的 RCR `P_n`；
- 不把求解器输出的 `p-out*` monitor / outlet-face pressure 用作监督 loss；出口物理只通过求解前 `R1/R2/C` 构成的 RCR 一致性残差进入（见 9.3）；
- 不把已完成旧 field-v4 的 G-Raw/G-PE/local 结论直接继承为新模型架构；
- 不使用 val15 做 early stopping 或 checkpoint 选择；
- 不用 test35 调 epoch、动态权重、网络结构或超参数。

新 V4 保留的目标是：

- 输出固定为 `u,v,w,p`；
- 显式输入患者几何与求解前边界参数；
- 比较 PointNet / PointNet++；
- PINN 保留 continuity、三分量 momentum、壁面 no-slip，并新增入口 Dirichlet 速度 BC 残差；瞬态模式另含出口 RCR 一致性残差；
- data 与 physics 的所有原始、加权分量都可单独追踪；
- 准稳态与瞬态物理通过配置启动，不能在同一个实验 ID 中混写。

8. RCR 解析必须使用容错正则（UDF 存在 `R1 =1.2208E+05`、`C =9.5285E-07` 等无空格写法），并断言每例恰好 4×3 个正值；
9. 提取并冻结 ρ 与 Carreau 黏度参数，断言全库一致；物理残差的 `μ(γ̇)` 必须与 Fluent 逐参数相同；
10. 跨 173 例回归审计 `R1/R2/C ~ A_out` 共线性并写入数据合同；该结果约束 12.4 中 BC 有效性结论的表述边界；
11. 用 81 帧标签评估物理残差的标签级参照，并区分两类：时间有限差分与出口 RCR 时序残差（质量流量口径）可冻结为**参考尺度**；散乱 cell-center 的空间动量残差对邻域选择敏感（既有审计 k=48/96 点级相对差约 1–2.2×），只能冻结为**敏感性参考带**，不得称为“物理收敛地板”或 Fluent 原生离散残差。该审计仍给出峰值 `du/dt` 项与电容项量级，作为准稳态物理取舍与 `λ_max` 标度依据；
12. 提取入口/四出口 face 点集、外法向（定向与 UDF 流量符号约定一致）与面积权重，作为 BC 残差与 `P_out/ṁ_out`（质量流量口径）面积分的冻结基础。

在上述 Gate 完成前，瞬态路线状态只能写为 `source-data feasible / derived contract pending`。

## 5. 输入、输出与标准化

### 5.1 局部点输入

每个体域/查询点保留：

```text
x, y, z,
abscissa_norm,
local_radius_mm,
curvature_signed_log1p
```

Centerline V2 重建后，raw 曲率不做静默 clip；steady/transient 使用同一 raw geometry，
统一先做 `signed_log1p(curvature_per_mm)`，再只用 train138 统计标准化。2026-08-31 staging
采用 `max(population_std, train_max_abs_deviation/6)` 作为缩放量，在保留单调性和物理原值的
同时把 train 几何输入限制在 `±6`；`radial_ratio` 作为独立 auxiliary，不再与
`local_radius_mm` 共用字段名。

### 5.2 病例级显式 BC 输入

固定出口顺序：

```text
out-le, out-li, out-ri, out-re
```

统一病例条件向量：

```text
A_in (mesh),
Q_actual_peak,
[A_out, R1, R2, C] × 4 outlets
```

入口数据合同（v1.2 冻结）：全库 173 例共享同一组 Fourier **分子**系数，但 UDF 施加的是速度 profile `U_in(t) = Q_nom(t)/A_udf`，其中 `A_udf` 是 UDF 除数；实际入口流量为

```text
Q_actual(t) = U_in(t) · A_mesh = Q_nom(t) · A_mesh / A_udf
```

历史边界 Gate 已确认 6 例 `A_udf ≠ A_mesh`（最大偏差约 35.6%，ZHOU_KE_XUN 实际峰值 1.45494e-4 对名义 1.0727e-4 m³/s），因此 v1.1 的“入口流量全库零方差”结论**不成立**。由此：

- `Q_actual_peak` 恢复为输入特征：只输入 `A_mesh` 时，6 例标签对应的边界条件无法唯一恢复；
- `A_udf` 随 manifest 落库作为 provenance；6 例不一致病例逐例标记，保留/排除在 Stage 0 Gate 预注册（默认保留，因合同已精确描述其边界）；
- 禁止用 `Q_nom/A_mesh` 充当入口速度监督——那不是 Fluent 实际施加的边界（见 6.1）；
- 零方差检测 Gate 保留：任何 train138 标准差低于阈值的特征禁止 z-score；
- 为未来逐例波形 cohort 保留完整 `Q_in(t)` 输入接口，本 cohort 中禁用；启用须重新预注册；
- `A_in/A_out` 来自 Fluent mesh zone 的真实面积；
- `R1/R2/C` 来自病例 UDF 中求解前已定义的四组 RCR 参数（抽查已证实逐例、逐出口不同，全量以 Stage 0 审计为准）；
- 面积与 RCR 均为正值，先做 `log10`，再用 train138 统计 z-score；
- 当前 173 例均为四出口，保留 `outlet_valid_mask[4]`，便于未来扩展和显式防错；
- `RCR ~ A_out` 的共线性以 Stage 0 审计为准；审计明确前，不得把“加入 RCR 提升指标”表述为“面积之外的独立 BC 信息”。

### 5.3 BC 注入方式

BC 必须显式进入网络，但不要求把同一个原始向量机械复制到每层。建议使用共享的 `BCEncoder`：

```text
bc_vector -> smooth MLP -> bc_latent
```

再把 `bc_latent` 与 PointNet/PointNet++ 的几何表示、query coordinate/time 表示拼接到连续 query decoder。两个 backbone 必须使用完全相同的 BCEncoder 宽度和注入位置，避免把 BC 编码差异误写成 backbone 增益。

### 5.4 输出

```text
u, v, w, p
```

- `u/v/w` 单位为 m/s；
- 峰值方案：物理 loss 无出口压力锚点，压力水平不可辨识，沿用病例级体域均值中心化的固定 gauge；
- 瞬态方案：出口 RCR 一致性残差可消除压力的任意加常数自由度，但该“锚定”只在四个条件同时成立时才成立——远端压力为 0、operating pressure/gauge 约定全库一致、`P_out` 定义（UDF profile state / face 面积平均 / 独立 outlet scalar head 三选一）已冻结、81 帧标签上的离散 RCR 残差 Gate 通过；压力目标定义为“远端压力零约定下的 raw Fluent gauge pressure”（不是热力学绝对压力），按 train138 统计标准化；不做逐时相中心化，不得在训练 batch 内动态定零；
- 两种模式压力口径不同，跨模式压力比较只允许使用 gauge 不变量；
- 主评估同时报告 pressure gradient 与入口—出口 pressure drop，避免只看 gauge-sensitive 的绝对 R²。

## 6. 两种物理模式

### 6.1 模式 A：单峰值准稳态

配置建议：

```yaml
temporal_mode: steady_peak
momentum_mode: quasi_steady
time_input: false
```

映射：

\[
f_\theta(x,y,z,\mathrm{geom},A,\mathrm{RCR})
\rightarrow u,v,w,p.
\]

物理残差：

\[
\nabla\cdot\mathbf u=0,
\]

\[
\rho(\mathbf u\cdot\nabla)\mathbf u+\nabla p-
\nabla\cdot(2\mu(\dot\gamma)\mathbf D)=0,
\]

\[
\mathbf u|_{\Gamma_w}=0,
\]

\[
\mathbf u|_{\Gamma_{in}}=U_{in}^{peak}\,\hat{\mathbf n}_{in},
\qquad
U_{in}^{peak}=\frac{Q_{nom}^{peak}}{A_{udf}}.
\]

入口 Dirichlet BC 的目标是 UDF **实际施加**的速度 `Q_nom^peak/A_udf`，不是 `Q/A_mesh`——6 例 `A_udf≠A_mesh` 的病例里二者不同，用后者会监督一个 Fluent 从未施加过的边界。分子与除数均为求解前信息，标签与该 profile 一致。

入口 collocation 只取带边缘 buffer 的 face-interior 点：历史 138 例深审计显示入口面与壁面共享 32–83 个顶点，同一点不能同时施加 plug 与 no-slip；共享带一律归 no-slip，入口 BC 点集在 Stage 0 冻结。

本模式**不含**出口 RCR 残差：峰值标签由带电容状态的瞬态 RCR 求解产生，峰值时刻 `dP/dt≠0`，稳态关系 `P_out=(R1+R2)·ṁ_out`（质量流量口径）与标签系统性不一致；是否以“近似正则”形式加入，须凭第 2 节第 11 项标签级残差审计结果另行预注册。

该模式的标签来自瞬态峰值时刻，但 residual 不含 `du/dt`，因此只能称为：

> Fluent transient peak labels + quasi-steady physics regularization

`C` 在准稳态空间 PDE 中不直接出现，但仍作为数据条件输入，因为峰值标签由带历史状态的 RCR 瞬态求解产生。`Q_in_peak + R1/R2/C` 不能严格恢复电容状态，所以本模式不是闭合的瞬态求解器。

### 6.2 模式 B：显式包含 `du/dt` 的瞬态模型

配置建议：

```yaml
temporal_mode: transient_81
momentum_mode: transient_autograd
time_input: true
```

时间输入：

```text
t_norm,
sin(2π t_norm),
cos(2π t_norm),
Q_wave(t_norm)
```

`Q_wave` 是全库统一的名义 Fourier 波形按 UDF 的 mod-T 分段语义在计算图内的求值结果：它属于时间编码，不是病例特异 BC 信息，文档与结论中不得将其表述为“患者 BC 输入”。注意 `w=6.491 ≠ 2π/0.8`，波形谐波与 `sin/cos(2π t_norm)` 频率不重合，后者仅作通用周期编码。

映射：

\[
f_\theta(x,y,z,t,\mathrm{geom},A,\mathrm{RCR})
\rightarrow u,v,w,p.
\]

动量残差：

\[
\rho\left(
\frac{\partial\mathbf u}{\partial t}
+(\mathbf u\cdot\nabla)\mathbf u
\right)
+\nabla p-
\nabla\cdot(2\mu(\dot\gamma)\mathbf D)=0.
\]

边界条件残差（均只依赖求解前信息）：

\[
\mathbf u|_{\Gamma_{in}}(t)=\frac{Q_{nom}(t)}{A_{udf}}\,\hat{\mathbf n}_{in}
\quad(\text{face-interior buffer 采样，同 6.1}),
\]

\[
C_m\frac{dP_{out}}{dt}+\frac{P_{out}}{R_2}
-\left(1+\frac{R_1}{R_2}\right)\dot m_{out}
-R_1C_m\frac{d\dot m_{out}}{dt}=0
\quad(\text{每出口，远端压力取 }0),
\]

\[
\dot m_{out}=\rho\int_{\Gamma_{out}}\mathbf u\cdot\hat{\mathbf n}\,dA
\approx\rho\sum_i w_i\,\mathbf u_i\cdot\hat{\mathbf n}.
\]

**单位契约（硬 Gate）**：UDF 递推对 `F_FLUX`（质量流量，kg/s）直接累加，因此四组 `R1/R2/C` 是按**质量流量口径**标定的；残差必须使用 `ṁ_out`（或显式换算 `R_v=ρR_m`、`C_v=C_m/ρ` 后用体积流量，二选一冻结），混用会引入约 ρ≈1060 倍的量级错误（已有诊断：`0.04831 kg/s → 4.56e-5 m³/s`）。出口外法向与 UDF 流量符号约定一并冻结，并配单出口解析单元测试：给定解析 `ṁ(t)`，连续 ODE 与 UDF 后向差分递推逐步对照。

`P_out` 的定义必须三选一冻结：UDF profile state、face 面积平均或独立 outlet scalar head——已有证据显示施加 profile 与求解后 face-average 存在约百 Pa 差异，二者不可混写。该残差只联系网络自身预测与求解前 `R1/R2/C`，不使用任何求解器输出；其对压力加常数自由度的“锚定”仅在 5.4 所列四条件同时成立时才成立。

`du/dt` 必须由网络对显式连续时间输入 autograd 得到。禁止把“峰值前后 CFD 标签有限差分”与 autograd transient PINN 混成同一结论；有限差分只允许作为数据/Gate 对照。

链式法则硬 Gate：`sin/cos/Q_wave` 等一切依赖 `t` 的输入特征必须在计算图内由同一个 `t` 叶子张量计算，`Q_nom(t)` 用 UDF Fourier 系数按 mod-T 分段语义解析求值；任何图外预计算的时间特征都会让 `du/dt` 系统性漏项。

波形周期性边界（v1.2 修正）：`w=6.491 ≠ 2π/0.8=7.854`，UDF 的 mod-T 重置点存在值与导数跳变（`Q(0)≈1.48424e-5` 对 `Q(0.8⁻)≈1.43140e-5 m³/s`），不得宣称“周期上无限光滑”。处理：按 UDF 原样实现分段波形；strong-form 时间 collocation 排除 `t≈0/T` 的 buffer 邻域；不强制首尾导数连续；周期首尾场连续性只作诊断（压力标签首尾本就不严格一致）。

瞬态训练不建议每个 epoch 穷举 138×81 全部病例—时相。建议每个 epoch：

- 每病例随机抽取 1–2 个有标签时相；
- 独立抽取 physics collocation time；
- `Q_nom(t)` 由 UDF Fourier 系数按 mod-T 分段语义在计算图内解析求值，禁止 81 点插值或图外预计算；physics collocation time 避开 `t≈0/T` 重置 buffer；
- DATA、DATA+BC、BC+PDE-fixed、BC+PDE-EMA 四臂共享完全相同的病例、时相、support/query 和随机种子；
- 跨 epoch 重采样，保证全周期覆盖。

## 7. PointNet 与 PointNet++ 的 PINN 兼容设计

### 7.1 共同原则

- PointNet / PointNet++ 作为 support geometry encoder；
- query decoder 使用平滑激活，如 SiLU 或 tanh；
- PDE 点使用独立 collocation coordinates/time；
- 不在 support 重合点上用退化的 3NN-IDW residual 作为主物理证据；
- query 移动不能触发不受控的 top-k/kNN 邻居跳变；
- collocation 点必须有域内保证：基于网格单元的受限抖动或 SDF/拒绝采样生成，越界率为零作为 Stage 1 Gate；
- 正式训练前必须通过制造解的场值、一阶、二阶和时间导数 Gate；瞬态制造解必须包含“通过时间特征通道（sin/cos/Q_wave）依赖 t”的构造，专门捕捉链式法则漏项。

### 7.2 PointNet

```text
point features -> PointNet support encoder -> case/local geometry latent
bc_vector -> BCEncoder -> bc_latent
query xyz[/t] + geometry latent + bc_latent -> smooth decoder -> uvwp
```

### 7.3 PointNet++

PointNet++ 保留层次化 FPS/grouping 的 support encoder，但 strong-form residual 只对连续 query decoder 求导。若使用局部 support 条件，必须采用正带宽、可微且通过导数 Gate 的连续核；不得在 query 侧直接使用离散邻居选择后宣称二阶 strong-form 收敛。

### 7.4 公平性

- 两个 backbone 使用相同输出头深度、BCEncoder、数据采样、loss、scheduler 和停止规则；
- 同一时间模式/backbone 下的 DATA、DATA+BC、BC+PDE-fixed、BC+PDE-EMA 四臂严格共享初始化哈希与采样序列；
- 参数量差异需预注册并报告；若超过 10%，增加 matched-capacity 对照或解释；
- 不加载旧 V2/V3/field-v4 checkpoint，正式比较从相同随机初始化开始。

## 8. 正式实验矩阵

输入固定为 `xyz+geom+面积/Q_actual_peak/RCR`，不再重复 `xyz` 或无条件输入消融。

## 9. Loss 定义与逐分量监督

### 9.1 Data loss

所有输出先按 train138 统计标准化：

\[
\mathcal L_{data}=
\frac{1}{4}
(\mathcal L_u+\mathcal L_v+\mathcal L_w+\mathcal L_p).
\]

首版保持四通道等权，不动态改变 `u/v/w/p` 之间的权重，避免通过调权隐藏某个分量退化。

### 9.2 Physics loss：BC/PDE 分组与无量纲化

物理项分为两组，对应第 8 节四种训练模式的归因边界：

- **BC 组**（`λ_bc≡1`）：no-slip、入口 Dirichlet；瞬态另含出口 RCR 残差；
- **PDE 组**（`λ_pde` 由训练模式决定）：continuity 与三分量 momentum。

各子项量纲互不相同（1/s、kg·m⁻²·s⁻²、m/s、Pa 类），不做无量纲化，“等权”与 `λ=1` 都只是单位制的偶然标度。因此所有子项必须先无量纲化再组合，作为 Stage 1 硬 Gate：

- 逐例特征标度（全部为求解前量，Stage 0 冻结）：`U_c = Q_actual_peak/A_mesh`、`L_c = 2·sqrt(A_mesh/π)`；
- momentum 残差除以 `ρU_c²/L_c`；continuity 除以 `U_c/L_c`；no-slip 与入口 BC 除以 `U_c`；
- RCR 残差**不得**除以动态压强 `ρU_c²`：其量级仅数十 Pa，而出口压力约 1e4 Pa，会让 RCR 主导整个 physics loss；改用逐出口特征尺度 `P_RCR,c,i = (R1+R2)_i · ṁ_c,i`，其中 `ṁ_c,i = ρ·Q_actual_peak·g_i/Σ_j g_j`、`g_i = 1/(R1+R2)_i`（求解前可算的电导分流），Stage 0 冻结。

组内等权：

\[
\mathcal L_{mom}=\frac{1}{3}
(\mathcal L_{mx}+\mathcal L_{my}+\mathcal L_{mz}),
\qquad
\mathcal L_{pde}=\frac{1}{2}
(\mathcal L_{continuity}+\mathcal L_{mom}),
\]

\[
\mathcal L_{bc}^{steady}=\frac{1}{2}
(\mathcal L_{no\text{-}slip}+\mathcal L_{inlet\text{-}bc}),
\qquad
\mathcal L_{bc}^{transient}=\frac{1}{3}
(\mathcal L_{no\text{-}slip}+\mathcal L_{inlet\text{-}bc}+\mathcal L_{rcr\text{-}bc}).
\]

总损失：

\[
\mathcal L=
\mathcal L_{data}
+\lambda_{bc}\mathcal L_{bc}
+\lambda_{pde}(t)\mathcal L_{pde},
\qquad \lambda_{bc}\equiv 1.
\]

表述边界（v1.2 修正）：无量纲化只消除单位制依赖，使 `λ_pde=1` 成为**可复现、单位不变的固定基线**；它不保证各子项的数值分布或梯度范数相等，不得表述为“data 与 physics 等贡献”。首轮组内固定等权，不在子项之间再套第二层动态算法。三轴 momentum 必须分别记录，但调权时作为一个向量组处理；不能因为某注册轴数值较大就独立强制等平，从而破坏旋转一致性。若任一 physics 子项在末段长期占 `L_phy` 的 90% 以上，判为 dominance warning，不允许只凭总 physics loss 宣称收敛。

### 9.3 出口压力与 BC 的三种角色边界

- 求解后 `p-out*` monitor / outlet-face pressure 作为**输入**：标签泄漏，禁止（这是与 V3 的根本区别）；
- 求解后 monitor 作为**监督 loss**：不构成输入泄漏（训练标签本就来自 CFD），但与体场 `p` 标签冗余，为保持四臂干净，不使用；
- 求解前 `R1/R2/C` 构成的 **RCR 一致性残差**：合法物理 BC，瞬态模式默认启用；它只约束网络自身预测的 `P_out/ṁ_out` 关系（质量流量口径，见 6.2），在新病例推理时同样成立，不需要任何求解器输出；
- 入口流量不作为输入特征，改以入口 Dirichlet BC 残差进入物理 loss；面积与 RCR 参数本身不作为回传监督目标；
- 评估阶段可记录出口压力、分支流量和 BC 扰动响应作为诊断，除上述 BC 残差外训练权重为 0。

### 9.4 必须记录的 loss 与权重

逐 step 和逐 epoch 至少保存：

```text

```

所有 physics 子项日志须同时落盘第 2 节第 11 项的标签级参照值，并区分口径：时间 FD 与 RCR 时序残差为**参考尺度**；散点空间动量残差只提供**敏感性参考带**（k=48/96 点级相对差约 1–2.2×），不得当作“物理收敛地板”或 Fluent 原生离散残差使用。自 v1.2 起 `lambda_phy` 字段记录 `λ_pde`，`λ_bc=1` 以断言形式落日志。

## 10. 动态 PDE 权重

自 v1.2 起，动态权重只作用于 PDE 组：本节公式与配置中的 `L_phy`/`lambda_phy` 一律读作 `L_pde`/`lambda_pde`；BC 组权重恒为 1，不参与调权。

动态权重不能保证数学意义上的必然收敛。老师建议的 detached `EMA(L_data)/EMA(L_pde)` 比值只平衡**标量 loss 量级**，不平衡梯度，因此它是与固定权重严格配对的实验臂，而非保证收敛或最优的默认策略。新 V4 将其稳定化后作为动态臂，同时保留 `lambda_pde=1` 固定权重臂。

### 10.1 数学定义与必须 detach 的边界

老师方法的稳定版定义为：

\[
\lambda_{target}^{(k)}=
\operatorname{clip}\left(
\alpha(k)
\frac{\operatorname{EMA}(\mathcal L_{data})}
{\operatorname{EMA}(\mathcal L_{phy})+\epsilon},
\lambda_{min},\lambda_{max}
\right).
\]

随后对权重本身平滑：

\[
\lambda_{phy}^{(k)}=
\beta_w\lambda_{phy}^{(k-1)}
+(1-\beta_w)\lambda_{target}^{(k)}.
\]

`L_data`、`L_phy`、EMA 和比值更新必须全部 `detach()` / `torch.no_grad()`。若让
`lambda=L_data/L_phy` 保留在计算图内，则：

\[
\mathcal L=
\mathcal L_{data}+
\frac{\mathcal L_{data}}{\mathcal L_{phy}}
\mathcal L_{phy}
=2\mathcal L_{data},
\]

physics 梯度会在比值求导中抵消，等价于没有用 physics 训练。这是正式实现的硬 Gate。

### 10.2 physics warm-up

- `lambda_data=1` 固定；
- `alpha(k)` 从 `0.1` 平滑增加到 `1.0`，避免初始近零速度场产生伪低 physics residual 时比值爆炸；
- 建议配置 `physics_ramp_epochs`，而不是从第一个 step 突然追求 data/physics 等贡献；
- DATA、DATA+BC、BC+PDE-fixed、BC+PDE-EMA 四臂保持相同 optimizer/scheduler；仅物理开关与 loss controller 不同。

### 10.3 建议默认配置

建议默认模式：

```yaml
loss_balancing:
  mode: ema_loss_ratio
  detach_ratio: true
  update_interval_steps: 50
  ema_beta: 0.99
  weight_smoothing_beta: 0.90
  epsilon: 1.0e-12
  alpha_start: 0.10
  alpha_end: 1.00
  physics_ramp_epochs: 200
  lambda_min: 1.0e-4
  lambda_max: 10.0
  gradient_check_interval_steps: 50
```

原则：

1. EMA 每 step 更新，比值权重每 50 step 更新一次；
2. 更新时使用 EMA，而不是单个 batch 的瞬时 loss；
3. `lambda_target` 先夹紧，再用 `beta_w` 平滑得到实际 `lambda_applied`；
4. 所有 ratio/weight 均在计算图外更新；
5. 定期测量 data 与 physics 在共享参数上的梯度范数与夹角，但首轮不再用梯度反向控制权重；
6. 连续撞上限或下限、physics 子项 dominance、梯度长期强冲突均触发 warning；
7. test35 不能用于选择 update interval、EMA、夹紧区间或 ramp。

上述数值是工程默认初值，必须经 train-only smoke 冻结。若 smoke 表明权重长期撞限，允许在不读取 test35 的前提下修改配置并重新预注册。

### 10.4 三种训练模式的配置边界

```yaml
# DATA
bc_enabled: false
pde_enabled: false
loss_balancing.mode: disabled

# DATA+BC
bc_enabled: true        # lambda_bc = 1.0 固定
pde_enabled: false
loss_balancing.mode: disabled

# BC+PDE-FIXED
bc_enabled: true
pde_enabled: true
loss_balancing.mode: fixed
lambda_pde: 1.0

# BC+PDE-EMA
bc_enabled: true
pde_enabled: true
loss_balancing.mode: ema_loss_ratio
lambda_pde: dynamic
```

四臂除物理开关与 loss controller 外必须完全配对。任何臂不得从其他臂的 checkpoint 热启动。

## 11. 无 validation 时的训练停止与 checkpoint

老师建议只使用训练集和测试集，因此新 V4 不使用 validation early stopping。训练停止只依据 train-only、未经动态权重掩盖的原始分量趋势。

建议配置：

```yaml
convergence:
  min_epochs: 1000
  max_epochs: 10000
  window_epochs: 200
  consecutive_windows: 3
  relative_change_threshold: 0.005
  require_min_lr: true
```

停止条件必须同时检查：

- raw `data_total` 平台；
- 含物理臂的 raw PDE 与 BC 子项（continuity、momentum group、no-slip、inlet BC、RCR BC）均平台且无持续发散；
- EMA-ratio 臂的动态权重不再持续撞上下限；固定权重臂检查 physics 子项无持续发散；
- data/physics 梯度比例稳定；
- 末尾窗口无 NaN/Inf，梯度裁剪比例不异常；
- 已达到 `min_epochs`；
- `max_epochs` 是硬停止上限，防止“直到稳定”变成无限训练。

由于动态权重会改变 total loss 数值，**禁止只看 weighted total 判断平台**。

补充约束：

- LR 调度器的形态与终点必须在预注册时写死；若 LR 衰减至地板必然造成 loss 平台，则平台判据实际退化为“跑满预算”，预注册必须写明实际负责停止的条件；
- 平台停止可能让配对臂停在不同 epoch，构成训练时长混淆；利用 milestone checkpoint 预注册“全部臂在同一固定 epoch 的额外对比”作为稳健性检验；
- 无 validation 的过拟合盲区由 4.3 的 train138 内部交叉验证缓解；CV 只提供训练侧诊断与配置选择，不改变 test35 协议。

主 checkpoint 定义为：

```text
last_converged.pt
```

同时保留 initialization、milestone、last 和 plateau diagnostic checkpoint。`best_test` 不存在；test35 不参与 checkpoint 选择。

## 12. 评估与分析

### 12.0 primary endpoint 与统计边界预注册

- primary endpoint：test35 病例等权的**速度向量相对 L2 误差** `E_case = ‖u_pred − u_true‖₂ / ‖u_true‖₂`（逐病例在全部评估点计算，分母为该病例真值速度向量场的 L2 范数；瞬态对全部评估时相 pooled）；每病例先对 3 seeds 取均值；
- primary contrasts 预注册为固定集合：`DATA+BC − DATA`、`BC+PDE-FIXED − DATA+BC`、`EMA − FIXED`、`PointNet++ − PointNet`（各时间模式内分别检验），35 例配对 Wilcoxon + Holm 校正；单一 endpoint 不等于解决了 16 臂多重比较，检验只在这组预注册对比上做；
- NMAE 一律写明分母（病例内真值 speed 均值），且只作 secondary：历史上出现过 NMAE≈2% 而 speed R²≈0.18–0.24 的组合，禁止单独用 NMAE 宣称成功；12.1–12.5 其余指标全部为 secondary / 描述性；
- test35 已是 development-exposed screen：所有检验只提供**探索性**效应量与置信区间，不构成确认性结论；确认性检验需要未参与设计的新 cohort；
- 臂间差异小于 seed 间离散度时，结论必须记为 inconclusive。

### 12.1 场值主指标

- `u/v/w/speed/p`：病例等权与 pooled 的 R²、MAE、RMSE、NMAE；
- 速度向量 L2 误差、夹角误差；
- near-wall/core/分叉分区；
- AG/AAA/ILO 分层与逐病例失败率；
- pressure gauge、压力梯度与入口—出口压降。

### 12.2 工程积分量

- 入口/出口流量误差；
- 四出口流量分配；
- 全域质量守恒；
- 壁面速度 RMS/P95/max；
- continuity 与 momentum independent-collocation residual。

### 12.3 瞬态附加指标

- 逐相位与全周期 `u/v/w/speed/p`；
- 峰值时刻、峰值幅度和相位偏差；
- 周期首尾连续性（仅诊断：UDF 波形在重置点本就存在跳变，标签首尾并非严格一致）；
- `du/dt` 与各动量项 RMS；
- 不同时相的分支流量波形相关性与幅值误差。

### 12.4 BC 使用有效性

RCR 参数是输入，不是监督目标，因此不存在普通的 `R1/R2/C loss`。应增加：

- batch 内 RCR permutation/shuffle 诊断；
- 在合理生理范围内的小扰动敏感性；
- 同一几何固定、只改变 RCR 的 counterfactual 推理（本 cohort 入口波形全库统一，不存在“改 Q”的对照）；
- `BCEncoder` 梯度与输出响应幅度；
- RCR 一致性残差在 test35 上的独立评估（出口 P–Q 关系残差，相对标签级地板报告）；
- 面积/RCR 去除消融只在主矩阵完成后单独预注册；
- permutation/扰动诊断只对面积与 RCR 有定义；其结论表述受 Stage 0 `RCR ~ A_out` 共线性审计约束——若 RCR 可由面积确定性重构，只能声明“面积衍生条件有信息”，不能声明“独立 RCR 信息”。

现有数据每个几何主要对应一个 BC 组合，因此即使加入 RCR 后测试指标提高，也只能首先证明“条件增加预测信息”，不能直接证明网络学会了同几何多 BC 的因果响应。最强确认仍需要少量同几何、多 RCR/Q 的 CFD 反事实数据。

### 12.5 WSS 边界

新 V4 不直接输出 WSS，不使用 WSS loss，也不用 WSS 选 epoch、权重、架构或 checkpoint。冻结的 velocity→WSS 后处理器只能在 `u,v,w,p` 主 checkpoint 固定后做一次 downstream sanity check。
