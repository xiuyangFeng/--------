### P0-2：steady 与 transient 的第 2 个几何通道不是同一个物理量

V4 设计文档和 stats 把三个几何通道写成：

```text
abscissa_norm, local_radius, curvature_signed_log1p
```

实际数据为：

- steady：读取 WSS-min bundle 的 `int_local_radius`，含义是中心线局部半径，单位 mm；
- transient：读取 `data_new/processed/features/result_features_merged-*.csv` 的
  `NormRadius`，其代码定义是“点到中心线距离 / 局部半径”，为无量纲径向位置；
- stats：从 transient 的 `NormRadius` 计算，却把字段命名为 `local_radius`；
- steady loader：再用这组 transient stats 标准化 mm 制 `local_radius`。

这不是轻微分布漂移，而是同一模型输入位置在两个时间模式中代表不同物理量。

抽查同一注册点的 peak 几何显示：

| 病例 | transient 第 2 通道中位数 | steady 第 2 通道中位数 | 含义 |
| --- | ---: | ---: | --- |
| `AG/fast/CHEN_SHI_MING` | 0.999 | 6.279 | 径向比值 vs 半径 mm |
| `AAA/ruputer/ZHOU_KE_XUN` | 258.619 | 12.406 | 旧错位特征已严重失真 |
| `AAA/unruputer/LIU_WEN_QI` | 26.571 | 6.222 | 旧错位特征已严重失真 |
| `ILO/YANG_YU_QING-1/before` | 10.991 | 7.756 | 旧错误中心线/STL 口径 |

当前 peak Gate 只比对坐标、速度和压力，没有比对几何通道，所以该错误仍可 173/173 pass。

**风险**：阻断。必须先冻结唯一语义，并在 schema 中把 `local_radius_mm` 与
`radial_ratio` 分成两个不同字段。

### P0-3：旧曲率是按 VTP 全局点存储顺序求导，分叉病例中系统性失真

旧 `pipeline/vmtk_core.py` 的 `compute_curvature_manually(points)` 直接对 VTP 全局
point array 执行 `np.gradient(points, axis=0)`。分叉中心线的全局 point storage order
不是单条连续路径，跨分支相邻数组行会制造非物理的一/二阶导数尖峰。

当前 173 例 transient eligible 点共 411,380 个，审计结果：

| 阈值 | 超阈点数 | 比例 | 涉及病例 |
| --- | ---: | ---: | ---: |
| `|Curvature| > 1` | 75,477 | 18.35% | 171/173 |
| `|Curvature| > 10` | 37,942 | 9.22% | 171/173 |
| `|Curvature| > 100` | 19,171 | 4.66% | 171/173 |
| `|Curvature| > 1e3` | 11,138 | 2.71% | 171/173 |
| `|Curvature| > 1e5` | 4,391 | 1.07% | 167/173 |
| `|Curvature| > 1e7` | 627 | 0.15% | 118/173 |

最大值：

- train：`AG/slow/XU_YI_CAI`，约 `3.15e11`；
- test：`AAA/unruputer/SUN_SHU_MING`，约 `2.28e12`。

train138 stats 因此得到 `curvature_clip_abs=116,434.15`。对照 Centerline V2 按 0.5 mm
弧长、逐路径重采样后的 422,388 个点：

- 曲率绝对值中位数约 `0.058 /mm`；
- p99 约 `0.272 /mm`；
- 最大约 `6.044 /mm`。

数量级差异已经证明旧曲率不能作为可靠几何先验。

**风险**：阻断。不得只靠 `signed_log1p + p99 clip` 掩盖源特征错误。

### P0-4：steady/transient 曲率变换仍不一致，且现有 stats 已被旧特征污染

steady sidecar 在写盘时已经对曲率做 `signed_log1p(abs(curvature))`，但不使用 V4 的
全局 p99 clip；transient 则在 loader 中先按 `116,434.15` clip，再 `signed_log1p`。

因此即使忽略 P0-3，两个时间模式仍使用不同的曲率预处理。抽查病例中 steady 归一化曲率
最大可达约 `13～15σ`。现有 `train138_stats.json` 不能复用到新数据。

**风险**：阻断。所有几何变换必须在同一个 builder 中执行一次，steady/transient 直接
引用同一静态 geometry asset。

### P0-5：transient 绝对压力存在孤立低值簇，统一 gauge/RCR 合同未被证明

173 例 steady pressure reference 中存在明显断层：8 例为 `475.9～3508.4 Pa`，下一例
已升到 `10362.5 Pa`，其余主体约为 `1.3e4～1.8e4 Pa`。

低值病例：

- train：`ILO/LIU_YUE_DONG-0/before`、`ILO/LI_SHENG_WEN-0/before`、
  `AG/slow/LI_BING_YI`、`AAA/ruputer/MENG_GUANG_QIN`、
  `AAA/unruputer/CHEN_SHU_LIN`、`AG/slow/LIU_ZONG_YANG`；
- test：`ILO/ZHANG_YONG_SHENG-0/before`、`AAA/ruputer/WANG_FU_SHUN`。

这些病例的 81 帧压力本身有限且大多首尾接近，但其绝对水平与主体病例不同。现有数据尚未
证明差异来自：

- Fluent gauge/reference 设置；
- UDS/RCR 初值与预热周期；

此外，4 个 train 病例缺完整 outlet log reference：

Stage 0 的 `outlet_label_reference_available_train` 实际只检查“可用病例数 > 0”，而不是

## 4. 高风险问题（P1）

### P1-1：左右方向没有用稳定出口语义做 Gate

当前 roll 符号只锚定原始 STL world `+X`，并把它解释成 patient-left。使用 V4 稳定出口
标签比较 left=`out-le/out-li` 与 right=`out-ri/out-re` 后：

- 169/173 为 left 组 `x <` right 组；
- 4 例方向相反：
  - train `AG/fast/LI_ZHEN_SHAN`；
  - train `AG/fast/LI_ZHI_LIN`；
  - train `AAA/unruputer/CAO_HONG_TAI`；
  - test `AG/slow/ZHANG_WEI_XIAN`；
- 另有两个左右分离接近零、需复核：`AAA/ruputer/WANG_KUI_WU`、
  `AAA/ruputer/GAO_FENG_SHAN`。

BC vector 固定按四出口顺序输入。若同一解剖侧在少数病例中镜像到相反 x 方向，会增加
跨病例条件学习难度。

### P1-2：WSS-only 的 wall scale 被直接复用于 volume PINN

当前 `coord_scale` 按 wall 的最大绝对坐标确定，而 V4 使用体域、入口和四出口边界：

- 172/173 病例 interior 存在 `|coord|>1`；
- 病例 `max|coord|` 中位数约 1.741，最大约 2.338；
- 每例 interior 超界行比例中位数约 22.6%，最大约 43.9%；
- 173/173 inlet face 均超出 `±1`，中位最大绝对值约 1.758，最大约 2.448。

这不是刚性变换公式错误，但说明 WSS-only 数值范围合同不适合直接充当 volume 网络输入
合同，尤其会让 BC 点位于不同的数值尺度区间。

### P1-3：transient 空间池过小，所谓空间重采样对多数病例并不成立

transient target-domain interior pool：

- 123/173 病例恰好只有 2000 点；
- 44 例多于 2000 点；
- 6 例少于 2000 点：
  - train `ILO/WANG_SHU_SHENG-0/before`：1569；
  - test `AAA/ruputer/YANG_BAO_KUI`：1609；
  - train `ILO/ZHANG_YAN_SHAN-0/before`：1610；
  - train `AAA/unruputer/GUO_BAO_CHUN`：1742；
  - train `AAA/ruputer/XIE_JIN_QUAN`：1792；
  - train `AG/fast/LI_ZHEN_SHAN`：1835。

只看 train138 时，100 例恰好 2000 点、33 例多于 2000 点、5 例少于 2000 点。因此这不是
test35 的偶发现象，而是当前训练空间池本身的主要形态。

当前 transient 配置 `support_points=query_points=2000`：

- 对 123 例，support/query 每个 epoch 只是同一 2000 点池的重新排列；
- 对 6 例，loader 自动有放回采样，产生重复点；
- transient official evaluation 也主要受这批固定空间池限制，不能等同于 full-volume
  transient 泛化。

### P1-4：train/test 边界资产生成合同不同

- train138 全部使用 field-v4 的 `face_interior_contract.npz`；
- test35 全部回退使用 V3 的 `peak_boundaries.npz`。

这不会造成标签泄漏，但训练 BC 与 test 物理诊断不是同一个边界资产生成流程。新版本应
统一为 173/173 face-interior、法向、面积权重和 opening ID 合同。

### P1-5：loader/resume/preflight 的哈希绑定不足

当前文件没有发现实际 split 泄漏，但代码护栏不足：

- loader 不读取 `paths.split`，只相信 aggregate manifest 的 role；
- train role 选择完成后再检查是否含 test role，判断恒为假；
- loader 不核验 aggregate/case/array SHA、stats scope、stats train IDs；
- checkpoint/resume 不绑定 manifest/stats/split snapshot digest；
- Stage 0 `--resume` 主要检查旧 manifest 状态和文件存在，不复核父源/派生文件 hash；
- CPU/GPU preflight 没有遍历证明 173 例全部可加载，GPU smoke 只取首个 batch。

Centerline V2 出现后，这些缺口会允许“陈旧但存在”的旧资产继续通过。

### P1-6：单位/原点接口仍依赖旧中心线推断逻辑

当前 WSS-min 预处理仍可用 centerline bbox 反推 Fluent→mm 单位，并用 resampled path 点
再次 k-means 推断 flow divider；这与 Centerline V2 的冻结合同冲突：

- 权威 STL/单位必须先冻结；
- 新中心线不得反向决定单位；
- V2 已有显式 graph root/junction/opening IDs，不应再次猜测。

直接把 V2 path CSV 塞入旧 `_flow_divider_origin` 逻辑，已有 4 例退回 fallback：

- `AAA/unruputer/LIU_WEN_QI`；
- `ILO/LV_JIAN_HUA-0/before`；
- `ILO/GONG_HAI_ZENG-1/before`；
- `AAA/ruputer/LI_ZHEN_HUA`。

### P1-7：少数 BC 条件在 train 标准化后超过 6σ，可能产生高杠杆梯度

train-only stats 可复现，但其标准化结果中仍有少数病例远离主体分布：

- `AAA/ruputer/ZHOU_KE_XUN`：`Q_actual_peak` 约 `8.94σ`；
- `AAA/ruputer/ZUO_DAO_SHENG`：`Q_actual_peak` 约 `6.54σ`；
- `AAA/ruputer/ZOU_LI_SHUN`：`out-re` 的 `C` / `R2` 约 `6.50σ` / `6.46σ`。

这些值不等于数据错误，但会让标准化后的条件向量和 BC/PDE 残差对少数病例高度敏感。
重建时必须回查原始 UDF、面积、RCR 单位和出口标签；若来源正确，应显式登记为物理长尾并
在采样、loss/gradient 监控和病例级指标中单独报告，不能静默 clip。

## 7. 修复方案

### Phase 0：冻结旧版本并建立切换边界

1. 保留当前 `data_wss_pinn/volume_uvwp_bc_rcr_v4_train138_test35/` 和现有 run，只读归档；
2. 不覆盖旧文件、不在旧 run 目录 resume、不从旧 checkpoint warm-start；
3. 新建独立 route/data root，例如：

```text
data_wss_pinn/volume_uvwp_bc_rcr_v4_centerline_v2_train138_test35/
outputs/wss_pinn/volume_uvwp_bc_rcr_v4_centerline_v2/
wss_pinn/configs/volume_uvwp_bc_rcr_v4_centerline_v2/
```

4. 生成 173 例 cutover manifest，逐例绑定 V2 surface/graph/paths/openings/result、raw CFD、
UDF、mesh、旧/新 transform 和全部 SHA256。

### Phase 1：冻结统一几何 schema

建议静态几何资产至少保存：

```text
abscissa_norm
local_radius_mm
radial_ratio
curvature_per_mm
path_id / outlet_id
junction_mask
distance_to_bifurcation_mm
```

首轮 V4 模型仍保持三个几何输入时，应明确选用：

```text
abscissa_norm + local_radius_mm + signed_log1p(curvature_per_mm)
```

`radial_ratio` 单独落库，可作为后续消融，禁止再与 `local_radius_mm` 共用字段名。

几何特征必须只从 Centerline V2 显式 graph/path 计算一次，再按静态 point identity 同时供
steady 和 81 帧 transient 引用。不得继续读取旧 `data_new` CSV 的
`Abscissa/NormRadius/Curvature`。

### Phase 2：重建刚性注册帧

1. 单位直接读取 V2 `surface_selection.json` 的 frozen Fluent→mm 合同，不由新中心线 bbox
反推；
2. 原点直接使用显式 graph junction/root，不再对 path 点重新 k-means；
3. 主轴使用 junction→proximal trunk；
4. 左右轴使用稳定 opening IDs：

```text
e_x = center(patient-left outlet pair) - center(patient-right outlet pair)
e_z = junction -> proximal trunk
e_y = cross(e_z, e_x)
```

5. Gram-Schmidt 正交化并保证 `det(R)=+1`；
6. 点、速度、法向、WSS vector 全部用同一个 R；压力保持标量不旋转；
7. `coord_scale` 改为 volume-aware：建议由 target volume + wall + inlet/outlet 的全体 registered
点统一计算各向同性 max-abs scale，使新合同下所有训练/BC 坐标位于 `[-1,1]`；同时保留
`coordinate_length_m` 供 PDE 链式缩放。

### Phase 3：从完整 raw 数据重建 173 例

1. 从完整 raw wall/interior/81 帧场重建，不从已裁剪旧 bundle 派生；
2. 重新生成 steady full-volume sidecar；
3. 重新生成 transient 空间池，建议每例至少 5000 个 target-domain interior 点，并保证
support/query 不需要有放回采样；
4. 173/173 使用统一 face-interior 边界资产生成器；
5. 保存 `transform_centroid/rotation/scale`、V2 hashes、raw row identity、单位、裁剪/排除原因；
6. 重新计算 train138-only geometry/BC/field stats；旧 stats 禁止复用。

### Phase 4：压力与 RCR 专项修复

对 173 例逐一冻结：

- Fluent operating/reference pressure；
- pressure 导出定义与单位；
- UDF/UDS 初值；
- 导出属于第几个周期、是否达到周期状态；
- outlet UDF profile、face-area mean、volume field 的关系；
- 质量流量符号约定。

对 8 个低值病例做病例级结论：

- 若证明仅为 gauge offset：显式记录 offset 来源并统一到冻结 gauge；
- 若为 RCR 初态/周期未收敛：重跑 CFD 或从 transient 路线排除；
- 若为合法不同状态：必须增加可辨识的病例条件，不能让网络猜测不可观测常数。

### Phase 5：修复 loader、resume 与 preflight

loader 启动时强制核对：

- split train/test IDs 与 manifest role 的集合、顺序和数量；
- train/test 零交集；
- stats `train_case_ids == split.train_cases`；
- aggregate/case/array SHA256；
- V2 provenance 173/173；
- route/schema/data snapshot digest。

checkpoint/environment 写入 dataset snapshot SHA；resume 必须完全相等。Stage 0 `--resume`
必须重新核验父源与派生资产 hash。CPU preflight 遍历 steady/transient 全 173 例，GPU smoke
再覆盖 16 个科学臂。

### Phase 6：分级重训

1. 四个高风险病例 + 两个普通病例做 builder/loader/可视化 pilot；
2. 全 173 例数据 Gate；
3. 单 batch CPU/GPU 数值 smoke；
4. 少病例过拟合：steady/transient 各选 normal、YANG、XIE、ZHOU/LIU 一例；
5. 先跑两个最小 data-only sanity：PointNet 与 PointNet++，固定小预算；
6. 只有当新 data-only 明显优于旧帧且没有病例级异常，再启动 BC/PDE 和 3-seed 全矩阵。
