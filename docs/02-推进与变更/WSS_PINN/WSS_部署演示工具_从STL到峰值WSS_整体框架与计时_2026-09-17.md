## 0. 一句话结论

- **链路已经存在，但散在验证脚本里。** `training_wss_min/tools/deployment_stl_simulation.py` 的两个函数（`sample_surface` 重采样、`build_deployment_case` 建 27 维特征）加上 `evaluate.predict_case_norm` 就是完整的 STL→WSS，只是它为了验证而读训练库里的中心线（`case.h5`）和 CFD 真值（`bundle.npz`）。中心线提取则已有独立包 `outputs/vessel_geom_toolkit_2026-09-17/`（VMTK，50 个解析解测试）。
- **缺的是四段"胶水"**：① 新病例中心线 → 训练同款 atlas 的适配器（含出口命名 / 左右判定）；② 去掉真值依赖、把硬编码路径（capfit 规则仍指向 v5.0 的 train138 文件、`DEFAULT_RUNS` 仍指旧 X5）冻结进发布包；③ 五模型 Pa 均值集成 + 峰值统计 + 导出；④ 一个能看的界面。
- **实测耗时（登录节点，单张 4090）**：一例端到端 24–86 s，其中 GPU 推理只占 5–6 s；瓶颈是中心线提取（稠密 STL 58 s）和 0.5 mm 重采样（8–16 s），两者都能优化到 5 s 以内。纯 CPU 推理 68 s，一例约 100 s，也能接受。
- **建议路线**：先做"命令行 + 单文件 HTML 三维报告"（一周内可演示），再做"上传 STL 的本地网页服务"（再两周）。不建议一开始就做桌面软件。

## 2. 实测分段计时（2026-09-17，登录节点，Slurm 之外，`CUDA_VISIBLE_DEVICES=1`）

方法：中心线用 vessel_geom 工具包直接跑原始 STL；重采样/特征/推理用 `deployment_stl_simulation.py` 的原函数（atlas 暂取训练库 `case.h5`，真值只用来算该例 R²）。脚本与原始数值在 `training_wss_min/experiments/wss_deploy_timing_20260917/`。

| 病例（队列） | STL 顶点 | 0.5 mm 点数 | 中心线+atlas | 重采样 | 特征 | 五模型推理 | 端到端 | 该例 Pa R² | 预测/真值 p99 WSS（Pa） |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---|
| KANG_YONG（AAA） | 16,448 | 88,469 | 10.2 s | 16.0 s | 7.0 s | 6.4 s | **40 s** | 0.887 | 5.31 / 4.89 |
| FAN_JIAN_MING（AG） | 10,627 | 58,031 | 5.3 s | 8.5 s | 4.5 s | 5.6 s | **24 s** | 0.852 | 12.90 / 13.06 |
| LI_YOU_ZHI-0（ILO） | 101,654 | 89,503 | 57.8 s | 15.6 s | 6.8 s | 5.5 s | **86 s** | 0.801 | 8.95 / 8.34 |
| KANG_YONG，纯 CPU（192 核） | 16,448 | 88,469 | 10.2 s | 15.8 s | 7.0 s | 67.8 s | **101 s** | 0.888 | 5.30 / 4.89 |

判读：

1. **GPU 推理不是瓶颈**：单模型稳态 1.0–1.1 s（第一个模型多 1 s 是 CUDA 预热），五模型 5.5–6.4 s，显存 0.3 GB；A100 或 4090 都绰绰有余。
2. **中心线提取随 STL 顶点数线性增长**：1–1.6 万顶点 5–10 s，10 万顶点 58 s（ILO 的 STL 本身就是 0.5 mm 级）。对策：VMTK 前先把表面抽稀到约 1 mm（中心线只需要管腔形状，与训练 atlas 的一致性要复核一次），预计压到 10 s 内。
3. **重采样 8–16 s 是纯 CPU 数值代价**（6 倍过采样 + 3 轮体素校准），改成单轮采样或泊松盘可到 2–3 s。
4. **单例精度与集成读数一致**：三例 R² 0.80–0.89，peak p99 误差 5–10%，最大值误差 ILO 例偏高（30.5 对 23.5 Pa），这是已知的射流尾部问题（跟踪文档 §28.9）。
5. 优化后目标：**GPU 一例 15 s 内、CPU 一例 90 s 内**。演示时"进度条按段走"比总时长更重要。

## 3. 目标形态：三层架构

```
[STL 上传/拖入]
   │  ① 读入 + 单位/流形/开口检查（<1 s）
   ▼
[中心线层]  vessel_geom（VMTK）→ atlas + 开口 + 出口命名(自动规则 + 可人工改)   5–60 s
   │
   ▼
[几何层]    1 mm Taubin 平滑 → 0.5 mm 重采样 → 27 维特征（法向/曲率/管道坐标/Murray 份额）   10–25 s
   │
   ▼
[模型层]    5 × X5D_v51 常驻显存 → log_z → Pa → Pa 均值集成 + seed 离散度   5–6 s
   │
   ▼
[结果层]    点上 WSS(Pa) → 峰值卡片 / 分支峰值 / 热点位置 → VTP + CSV + JSON + 单文件 HTML 三维报告   2–5 s
```

三层代码组织（建议新建 `wss_deploy/` 包，不改动 `wss_v5/`、`training_wss_min/` 的训练行为，符合"配置驱动 + 旧配置逐位不变"的硬要求）：

| 层 | 内容 | 形态 |
|---|---|---|
| **内核包 `wss_deploy/`** | `ingest.py`（读 STL、单位、检查）、`centerline.py`（子进程调 vessel_geom，出口命名规则，atlas 适配器）、`geometry.py`（平滑、重采样、`build_deployment_case` 的无真值版）、`infer.py`（发布包加载、五模型集成、离散度）、`report.py`（峰值统计、VTP/CSV/JSON/HTML 导出、PNG 渲染）、`cli.py`（`python -m wss_deploy run case.stl --out dir`，每段写时间到 `run.json`） | 纯 Python，可被服务与脚本共用；权重固定读 `outputs/wss_deploy_release/<release>/` |
| **服务层** | 一个进程常驻模型，接收任务、按段推送进度；单 GPU 串行队列即可（一例 15–40 s） | 第一阶段可以没有：CLI 直接出报告；第二阶段 FastAPI + 一个 worker |
| **展示层** | 页面按四段展示：原始 STL → 中心线（带分支名和半径）→ 输入点云 → WSS 热图；右侧峰值卡片、分支峰值表、每段耗时；可切换"与 CFD 对照"模式（test34 病例有真值） | 第一阶段：每例一个自包含 HTML（three.js 点云着色，无需服务器）；第二阶段：同一页面接服务 |

## 4. 输入合同与自动检查（这些都已经有实验证据，只是要写进代码）

| 项 | 规则 | 证据 | 不满足时 |
|---|---|---|---|
| 单位 | STL 为 mm；bbox 对角 < 1 m 判为米制自动 ×1000 | V4 单位合同（STL=mm，Fluent=m） | 提示并自动换算 |

| 密度上限 | 0.35 mm 反而 −0.021 | §22.1 | 自动执行 |

## 5. 输出定义与可视化

- **模型输出的是什么**：峰值收缩期那一帧（step 1162，心动周期 0.8 s 内第 0.21 s）的壁面 WSS 幅值（Pa），逐点。所以"峰值 WSS"要分清两层：时间上的峰值帧（模型已固定），空间上的峰值（要在报告里定义）。
- **峰值卡片建议同时给四个数**：全壁面最大值（对噪声敏感，只作参考）、p99、top-10% 面积平均、热点位置（所在分支 + 距分叉距离）。分支表按主动脉 / 左右髂总 / 左右髂内外给 p99 与均值。
- **不确定度**：五 seed 的 Pa 标准差按点显示（第二张热图）；这是零成本的"可信度"展示，也提醒观众射流区偏差大。
- **对照模式**：test34 病例可以并排显示 CFD 真值与预测（口径与工作簿一致：Pa R²_cb、MAE、top10 比）；新病例只有预测 + 不确定度。
- **导出**：`wall_wss.vtp`（ParaView）、`wall_wss.csv`、`summary.json`（峰值卡片 + 每段耗时 + 输入检查结果 + 发布包哈希）、`report.html`（自包含三维查看器，三十万点以内浏览器流畅）。

## 8. 需要拍板的问题

1. **展示形态**：P1 的"命令行 + 单文件 HTML"先行，还是直接做 P2 网页？（建议先 P1，P2 复用同一页面。）
2. **运行位置**：master 4090 / node04 A100 / 无 GPU 的展示笔记本？决定要不要优先做 CPU 加速。
3. **"峰值 WSS"的正式定义**：报告以 p99 为主、最大值为参考，是否可以？分支表要不要细到髂内/髂外？
4. **对照模式是否展示**：test34 的"CFD vs 预测"并排图很有说服力，但要说明 test34 参与过方法筛选；新病例预期读数按 cv3 折外 0.71 说。
5. **出口命名与切口**：自动规则出错时允许人工改名，还是要求上传前按协议切好？（建议自动 + 人工确认，把盖面半径和切口位置画出来。）
6. **不确定度要不要出现在展示里**：五 seed 离散度热图对内部很有用，对外可能引起疑问。

## 9. 风险与边界

- 精度口径：对外说 test34 0.77 时要同时给 cv3 折外 0.71 与队列差异（ILO 折外 0.62 最弱）；单例 R² 0.80–0.89 只是三例。
- 新病例分布外：训练只覆盖腹主动脉–髂动脉 5 开口几何；其它血管走 vessel_geom 可以出中心线，但模型不适用。
- 输入几何质量：粗糙 0.2 mm 掉 0.035，2 mm 尺度起伏平滑救不回（§22.6-B）；临床分割面要在页面上给出"表面粗糙度"读数。
- 密度：K16 patch 仍对粗云敏感；点云粗于 1.5 mm 时可切换到 X5Ddual 备选（不进默认底座）。
- 硬编码路径：`wall_flowref_v1.CAPFIT_RULE_PATH`、`deployment_resample_reeval.DEFAULT_RUNS`、`C.PROJECT_ROOT` 都要在 `wss_deploy/` 里显式覆盖，不能靠默认值。
- 两个 conda 环境：P1 用子进程跨环境；合并环境要重新跑 vessel_geom 50 项测试与 `regress_old_bundle` 核对。

## 15. 基础设施改造：为多模型、多时间帧和多物理场预留接口（2026-09-18）

### 15.1 本轮已落地的四项基础改造

1. **模型发布版本独立化**：每次计算记录 `model_release`、发布包目录、`release.json` 和 `MANIFEST.sha256`，不覆盖旧权重。结果包含模型发布版本、权重清单、来源提交和输入契约。
2. **通用字段描述**：结果增加字段元数据（字段名、单位、标量/向量、壁面/体场、存储位置和时间帧），当前 `wss_pa` 仍作为兼容别名；以后可并列加入 `velocity`、`pressure`。
3. **统一时间轴**：即使当前模型只有一个固定收缩期帧，也保存 `time_axis`，包含帧 ID、物理时间、相位和选中帧。后续多帧统计应在同一结构上扩展，不再把“peak”写死成唯一时间含义。
4. **可复现运行清单**：每个任务写入 `run_manifest.json`，记录输入 SHA256、预处理参数、模型版本、时间轴、字段、自动/人工映射、设备、随机种子、代码版本和导出文件哈希；旧的 `summary.json` 继续保留为 WSS 兼容视图。

### 15.2 长期数据合同

```text
Case
 ├─ InputAsset / preprocessing
 └─ Run
     ├─ model_release
     ├─ time_axis
     ├─ fields: WSS / velocity / pressure
     ├─ metrics: spatial / temporal / space-time aggregation
     └─ review and audit events
```

`peak`、`p99` 等指标今后必须同时记录空间范围、时间窗口、权重方式、单位和来源字段。压力需要记录表压/绝对压及参考值；速度需要记录向量坐标系；壁面字段与体场字段不能用同一位置语义混合。

### 15.3 验收与兼容要求

- 现有单帧 WSS 报告、VTP、CSV 和 `summary.json` 继续可读。

- 更换权重只新增发布包和运行记录，不修改旧任务结果。
