## 1. 背景（给没看过这个工具的人）

### 1.1 这个工具在做什么

- 用户上传一根主动脉—髂动脉的血管 STL，工具自动提中心线、确认出口命名，几十秒后给出三维预测结果，不需要跑 CFD。
- 可选三种模型：
  - **X5D**：峰值收缩期壁面 WSS，默认模型。
  - **M1 三头**：峰值 WSS + 周期平均 TAWSS + OSI，再派生出 RRT 和 ECAP。
  - **PF6/VF6**：峰值时刻的体内压力和速度，含流线与截面。
- 目前部署在 master:8765，**只在课题组内部展示**。
- 使用的人：医生、导师、组内研究者，也会对外演示。各场景谁优先还没定，见 Q1。

### 1.2 现有页面

### 1.4 从第一性原理定义问题：使用者究竟买到了什么

使用者要完成的是：**认清当前病例与结果 → 找到值得关注的位置 → 理解数值及适用边界 → 留下可以复查的说明或图件。** 三维渲染、展开图、多视口都只是帮助完成这些任务的手段。

| 不可省略的问题 | 设计推论 | 可以舍弃或延后的东西 |
|---|---|---|
| 我在看谁、哪次扫描、哪次预测？ | 病例、扫描、任务/发布包三层身份始终可辨；同病例的三头和体场仍是不同结果 | 首页无行动价值的总数、重复的任务标题 |
| 我需要看哪里，下一步做什么？ | 首屏显示场与可定位的发现；计算未完成时显示下一项可执行操作 | 每个指标同等大小的大卡片、所有控件同时外露 |
| 这个值代表什么、来自哪里？ | 单位、空间范围、时相、统计口径和数据支撑就近可查 | 重复免责声明、实现细节长文案 |
| 两张图能不能直接比较？ | 比较前校验字段、单位、时相、坐标与统计定义；不同条件显式列出 | 仅因为两个数字都叫 WSS 就自动相减 |
| 我能否回到同一发现，并交给另一个人？ | 保存结果身份、位置、口径和视图；导出携带来源 | 只能看、不能定位回去的漂亮截图 |

重构的收益应表现为：**完成任务更快、误读更少、恢复与交接更容易、重复维护更少。** “页面更少”“代码更短”“更像期刊”只能作为手段，不单独作为成功标准。

### 1.5 用任务区分使用场景，不先做四套角色界面

| 场景与使用者 | 典型任务 | 默认呈现 | 成功的证据 |
|---|---|---|---|
| 组会讲解者、导师 | 90 秒解释本例的一个发现及依据 | 主场 + 发现书签 + 简短来源 | 讲解途中无需翻找菜单，听者能复述位置和边界 |
| 组内研究者 | 复核低值区域，导出可复现的图 | 场 + 沿程定位 + 口径检查器 | 导出图、表和重新打开的视图一致 |
| 医生试用者 | 判断结果是否值得继续查看，提出具体疑问 | 形态定位 + 相关场 + 支撑提示 | 能辨识预测值与临床结论的区别；不要求熟悉全部术语 |
| 对外演示者 | 稳定展示已准备病例并回答追问 | 只读讲解预设、可返回探索 | 掉网仍能展示已导出的报告，退出讲解可回原位 |

初始优先级仍建议组会讲解与科研复核。医生的“像翻 CT 层”是否自然，要通过任务试用验证，不能由设计者代答。角色只改变初始布局；同一人可在讲解、探索、出图之间切换，暂不新增权限角色。

### 1.6 三个设计不变量

1. **显示变化不能悄悄改变数值含义。** 色标、光照、简化网格和补全插值影响显示；点值、壁面环均值、体场截面积分各用已定义的数据与算法。改变统计方法属于独立分析变更。
2. **状态必须附着于明确的结果身份。** 同病例不等于同几何，同几何不等于同模型输出；一组相同的相机坐标更不等于同一组织位置。
3. **少解释是降低重复，不是省略证据。** 无数据、无法映射、无支撑、未保存都应可识别；不能用 0、平滑颜色或绿色标签掩盖。

## 2. 现状诊断

### 2.1 AI 味从哪来

**文案**
- 首页写「上午好，有 2 例待审阅」，还有「三步上手」①②③。
- 几乎每个标签后面都挂一个「?」。
- 「非诊断结论 / 参考」这句话在详情页出现三四次。
- 耗时卡写成「本次 4 秒 · 累计 8 秒，不含排队与人工确认；另有确认出口期间后台预计算 6 秒」。
- 数字下面都跟一行灰色小字解释，像在念说明书。

**视觉套路**
- 卡片里套卡片，圆角 10–13 px，带阴影。
- 首页四块大数字卡显示 0 / 0 / 2 / 2，数字大但没有信息量。
- 淡色胶囊标签到处都是（待审阅、WSS+TAWSS+OSI、压力+速度体场）。
- 小标题用青绿色大写风格（「今日概览」「预测结果」）。
- W 方块 logo、渐变底色。
- 用 Unicode 字符当图标（＋ ▸ ⌀ ← ☰）。

**结构**
- 每条信息都占一张同样大的卡，没有主次。
- 详情页（截图 02）从上到下：3 张大数字卡 → 结论 → 5 张周期量卡 → 发现 → 4 张形态卡，是一个长滚动页，一眼找不到重点。

### 2.2 看起来费劲

- **详情页上看不到血管上的场。** 最重要的东西不在这里：缩略图只有灰白几何，要看 WSS 必须跳到另一个页面。
- **视口空间需要按任务利用。** 截图 03 的血管已占较多高度，横向留白部分来自血管本身细长，不能简单放大到裁掉入口/出口。左侧约 350 px 菜单与顶部两层标签仍占空间；可收起菜单，把空白用于局部放大、沿程图或第二个字段，并保留完整血管概览。
- **默认色标可能压缩低 WSS 细节。** 原稿示例色标为 0–17 Pa，报告记录低于 0.4 Pa 的占比约 41%；这说明需要“低值观察”入口，尚不能据此认定低值就是本例的临床重点。现有面积占比是预测点占比估计，不能写成精确壁面面积测量。
- **形状读不出来。** 着色是平涂，没有光照，看不出凹凸和前后关系。
- **一次只能看一个场。** TAWSS 和 OSI 要来回切，「低 TAWSS 又高 OSI」的滞留区只能靠一个单独的勾选项。
- **一个病例分散在 5 个页面里**：详情、壁面报告、体场报告、一页纸、并排比较，每跳一次都要重新找视角。
- **并排比较挤。** 两个报告 iframe 各自带全套菜单和标题，视口被压得很小（截图 05）。

### 2.3 操作上

- 功能多，但散在折叠菜单里。壁面报告有四个标签，每个下面又有 3–5 个折叠卡，常用的和不常用的混在一起。
- 视角、口径、选中的位置在页面之间不共享。
- 沿程曲线、截面、探针、分支展开图其实都有，但各管各的，没有联动成一套「顺着血管看」的流程。

### 2.4 底层原因

- **报告是按任务生成并内嵌脚本、数据的静态 HTML。** 当前已有 `report_freshness.ensure_fresh` 按需刷新 UI，保留内嵌数组和元数据，失败时保留旧报告；并非每改界面都必须全量重建历史任务。真正的耦合是：界面版本跟着各份产物走，刷新、缓存、旧数据兼容需要额外管理。
- **三套三维查看器仍有重复实现。** 已有 `report_common.js` 共享色表和部分几何/交互函数，但视图状态、相机、标签、拾取与生命周期仍分散，需核对实际重复再抽取，不能把已共享的能力再造一遍。
- **2026-09-24 的范围是「前端只做快赢，不拆 app.js，不做设计令牌」。** 功能增长后需要重新评估模块边界，但当前复杂度不能归因于某一条裁定。本文建议重开讨论，不代表已推翻旧范围，见 B3。

## 3. 竞品与定位

| 类别 | 代表 | 可借鉴的交互 | 本工具拟聚焦的任务 |
|---|---|---|---|
| 通用 CFD 后处理 | EnSight、CFD-Post、ParaView | 联动视图、显式参数、可重复的后处理 | 减少为 AAA/WSS 常见问题反复配置的成本 |
| 临床血流报告 | HeartFlow FFRct、国内 CT-FFR | 结果摘要与空间定位相结合 | 说明本研究模型的多场结果及证据边界 |
| 血管术前规划 | 3mensio、Endosize | 中心线导航、垂直截面、直径曲线 | 把形态位置与预测场联系起来 |
| 4D flow MRI 后处理 | cvi42、CAAS MR 4D Flow | 多视图阅片、流线与时相组织 | 服务现有峰值场和周期派生量，不虚构时间序列 |

此表用于寻找交互参照，未做各产品版本的功能调研，不支持“别人没有”“医生看不懂”等排他性判断。创新优先体现在本项目的任务闭环与证据表达，不依靠未经核实的竞品空白。

**本项目已有、可以组合利用的基础：**

1. **快**：几十秒出结果，不用等 CFD，可以一次看很多例、反复比较。
2. **场多**：一根血管上同时有峰值 WSS、TAWSS、OSI、RRT、ECAP，再加体场压力和速度。
3. **中心线**：可关联分支命名、沿程曲线、截面和形态定位；全局场统计仍有独立的数据口径。
4. **队列参照**：
   - X5D 有 136 例 CV3 折外预测的空间 p99 分布；
   - 发布包有几何/采样范围参照，原稿记录为 29 条边界项，非 29 例人群分布；
   - M1 和 PF6/VF6 没有人群分布，见 D4。
5. **随访**：同一患者多次扫描已按病例归组，并有时间线。
6. **质量提示与可追溯性**：覆盖不足、粗糙、几何越界等规则叠加、质量门、审阅签字。这些是质量与处理记录，尚不是校准过的预测置信区间，也不证明医学正确性。

**定位（建议）**：做「沿血管阅读的血流动力学」，把 3mensio 那种顺着血管看的方式和血流场结合起来，不做又一个 CFD 后处理。一句话概括：**像翻 CT 层一样顺着血管看 WSS。**

## 4. 差异化视图（D）

每条按「是什么 / 为什么是差异 / 现有基础 / 成本 / 风险与未决」来写。

### D1 沿血管游标（核心交互候选，先做单分支验证）

- **是什么**：
  - 一个位置游标贯穿所有视图：三维里是一个环，沿程曲线上是一条竖线，截面图、展开图、数字面板全部同步到该位置。
  - 进入明确的“沿程浏览”工具后，滚轮或方向键移动站位；默认滚轮仍保留三维缩放。屏幕按钮提供同等操作，避免隐藏手势。
- **价值假设**：把旋转找位置变为连续沿程阅读；“像翻 CT 层”只描述操作习惯，当前截面不是 CT 影像。
- **现有基础**：沿程曲线、截面平面、探针和中心线弧长已存在。新增工作还包括站位定义、分叉选择、事件去回声与支撑判断，不能缩成“只加一个共享变量”。
- **位置契约建议**：记录结果身份、中心线版本、分支 id、分支内弧长 mm；按需计算显示用世界坐标。入口累计弧长另列字段，不与分支内弧长混用。
- **分叉策略**：沿当前支走到端点后停下，显示可选子支；记住本次会话的选择但不静默跳支。曲线先只展开当前支，其他支保留概览。
- **降级**：中心线缺失时保留三维拾取；截面切到多支或不闭合时提示不可用原因，不补出一个貌似正常的均值。
- **最小验证**：先做“一个游标 → 三维环 + 一条曲线 + 探针读数”，验证定位正确、键鼠不冲突，再联动体场与展开图。成本中等，依赖坐标合同，不依赖所有查看器迁完。

### D2 血管展开图

- **是什么**：
  - 把每条分支沿纵向剪开摊平：横轴是距入口的弧长，纵轴是周向角度，整个壁面一张图看完，不用转，也不会被遮挡。
  - 各分支按地铁线路图的方式排布，分叉处对齐。发现、阈值等值线、游标都画在上面。
- **价值假设**：用二维概览减少转动模型造成的遗漏；能否比三维加标准视角更快找全目标区域，需要实测。
- **现有基础**：`report.py` 里已经有 `branch_unroll_data`，提供每个预测点的 s、θ 坐标。但它藏在「统计」菜单的折叠项里，只是个散点小图。
- **成本**：中等偏高。要做连续的栅格化着色、分支布局和交互联动。
- **风险**：
  - **瘤囊处畸变大**：瘤囊不是管子，θ 映射在大直径、偏心段面积失真严重。可以标出面积比例，或者只对管状段展开、瘤囊另外处理。
  - **「前方」没有定义**：剪开线放在哪一侧、纵轴的「前」朝哪边，都需要患者方位参照，而方向侧车（N3）一直没做。候选：用中心线局部坐标系加分叉平面来定「前」，见 Q5。
  - **解释成本**：第一次看的人需要一句话说明，但不能又变成满屏小字。
  - **接缝与方向**：局部坐标架可能翻转、扭转；应验证平行移动坐标架或现有 frame 的连续性，记录接缝，不能把推断方向标成患者真实前方。
  - **统计与回定位**：栅格必须能映回三维原始点/面；空洞保留为缺失，不跨分支填色。展开像素面积不等于壁面面积，区域统计回到原数据口径计算。
- **止损验证**：先给一例管状分支和一例偏心大瘤囊做小样机。若使用者更难回定位或误认面积，就保留为研究辅助图，不进入默认首屏。

### D3 多场小图并排

- **是什么**：默认按任务提供两个视口，例如 TAWSS + OSI；大屏可扩展到四个。相机与位置可联动，各字段保留自己的单位和色标。
- **价值假设**：减少换场后记忆位置的负担；四图不应成为所有设备和任务的默认布局。
- **现有基础**：M1 已经有全部字段；并排比较已经有相机联动协议。
- **成本**：中等。现有 iframe 已能做双图联动，可作为过渡；不足是重复菜单、数据和 WebGL 资源，不是技术上做不了。
- **风险**：多视口会增加绘制、拾取和导出复杂度。先测双图，再比较独立上下文与单上下文 scissor；后者还需处理局部尺寸、遮挡和事件坐标。
- **解释边界**：RRT、ECAP 派生自 TAWSS/OSI，不能把多张相似彩图理解为多份独立验证。不同物理量可同步相机，不强行同步数值范围。

### D4 研究参照刻度（区分分布与范围）

- **是什么**：有分布数据的指标显示研究队列中的位置；只有上下界的指标显示训练范围，不伪造分布。示意文案如「空间 p99 17.0 Pa ｜ 本研究队列第 62 百分位」，其中数值仅作排版例子，实际须由兼容参照计算。
- **价值假设**：把孤立数字放回研究背景，帮助使用者提出问题；不据此定义患者风险。
- **现有基础**：
  - X5D 的 `reference.json` 里有 136 例 CV3 折外预测的空间 p99。
  - 几何侧车保存分支长度、中心线半径等量的训练最小/最大值及扩展边界，另有采样间距边界；“29 条”是边界项数量。可画同定义量的范围与越界位置，但没有逐病例几何分布供百分位计算；中心线半径不能直接替代瘤体最大 Feret 直径。
- **缺口**：
  - **现部署 M1 包的 `population` 是 unknown**，不能提供 TAWSS/OSI 的同口径分位；这不等于其他研究批次完全没有折外模型。
  - 03 块有 M1×v5.2 的 CV5 折外预测，但和部署中的 M1 发布包（v5.1 数据）不是同一个模型。能不能拿来当参照要单独裁定。
  - PF6/VF6 同样没有人群分布。
- **风险**：可能被误读成临床正常范围。文案必须写成「本研究队列的模型预测分布」。`reference.json` 的 caveats 已经写明「分位只表示在该参照分布中的位置，不是风险概率或临床阈值」。
- **显示条件**：同时注明统计量（例如空间 p99）、参照样本数、数据/模型协议与参照版本；分布尾部不伪造精密百分位。不能因字段同名就把 M1、PF6/VF6 放到 X5D 刻度上；不兼容时显示“暂无同口径参照”。
- **已有参照的限制**：X5D 侧车记录的是单 seed 折模型的折外分布，现部署使用五 seed 集成；这项差异要保留，不能把二者写成完全相同的模型分布。几何范围属于几何参照，不能借用 WSS 人群分位的图例。

### D5 讲解模式

- **是什么**：给组会、导师汇报和对外演示用。
  - 全屏，视口占满，字号加大。
  - 按已选证据书签的顺序定位，并配一行人工可编辑说明；自动发现只能提供候选。
  - 键盘翻页，也可以自动播放。
- **为什么是差异**：「便于观看」最直接的就是这个；现在演示时要一边讲一边手动点菜单。
- **现有基础**：发现列表已有「飞到」；视图状态可以保存和恢复；自动标注已有。
- **成本**：低到中。
- **建议**：第一版复用视图状态做手动书签列表（D10），允许排序与跳过。自动播放由讲解者启动，保留暂停、减少动效和回到原视图；播放不改变正式审阅状态。

### D6 随访差值图（候补）

- **是什么**：先做同一患者两次扫描的配对阅读，用解剖标志辅助定位；只有验证空间对应关系后，才考虑逐点差值图。
- **现有基础**：病例已按患者归组，已有患者时间线和并排比较。
- **成本与前提**：高。髂分叉同为零点仍不能保证同一组织对应，还需处理周向旋转、形变、截断、采样和模型/协议差异。当前只可比较同口径的分段摘要；几何相同的不同模型结果也要核对点索引才能相减。
- **建议**：作为独立候补，先验证解剖对应；不把 D2 实现作为证明配准有效的替代。

### D7 拉直血管视图（候补）

- **是什么**：类似 CPR，把每条分支沿中心线拉直成直管，保留场着色，左右髂动脉可以并排直接比较。
- **成本**：中到高，要做网格变形。
- **和 D2 的关系**：两者都试图减少遮挡，但保留/扭曲的信息不同。“拉直更符合医生直觉”是待验证假设；先比较定位任务，首轮最多选一个，也允许两者都不做，见 Q4。

### D8 按问题打开视图（低成本优先候选）

- **触发**：用户选择“低值区域在哪里”“同一位置的 TAWSS 与 OSI”“比较两次结果”三个明确问题之一。
- **行为**：调用现有预设，组合字段、布局、图例与工具；显示采用的范围和阈值，允许回到自由探索及撤销。名称不用“高危定位”“诊断”等结论词。
- **价值**：让用户从目的进入，而不必先学习四层菜单；也可将新手引导限制在当前任务。
- **边界**：预设只改变展示，不重跑推理、不修改原摘要，不把模板问题当成本例自动结论。
- **最小验证**：用静态可点击样机对照现有菜单，记录找到同一位置的时间、误选字段和求助次数。若无改善，保留普通预设入口即可，不增加一层导航。

### D9 证据透镜：点击一个值就能知道它从哪里来

- **触发**：点击发现、探针值或统计数字，右侧检查器显示一条来源链：**哪个结果 → 哪个位置/区域 → 预测或派生值 → 映射/聚合方法 → 支撑状态**。
- **具体例子**：对一个 TAWSS 值，区分“最近预测点”“壁面插值”“环上线长加权均值”；对体场截面，区分 Barnes 补全热图与 Voronoi 面积积分；对 RRT 显示来源、公式约定及截断/无效处理。
- **价值**：把方法说明变成在疑问发生处可查的证据，避免漂亮表面让使用者误以为每个像素都有真实预测样本。
- **边界**：覆盖、几何参照、局部采样支撑分开显示，未知写未知；没有校准误差模型就不生成“可信度 92%”。
- **最小验证**：复用字段描述符、trust、探针数据，先做一张来源面板。让使用者解释三种读数的区别，检查是否把“补全”误当成“测得”。

### D10 可复现的证据书签（连接探索、讲解和出图）

- **触发**：找到关注位置后点“保存关注点”，填写一句观察或疑问。
- **内容**：结果身份、数据与查看器版本、字段/单位/范围、分支和站位或 ROI、相机、过滤条件、人工备注。最低成本实现为现有视图 JSON 的扩展与本地导入/导出，不先建设多人协作系统。
- **价值**：同一个书签可用于恢复阅读、讲解排序、生成带口径的图件；比截图多一个“回到证据现场”的入口。
- **边界**：书签不是审阅签字；本地保存与已提交到服务明确区分。结果或坐标合同变化时提示不兼容，保留旧书签，不悄悄吸附到新位置。
- **最小验证**：另一位使用者重新打开书签，核对字段、位置、阈值和读数；离线报告也能恢复。URL 只放非敏感状态或现有不透明标识，不嵌入口令、患者姓名或服务器路径。

### D11 比较前核对口径（优先于差值图）

- **触发**：选择两个结果后，先显示一条可展开的“比较条件”：字段、单位、时相/周期定义、发布包与协议、几何范围、统计定义。
- **行为**：明确选择“同尺度看幅值”或“各自增强细节”；前者只对兼容字段统一色标及数值范围，后者醒目标明每图范围不同。模型版本不同可成为比较目的，但差异原因不能被抹掉。
- **价值**：防止两个自适应色标把不同幅值画成同一种红色，或把不同范围的 p99 当成疾病进展。
- **边界**：相机同步、位置对应、标量可比、逐点可比是四件事。兼容性不足仍可并排观察，但不给无依据的差值或好坏排名；具体条件沿用现有比较合同再增补。
- **最小验证**：同字段不同色标、单位可换算、协议不兼容、缺方向参照各放一对样例，检查用户是否理解哪些操作有效、哪些只能定性看。

### D12 阈值敏感性预览与区域刷选（研究辅助候选）

- **触发**：在直方图选择一个值域，三维与沿程图高亮对应原始样本；拖动阈值时同步显示占比曲线。后续可组合“低 TAWSS 且高 OSI”，首版只做一个字段。
- **价值**：回答“发现是否主要由阈值选取造成”“哪些位置贡献了这个统计数”，把数值分布与空间位置联系起来。
- **边界**：明确写“探索阈值”，使用字段自己的单位；点占比、现有面积估计、精确面积积分不可混写。阈值变化不是模型不确定性，交集条件也不是验证过的风险模型。
- **最小验证**：复用已有点数组做范围筛选，验证切单位后高亮集合不变、恢复后与原摘要一致、导出记下探索条件。若高频拖动阻塞主线程，先节流并在松手时计算，不急着加 worker。

### 4.1 怎样筛选创意，避免功能清单无限变长

每个候选只回答四项：**替用户省了哪一步、复用了什么、最大的错误解释是什么、什么结果会让我们停止做。** 不用虚构精确的 ROI 分数。

| 优先层 | 候选 | 首次投入边界 | 继续的条件 |
|---|---|---|---|
| 先验证 | D8 问题入口、D9 证据透镜、D10 书签、D11 比较条件 | 选择一条任务链，不同时全面实现四项 | §8 的任务测量改善，语义错误不增加 |
| 核心交互试验 | D1 单支游标、D3 双图 | 不先迁完全部旧功能 | 联动位置一致，用户能更快回答空间问题 |
| 按需求扩展 | D4、D5、D12 | 有兼容参照、有讲解需求或确有阈值问题时再加 | 用户真实使用，而非仅在演示里显得丰富 |
| 独立可行性研究 | D2、D6、D7 | 小样机/离线验证 | 映射可解释且可回定位；未满足就保留候补 |

## 5. 视觉（V）：信息清楚，风格克制

### 5.1 气质方向（待选，见 Q6）

| 方向 | 参照 | 特点 | 适合 |
|---|---|---|---|
| A 阅片工作站 | PACS、3mensio | 高密度、多视口、工具条紧凑 | 医生日常阅片 |
| B 期刊插图 | Nature/JBiomech 方法图 | 白底、细线、克制、数字排版讲究 | 汇报、出图、一页纸 |
| C 工程仪表 | EnSight、示波器 | 参数全部外露、密度最高 | 研究者调参 |

**建议**：整体用 B（浅色、克制、期刊感），视口和工具条的密度借 A。C 的东西收进「技术信息」。

### 5.2 原则

- **V1 视口优先，但以任务为准**：桌面探索布局以视口占主要空间为目标，约 60%–75% 可作为样机起点，不是硬门槛。先让模型自动适配有效视口，避免放大整块灰背景；读数与色标不被遮挡，键盘焦点、触控目标和缩放后的文字仍可用。
- **V2 排版代替卡片**：
  - 数字用表格对齐，等宽数字，细线分隔；
  - 优先平面布局、细分隔线，减少嵌套卡片；圆角与阴影按层级用途判断，不设审美一票否决；
  - 状态使用可读文字，色点只作辅助；锁定、失败、待处理必须可区分。
- **V3 颜色留给数据**：界面本身只用灰阶加一个强调色，语义色只用在警告和错误上。
- **V4 文案按需出现**：
  - 删掉无任务价值的问候语；首次使用保留可关闭的短引导，空状态说明下一步；
  - 共通术语集中解释；局部缺失、截断、低支撑等会改变判断的信息留在读数附近；
  - 全局研究用途说明集中呈现，导出报告也保留；不能用页脚一句话替代具体限制；
  - 数字带单位与必要的统计标签，如“空间 p99”，不用“优秀/危险”等未经验证的评价词。
- **V5 图标**：一套 20 个左右的细线 SVG 图标，放进仓库，不用 Unicode 字符。
- **V6 形状与读色分工**：
  - 定量读图建议默认平涂，辅以轮廓线或可切换的灰色几何；讲解预设可启用柔和光照；
  - 若采用光照，标明其用于形状观察，保留平涂切换；不能用受光照影响的颜色精确估值；
  - 探针取合同规定的数据值，不从屏幕颜色反算。默认是否调整见 Q10，尚未改变现行界面。
- **V7 色标**：
  - 色标旁可嵌直方图，注明是“采样点分布”还是面积加权分布；显示筛选分支、有效样本与缺失比例，不用展开像素作分母；
  - 阈值随字段切换，0.4 / 4 / 7 Pa 仅是现有 WSS 观察阈值，不能复制给 OSI、压力等量，也不包装成已验证临床界值；
  - 低值观察可用显式分段或对数预设；注明变换、零值/非正值处理、上下界截断比例。对数不能直接用于跨零的相对压力；
  - **彩虹默认作为历史裁定保留**，同时提供 viridis 等现有色带供比较；评估色觉差异、灰度打印和亮度伪边界后再讨论默认值，不以审美推翻偏好；
  - 自适应范围适合看本例细节，固定范围适合同字段跨例比较，两种模式应明显可辨并写入导出。
- **V8 字体与可及性**：中文用系统黑体，数字用等宽数字（tabular-nums）；用少量层级但不限制必要辅助文字。验证 200% 缩放、清晰焦点、文字对比度，图例不只靠颜色区分状态。
- **V9 动效与等待**：保留有定位意义的过渡，并支持减少动效；显示真实加载阶段和可取消状态。骨架屏不是必需，也不一概禁止，不能用假进度掩盖长时间阻塞。

### 5.3 可用性与表达检查表（替代纯审美否决）

**硬性不通过**：病例/结果身份混淆；单位、字段或时相错误；缺失值显示为 0；颜色截断或统计口径被隐瞒；低支撑被包装成正常；键盘无法退出工具；重要操作在窄屏或放大后不可达。

**任务验收**：主场与图例首屏可见；找到位置后能看到相关数值；能判断两图是否同尺度；能撤销探索并恢复；导出保留读图所需的来源与口径。具体任务见 §8.2。

**风格复核**：去掉无信息数字卡、装饰性嵌套、重复免责声明和营销用语；统一图标与排版。圆角、灰字、标签本身不判失败，只有妨碍阅读或产生误导才需要改。

## 7. 架构（A）

- **A1 共享机制，保留领域适配器**：
  - 以已有 `report_common.js` 为起点，从壁面、体场和工作台查看器渐进抽取相机、颜色映射、拾取事件、游标协议、标签、导出和资源生命周期的共用机制；
  - 壁面插值、壁面环均值、体场截面积分、流线各保留明确实现，避免把物理含义不同的操作统一成一个 `average()`；
  - 工作台壳负责列表、路由、审阅和保存；查看器只消费数据与状态、发出操作事件，不自行管理登录或任务写入；
  - 壁面/体场适配器声明支持的字段与功能，壳据此显示工具；缩略图只加载需要的能力。先用普通模块接口，不建设通用插件平台。

  目标是让同一规则只维护一处，同时保留可测试的差异。首个抽取以“壁面和体场各显示一个字段”验证边界，不能等壁面整页迁完才发现体场不适配。
- **A2 报告 = 查看器 + 数据**：
  - 在线页面通过同一份版本清单（manifest）获取该结果的数组，借鉴 `/geometry` 的 ETag 思路；但 `/geometry` 当前是预览几何，不含完整场，不能直接替代科学数据接口；
  - 数据读取接口沿用现有身份/任务访问检查，只读不等于公开。缓存键绑定结果和数据版本，不能只按文件名缓存；
  - 离线导出固定版本、无外部依赖的查看器脚本与内嵌数据，`file://` 打开无需服务。在线与离线共享源码和数据解码合同，不维护两份业务逻辑；
  - 在线兼容数据可使用新查看器而无需重建每个任务；旧 schema 仍需适配。`report_freshness` 在旧入口仍使用时保留，待迁移覆盖和回退路径验证后再讨论退役；
  - 旧 `report.html` 保持可用，已导出的离线文件保持快照。归档记录 `viewer_version + data_schema + run_identity + view_state + exported_at`，在线新外观不能冒充原图精确复现；
  - 离线报告显示“导出时审阅状态”，不伪装为实时状态，不承诺离线编辑已提交服务。
- **A3 页面渐进合并**：见 O1。先复用现有独立报告或 iframe 接入工作区，内核稳定后再替换；双视口优先，四视口依据资源实测决定，不把去掉 iframe 当作第一期成功标准。
- **A4 技术栈**（先验证交付约束，再选框架）：

| 选项 | 优点 | 缺点 |
|---|---|---|
| 原生模块，最小依赖 | 便于渐进复用已有代码；Python 可托管静态产物 | 状态订阅、销毁、DOM 更新需清晰约束；现有 Node 桩用 `require`/VM，迁到 ESM 需要适配 |
| Preact + htm 或其他轻量组件方案 | 工作区面板与状态驱动 UI 较易组织 | 需验证组件生命周期与 three 对象的边界；依赖固定版本并本地交付 |
| Vite + Vue/React 等构建方案 | 可组织复杂 UI，静态产物可复现 | 增加开发/CI 工具链和产物管理；需评估团队维护成本，并非要求集群安装构建链 |

  **建议**：先沿用原生 JS 和 r128，抽取小模块；是否引入轻量打包器与是否引入 UI 框架分开决策。在线 ESM 可以保留，离线需要单个自足脚本；直接拼接带 `import/export` 的文件不能保证单 HTML 可用。P0 用真实离线导出验证打包路线，禁止靠维护第二份查看器解决。框架选择不决定视觉风格；产物可随发布包交付，是否入 Git 另按发布规范决定。

- **A5 three.js 版本约束**：本轮先保持 r128。r163 起 WebGLRenderer 移除 WebGL1 支持；原沙箱截图链路记录为 WebGL1，因此 r162 是维持这条链路时的候选上限，不是永久架构上限。升级引擎另做浏览器/GPU、色彩管理、控件与截图基线验证；不能仅凭版本号低于上限就认为兼容。
- **A6 新旧并行**：
  - 新界面挂在新路径上（比如 `/v2/`），旧页面一直能用；
  - 首先按任务能力逐项切换，未迁移功能保留旧入口；验收后再讨论默认入口切换；
  - 新旧读取同一权威业务状态，视图本地存储使用不同版本命名空间。回退只切入口，不要求重跑模型或改回预测数据。
- **A7 测试**：
  - 保留旧启动桩，新入口另加对应检查；单测聚焦单位换算、坐标/站位、状态隔离、缺失值和版本适配，不给每个 DOM 包装函数机械加测试；
  - 截图套件覆盖新页面，固定窗口、相机、字段、色标和动效；像素差辅助发现布局问题，字体/抗锯齿允许合理差异；
  - 真实浏览器验证拾取、键盘焦点、双视口、导出和离线 `file://`；0 JS 错误只能说明未捕获到异常，不能证明数值、截图和操作正确；
  - 异常路径至少覆盖旧 schema、缺字段、快速切例、断线重连、审阅 409 冲突、WebGL 不可用/上下文丢失；完整任务验收见 §8.2。

### A8 状态合同：区分偏好、位置、业务事实

| 状态 | 真源与寿命 | 切换/恢复规则 |
|---|---|---|
| 用户偏好：布局、标签语言、兼容配色 | 版本化本地偏好或已有偏好接口 | 跨结果继承前校验字段能力 |
| 阅读位置：相机、游标、探针、截面、ROI | 按 `run_identity` 及几何/坐标合同隔离的视图状态 | 同结果恢复；跨结果必须显式映射，失败复位并说明 |
| 业务事实：计算状态、审阅、发现判定、标注 | 服务端现有接口及版本号 | 写入成功后才显示已保存；冲突读回新版本，不能客户端强覆盖 |
| 暂态：悬停、拖动预览、加载请求 | 当前视图实例 | 退出即释放，不当作长期记录 |

补充约束：

- 现有视图 JSON 的相机是世界坐标，跨报告联动使用解剖坐标架；适配器显式转换，变量名和接口不能混用两者。方向来源未知时保留推断提示。
- 游标事件带来源视口与更新序号，接收方不回发同一事件；不在每次拖动时刷新病例列表或整页 DOM。
- 快速切例取消过期请求；即使取消未成功，回包也须核对 `run_identity`、请求序号和数据版本，避免前一例覆盖后一例。
- 大型 TypedArray 和 three 对象保存在数据/渲染层，store 只存标识、参数与状态，避免每次状态更新深拷贝网格。
- 先保留 v1 视图导入适配；新字段缺失有明确默认，未知 schema 提示不支持，不猜测还原。

### A9 数据合同：显示面、预测点、统计量分别命名

建议只读 manifest 至少包括下列信息；这是待实现合同，不能误记成现有 API 已提供。

| 组 | 必须明确的内容 |
|---|---|
| 身份 | schema、结果身份、输入/几何指纹、发布包、分析版本 |
| 几何与坐标 | 预测点与显示网格分别标识；单位、坐标变换、方向来源、中心线/分支版本 |
| 字段 | 字段 id、定义、单位、位置（点/顶点/单元）、时相或周期定义、预测/派生来源 |
| 数组 | URL 或内嵌键、dtype、shape、字节序、长度、版本/内容指纹、有效值掩码 |
| 映射与统计 | 插值方法、支撑标记、统计取样来源与权重、派生公式及其无效值处理 |

一次加载固定 manifest 版本，再取其引用的数组；长度、字段位置或指纹不匹配时停止该字段显示。缺失不填 0，不使用上一例数组补位。简化网格只用于显示，不反过来成为现有指标的统计真源。

### A10 性能方法：先量预算，再决定优化

先在约定浏览器、窗口、网络和目标笔记本上记录旧版基线，包含冷/热缓存和一个较大病例。看首个可操作时间、换场延迟、游标响应、长任务、双图内存与导图峰值，不用一个平均 FPS 掩盖卡顿。

- **建议起始目标，P0 后校准**：已加载字段切换和游标轻量反馈 p95 ≤ 100 ms；较慢截面积分可异步更新并标示计算中。持续拖动争取 ≥ 30 fps；首屏时间与内存上限依据真实网格和设备冻结，当前不虚报毫秒数。
- 先做数组只解码一次、按需渲染、不可见视口停绘制、较重工具延迟加载；显示用低分辨率预览不能改变拾取与统计数据来源。
- 明确 `dispose` 几何、材质、纹理、控件、事件、订阅、计时器和请求；同一组病例连续切换 20 次，内存应趋于稳定而非单调增长。观察 GC 后稳定区间，GPU 资源计数只作辅助，不伪装成精确显存测量。
- 只有实测主线程阻塞才引入 worker；只有多视口成本成为瓶颈才切 scissor。每个优化都保留数值一致性和回退路径。

## 8. 实用方法论：先验证一条完整任务，再扩大迁移

### 8.1 分期与退出条件

原稿“全量约 3 周”缺少人员投入、旧功能复杂度与离线打包验证，不再作为交付承诺。下面是工作顺序；每期估算应在前一期结束、风险已验证后给出。P0 可先安排 2–3 个工作日的探索时间盒，表示届时汇报发现，不保证所有疑问已解决。

| 期 | 交付内容 | 本期通过条件 | 可以停在哪里 |
|---|---|---|---|
| P0 问题与技术探路 | 任务基线；2 个工作区样机；真实壁面/体场各显示一字段的技术小样；离线打包试验；功能迁移清单 | 明确首要使用者任务；验证坐标、数据加载、`file://` 和旧报告兼容；列出实测成本 | 如果瓶颈主要是入口与文案，先交付小改，不启动全面重构 |
| P1 首条完整任务 | 打开结果 → 看主场 → 定位关注处 → 查来源 → 保存书签 → 导出并离线复开；选择 D8–D11 的必要部分 | 同一条任务在真实浏览器走通；旧功能可从旧入口使用；§8.2 软件阻断错误为零，关键误读有处理记录 | 即使不做展开图，用户也得到完整可用的改善 |
| P2 工作区与可靠比较 | 病例导航、双图、按结果恢复状态、D1 单支游标；复用审阅与导出接口 | 快速切例不串状态；兼容性提示准确；异常恢复与回退有效 | 达到日常使用收益后可暂缓其他视图 |
| P3 逐项迁移 | 壁面/体场剩余工具、一页纸；按附录 A 补齐原功能 | 迁移矩阵逐项有入口和证据；选定旧入口才能退役 | 未迁功能继续保留旧路径，不要求一次删完 |
| P4 有证据的扩展 | 依据试用选择 D2、D3 四图、D4、D5、D12；D6/D7 独立评估 | 每项回答一个已观察到的问题，有定位/理解收益 | 无收益或科学对应关系不足时停止，不为凑功能继续 |

范围选项改为：**(a) 入口/布局与文案改善；(b) P0 后优先完成 P1–P2；(c) 按验收逐步完成迁移与选定扩展。** 建议先按 (b) 讨论资源，保留走向 (c) 的路径，不一次批准全部创意。

### 8.2 可用性验证：用同样的任务比较新旧界面

先记录现有界面的基线，再邀请 3–5 位目标使用者做形成性试用；若暂时没有医生参与，只能报告组内可用性，不能据此宣称临床易用。用两组难度相近的病例交换新旧界面顺序，避免熟悉病例造成假改善。

| 任务 | 观察项 | 必须追查的软件错误或关键误读 |
|---|---|---|
| 找到一个低 WSS 区并说明当前显示 | 完成与否、时间、求助/误选次数；能否说出单位、时相、阈值 | 把颜色深浅当成可直接跨图比较的数值，把观察阈值当临床界值 |
| 在同一位置查看 TAWSS 与 OSI | 定位是否一致、是否理解 RRT/ECAP 来源 | 切字段后位置漂移或把派生量当独立证据 |
| 查看一处无覆盖/低支撑截面 | 是否发现限制、是否能说出原因 | 将补全值当作直接样本；无效值显示正常 |
| 比较两份结果 | 是否辨识协议、范围、单位与色标差异 | 条件不兼容却给无提示的差值/好坏结论 |
| 保存关注点 → 换例 → 返回 → 导出 → 离线恢复 | 是否回到同一结果、位置和口径 | 串病例、丢未保存编辑、导出与屏幕口径不一致 |

软件语义/状态错误（串病例、错误单位、无效值显示正常等）必须修复后再通过。使用者的关键误读则记录诱因、修改提示并复测相关任务；未解决时限制相应功能的默认曝光。3–5 人都未误读不证明其他使用者一定理解，也不能将单个人的困惑直接等同为整期软件失败。

记录中位耗时、完成率、求助次数和具体误读，不把小样本结果包装成显著性检验。**候选改善目标**：主要任务耗时中位数降低约 20%，或步骤减少；P0 后按基线冻结，结合理解情况判断，不能成为独立通过条件。样机更漂亮或操作更快，均不能抵消未处理的关键误读。

### 8.3 工程验收：让错误可定位、回退可执行

1. **建立迁移矩阵**：给附录 A 每项补“旧入口 / 新入口 / 依赖接口 / 验证案例 / 未迁原因”。功能不减是能力仍可达，不是要求保留旧菜单排列。
2. **固定代表样本**：至少覆盖普通病例、大瘤囊、分支/截面困难、较大网格、缺字段旧报告；主要复用已有任务或合成测试夹具，不为前端验收启动新训练与测试集评估。
3. **一条变更一个可观察结果**：先抽共用模块并保持行为，再改交互默认；引擎升级、统计算法变更与布局迁移分开，便于追查回归。
4. **校验三条链**：数据值/口径一致；位置/交互正确；导出/离线可复现。截图只覆盖第三条的一部分，后端黄金回归也不覆盖前端所有计算。
5. **验证退出方案**：在沙箱演练切回旧入口，确认新视图状态不会破坏旧页，服务端审阅状态仍一致。上线流程另按现有运维规定执行。

### 8.4 讨论如何变成决定

对每个有争议的选择只写一条短决策记录：`问题 → 可选方案 → 已知证据/未知 → 暂选及理由 → 何时重开`。例如“先保留 r128”不是拒绝升级，而是本轮无需增加该变量；当现有版本阻挡必要能力时再评估。对于 D2 等创新，先约定停止条件，再投入样机，避免做完后只能为沉没成本找理由。

## 9. 边界草案（B）

## 10. 风险与反方观点（R）

- **R1 重写引入回归**：细节功能很多，比如截面 gizmo 的拖动、旋转、平移，截面补全，探针对照表，发现审阅等，重写容易丢细节。
  → 对策：附录 A 逐项对齐，新旧并行，老页面不删。
- **R2 用户已经习惯现在的界面**：医生和导师看过现在的版本。
  → 对策：默认视图的信息保持相近，只改呈现；讲解模式可以先给导师试用。
- **R3 光照改变颜色明度，导致读色不准**。
  → 对策：定量任务优先平涂，讲解预设可开柔和光照，探针直接读数据；默认值仍按 Q10 讨论。
- **R4 展开图难解释、有畸变**。
  → 对策：先做管状段与大瘤囊小样机，验证接缝、缺失和三维回定位；没有可靠面积映射时不编造畸变校正，降为研究辅助图。
- **R5 人群刻度被当成临床正常范围**。
  → 对策：文案固定写成「本研究队列的模型预测分布」；没有参照的量不显示刻度，不编造。
- **R6 离线单文件和在线 API 是两套数据路径**。
  → 对策：内核只认一个数据加载接口，两条路径只是来源不同。
- **R7 工作量低估**：旧功能对齐、浏览器差异和离线交付的成本尚未测量。按 §8 的技术小样与任务清单滚动估算，不再承诺全量 3 周。
- **R8「去 AI 味」是主观判断**。
  → 对策：风格与任务通过分开记录，先看完成率、误读和恢复能力，再选气质。
- **R9 一次改太多，无法二分定位问题**。
  → 对策：每期单独提交、单独验收、单独上线。
- **R10 共享内核变成新的大文件**：所有行为用 `if family` 拼起来，会把三套复杂度搬到一处。→ 共享稳定机制，领域算法保留适配器；两族各一条任务先验证抽象。
- **R11 “更可信”的外观放大过度解读**：光照、连续填色、百分位刻度会增强确定感。→ 来源与支撑就近可查，原始点/补全/派生可辨，不新增没有校准依据的概率。
- **R12 异步与缓存造成串例/旧状态覆盖**：工作区合并后比跳页更容易发生。→ 按结果隔离状态与缓存，回包校验身份/序号，覆盖快速切例与重连测试。
- **R13 导出变漂亮但无法复现**：默认色标、阈值或插值版本变化后，同一数据可能画出不同图。→ 固定查看器/数据版本与视图状态，保留旧离线快照；新版本只能声称数据兼容，不能默认为像素相同。
- **R14 模型问题被界面掩盖**：低值预设、平滑或裁切可能令误差区域不显眼。→ 保留全范围/原始支撑入口；可视化改善不作为模型精度提高的证据。模型发布与前端重构分别排期。

**投入判断建议**：若真实阻塞是模型适用性或发布包缺失，就优先补科学证据；若问题是使用者读错现有结果、反复找菜单或无法复现，则先投入 P1 的任务闭环。两项可以独立推进，不以“大重构”作为继续研究的前置条件。

## 13. 使用者与医生视角的补充审视（v0.3，2026-09-30）

> **做了什么**：只读核对了代码、发布包、7 张现状截图和一例真实任务（LV_GUO_YOU · M1 三头）；用 136 例折外预测算了发现规则的触发率。没有改代码，没有动服务。
> **没做什么**：没有访谈医生。下文标「推断」的是我对医生习惯的判断，需要找一位血管外科医生过一遍；标「已核对」的有代码、截图或数据为证。

### 13.1 结论

医生用这个工具要走六步：把数据送进来 → 等结果 → 判断能信多少 → 读懂 → 和上次或别人比 → 带走。v0.2 把「读懂」这一步想得很细（游标、证据透镜、书签、比较条件），其余五步基本没碰。现在的短板主要在三处：

1. **进门**：只收恰好 5 个开口的管腔 STL，界面上没有一处写明。
2. **能信多少**：验证数字就在发布包里，界面上一个都没有；给出的「模型集成稳定」容易被读成「结果准确」。
3. **说了什么**：首屏三张大卡是 p99、单点最大值和计算耗时；直径没写明是管腔；高值一侧的「关注」标签几乎每例必出。

这三处大多是文案和分析层的改动，不依赖前端重构，可以先做（§13.5）。

### 13.2 两类人，两件产品

| | 操作者 | 读者（医生、导师、听汇报的人） |
|---|---|---|
| 现在是谁 | 你本人（Q16 已裁定） | 看离线报告、一页纸、投屏的人 |
| 以后是谁 | 可能加上培训过的医生 | 同上 |
| 接触什么 | 工作台：上传、确认、批量、复核、导出 | 离线报告、一页纸、投屏讲解 |
| 要什么 | 快、批量、不出错、可复现 | 一眼看懂、知道边界、能放进病例讨论 |

推论：

- 工作台按操作者优化，离线报告和一页纸按读者优化。
- 读者版必须脱离工作台也能自己说清楚：适用范围、能信多少、每个数是什么。
- §1.5 的四个场景可以并成这两类，Q1 不必在四种角色里排序。
- 操作者以后会包括医生，所以工作台多一条要求：**能教会**。见下面 U22–U25。

**U22 基本流程要能在一次培训里教会**

- 医生要学会的只有四步：上传 → 核对单位和出口 → 看结果 → 出一页纸。
- 建议工作台分「基本」和「完整」两档显示，默认基本。
  - 基本：只有上面四步用得到的东西。
  - 完整：批量、换发布包重跑、队列总览、技术信息、完整统计 JSON。
- 这不是做两套界面，只是把不常用的收起来。和 v0.2「角色只改变初始布局」一致。
- 验收办法：找一位没用过的人，给一页操作卡，看能不能独立走完四步。记录卡在哪一步。

**U23 培训材料跟着工具一起发**

| 材料 | 内容 | 现状 |
|---|---|---|
| 示例病例 | 只读，打开就能看结果 | 没有（U1） |
| 输入说明 | 要什么样的 STL，分割软件里怎么导出 | 没有（U1） |
| 一页操作卡 | 四步流程，每步一张截图 | 没有 |
| 报错对照表 | 每条报错是什么意思，该怎么办 | 报错文案有，对照表没有 |

- STL 由谁来做要先定（Q26）。医生自己分割的话，输入说明是培训里最重的一块。

**U24 每位医生一个账号**

- 现状（已核对）：已有用户名登录，任务按所有者隔离，管理员能看全部；加账号用命令行。
- 要补的：医生之间互相看不到病例；医生离开后病例交给谁。
- 病例名脱敏（U19）在医生自己上传以后更要紧。

**U25 医生在哪里用**

- 现在服务只在组内网络。医生在医院里用，牵涉网络访问和病人数据出院。
- 这一条不是前端能解决的。你 09-30 裁定：先不考虑，部署方式以后再定（Q25）。

### 13.4 逐项说明

每条按「证据 / 对医生的问题 / 建议 / 成本」写。

#### 进门

**U1 输入要求没有写在界面上**

- 证据（已核对）：`ingest.py` 要求开口数恰好为 5，否则报「开口数 N ≠ 5」。上传对话框只写「选择血管壁面 STL」「上传后自动检查开口」。README 和界面里没有任何分割软件的导出说明，也没有示例文件。
- 问题（推断）：医生手里是 CTA。分割软件导出的常是封闭面，或带着肾动脉、腰动脉的残端。一侧髂内闭塞或已栓塞的病人只有三个出口。这些人第一次上传就会失败，而且不知道为什么。
- 建议：
  - 上传对话框放一张示意图和四句话：要管腔面；入口和四个髂支出口切开；其余分支封闭；单位。
  - 提供一份示例 STL 和一个只读的示例病例，没有数据也能先看到结果长什么样。
  - 适用范围写明「四个髂支出口都通畅的腹主—髂动脉」，三出口目前不支持（Q21）。
- 成本：低，文案和静态文件。

**U2 失败之后不知道改哪里**

- 证据（已核对）：失败页给出检查表（开口数、连通片、尺寸）。每个开口的中心和等效半径已经算出来了（`opening_geometry`），但没有画到三维里。
- 建议：失败页画出血管，给每个开口编号并标半径；半径明显偏小的开口提示「可能是没封闭的分支残端」。只提示，不自动修。
- 成本：中，前端工作，数据已有。

**U3 在工具里封闭多余开口、接收封闭面或掩膜（候选，不进本轮）**

- vessel_geom 已有封闭面切口流程；v0.10 提过「掩膜上传」，没有开。
- 先做 U1、U2，看输入失败还剩多少，再决定。

#### 能信多少

**U4 验证数字没有出现在界面上**

- 证据（已核对）：M1 发布包 `release.json` 里有 34 例留出结果。工作台、两份报告和一页纸的代码里搜不到这些数。

| 量 | Pa 口径 R² | 其他 |
|---|---|---|
| 峰值 WSS | 0.74 | 逐例均值 0.77 |
| TAWSS | 0.74 | 一致性系数 0.93 |
| OSI | 0.56 | 最差十分之一病例 0.36 |
| 滞留区 | — | 与 CFD 的重叠度（IoU）0.56 |

- 问题：首屏上「最大直径 72.2 mm」「TAWSS 均值 0.665 Pa」「OSI 均值 0.135」「滞留区 46%」字号和样式完全一样，可靠程度却差得很远。第一个是量出来的，最后一个是两个预测量再做阈值交集。
- 建议：每个数带一个来源标记，全工具和一页纸统一成三档。
  - **几何测量**：从输入表面量出，不经过模型。
  - **模型预测**：附该量在留出集上的一致性。
  - **派生量**：由预测量算出，没有单独验证。
- 成本：低到中。数字都在发布包里，做一张「字段 → 档位 → 验证数」的静态表即可。

**U5 「模型集成稳定」容易被读成「结果准确」**

- 证据（已核对）：一页纸关键数字里有一张「集成质量：模型集成稳定」卡，含义是几个 seed 之间差异小。
- 建议：改成「多模型一致」，旁注「一致不代表准确」；或者收进技术信息。
- 成本：低。

**U6 局限性声明里缺「标准血流条件」**

- 证据（已核对）：`onepager.limitations()` 现有几条讲的是时相、压力相对量、面积估计、适用几何、患者方向，没有一条提入口流量。训练用的 CFD 协议对所有病例用同一条入口流量波形，平均流量 30.38 mL/s（约 1.8 L/min），周期 0.8 s（`cfd_auto/sanity.py`）。
- 对医生的含义：预测的是「这副几何在标准血流下的 WSS」，不是这位病人此刻的 WSS。心输出量、心率不同，绝对值会变；空间分布的形态相对稳定。0.4 Pa 这类界值也以标准血流为前提。
- 建议：放在局限性声明第一条。壁面是否按刚性处理、血液模型等其余假设，核对 CFD 协议后一并写进模型说明卡（U7）。
- 成本：低。

**U7 模型说明卡（每个发布包一页）**

- 内容：
  - 训练数据：多少例、哪三类病人、单中心。
  - CFD 协议的假设（U6）。
  - 留出集一致性（U4 的表）。
  - 已知薄弱处：小口径髂支的高值容易被低估；OSI 和滞留区的边界只能用来定位；瘤腔里绝对误差小但相对误差大（依据 09-21 最差病例分析）。
  - 不适用：非五开口、其他血管、含血栓或管壁的外轮廓。
- 报告和一页纸各放一个入口。
- 成本：低，一份文档加一个链接。

**U8 按位置类型给典型误差（候选）**

- 用折外预测按局部管径、分支、是否瘤体分箱，得到「同类位置的典型误差」，在探针卡里显示。
- 这是验证集统计，不是本例的不确定度，和 09 月「不展示 seed 离散度」的裁定不冲突，但需要你拍板（Q17）。
- 成本：中。要先离线算出分箱表，随发布包发。

#### 说了什么

**U9 直径没有写明是管腔直径（优先级最高）**

- 证据（已核对）：`narrative.py` 写的是「主动脉最大直径 72.2 mm（截面最大 Feret 直径）」；没有瘤体时写「未见瘤样扩张（< 1.5 × 参考直径）」。只有术语表里提到「管腔轮廓」。
- 问题（推断，请医生确认）：临床说的瘤体直径量到外壁，包含附壁血栓；这里的输入是管腔面。有血栓时两者可以差很多。
  - 医生拿这个数和 CT 报告对不上，会直接怀疑整个工具。
  - 血栓填满瘤腔时管腔接近正常，「未见瘤样扩张」就是错的。
- 建议：
  - 所有位置改称「管腔最大直径」。
  - 首次出现处加一句：不含附壁血栓与管壁，通常小于 CT 报告的瘤体直径。
  - 无瘤句改成「管腔未见瘤样扩张，不能据此排除动脉瘤」。
- 成本：低。属于结论文案变更；审阅人已经手改过的文本不动。

**U10 首屏三张大卡选错了量**

- 证据（已核对，截图 02）：全场 p99 17.01 Pa、全场最大值 52.60 Pa（左髂内）、计算耗时 8 秒。
- 问题：
  - p99 是统计量，没有解剖位置。
  - 全场最大值是单点极值。`analysis.py` 自己给它的定义是「对噪声敏感，仅作参考」，它却占了首屏一张大卡。
  - 计算耗时和读结果无关。
- 建议：首屏按解剖分区给数。
  - 分区：近端瘤颈、瘤体、左右髂总、髂外、髂内。
  - 每区：TAWSS 均值、低剪切占比、OSI。
  - 左右髂支并排，给左右比值。同一个病人的对侧就是现成的对照。
- 可行性（已核对）：`morphology` 已有瘤体和瘤颈的弧长范围，每个预测点已有弧长，分区统计不用动模型。
- 成本：中，分析层加分区统计，前端加一张表。

**U11 峰值帧沿用了时间平均量的界值**

- 证据（已核对）：0.4 / 4 / 7 Pa 三个界值直接用在收缩期峰值帧上。136 例折外预测里：

| 规则 | 触发的病例占比 |
|---|---|
| 峰值帧最大值 ≥ 7 Pa（「全场最大 WSS」标关注） | 100% |
| 峰值帧 p99 ≥ 7 Pa（高值簇标关注） | 98.5% |
| 峰值帧低 WSS 占比 > 20%（低值簇标关注） | 11%（AAA 32%，AG 0%，ILO 3%） |

- 结论：低值一侧的规则有区分度，不用动。高值一侧每例都标「关注」，这个标签不带信息。
- 同一例里「低 WSS 占 41%」（峰值帧）和「低 TAWSS 占 65%」（周期平均）并列出现，读者不知道该看哪个。
- 建议：
  - 三头结果以 TAWSS 和 OSI 为主来叙述，峰值帧降为补充。
  - 峰值帧的高值改用队列分位定级（比如超过参照队列第 90 百分位才标），或者只描述不分级。
  - 0.4 / 4 / 7 Pa 的出处请导师确认（Q19）。
- 口径说明：上表用的是 CFD 网格节点上的折外预测，按节点等权；部署用的是近似均匀的点云。触发率的量级可信，具体百分比不能直接当参照分布。

**U12 发现太多，还有重复**

- 证据（已核对，LV 例）：
  - 共 18 条，其中 9 条标「关注」。
  - F1 和 F5 是同一个点（52.6 Pa，弧长 263.4 mm）。
  - 滞留区 F15 只有 0.9 cm²。
  - 每条都要单独判定。
- 建议：
  - 全场最大值并进它所在的高值簇，不单列。
  - 面积低于约定下限的簇不列。
  - 首屏每类只列最重的一条。
  - 审阅时提供「其余按自动结果确认」。
- 成本：低到中，分析层。

**U13 数字位数超过了模型的分辨能力**

- 证据（截图 02）：17.01 Pa、52.60 Pa、0.665 Pa；同一页的结论里又写 17.0。
- 建议：界面统一到两到三位有效数字；导出的 CSV 和 JSON 保留全精度。
- 成本：低。

**U14 界面上的内部代号**

- 证据（截图 02、03，`index.html`）：M1_3head、PF6_VF6_peak、发布包、p99、Feret、Gaussian 插值。上传时让人选的是「模型发布包」。
- 建议：界面只出现「峰值 WSS」「周期指标 TAWSS · OSI」「体内压力与速度」；上传时问的是「想看什么」；代号留在技术信息里。
- 成本：低。

**U15 色标用命名的固定窗**

- 现状：默认范围是本例的 0 到 p99。换一个病人，同样的红色代表不同的数值。
- 建议（推断）：医生熟悉 CT 的窗宽窗位。每个量给两三个命名的固定窗，再加一个「本例自适应」。
  - 例：TAWSS「低剪切窗 0–1 Pa」「常规窗 0–5 Pa」。具体范围要用队列分布来定。
  - 窗名写进每张导出图。
  - 随访和并排比较强制同窗。
- 和 V7、D11 方向一致，这里只是换成医生认识的说法。
- 成本：低到中。

**U16 屏幕上没有方位标记**

- 证据（已核对）：报告默认是解剖前视，患者左侧在屏幕右侧；`report.py` 和两份查看器脚本里没有 L / R、头 / 足的标记。
- 左右是按解剖坐标架推断后人工确认的，前后只是推断。
- 建议：
  - 加方位标；推断得来的方向用不同样式标出。
  - 上传时加一个选项「STL 坐标沿用 CT 患者坐标系」，勾了才显示真实前后。
- 成本：低到中。

#### 比较

**U17 随访表已经有，但埋得深**

- 证据（已核对）：`timeline.py` 已经在算最大直径和瘤体体积的年增长率；前提是上传时填了患者编号和扫描日期。
- 建议：
  - 上传时把这两项标成「随访需要」，能从文件名认出来就预填。
  - 同一患者有两次以上扫描时，首屏直接显示随访表。
- 对医生来说，这张表比逐点差值图（D6）常用得多，而且已经做好了。
- 成本：低。

**U18 队列参照应该覆盖首屏上的量**

- 现状：只有 X5D 的 p99 有参照分布。
- 例子：LV 例峰值帧低 WSS 占 41%；136 例折外预测里没有一例超过 40%（口径不同，仅作示意）。这样一句话比「p99 处于第 62 百分位」有用。
- 建议：v5.2 全量权重正在训练。做新发布包时，把首屏各量的折外分布一起生成，随发布包发。
- 成本：中，放进发布包构建流程。

#### 带走

**U19 病例名是病人姓名的拼音**

- 证据（已核对）：LV_GUO_YOU 来自文件名，出现在列表、报告标题、一页纸和导出图里；一页纸把它标成「匿名病例编号」。v0.15 的脱敏只处理了服务器路径。
- 建议：
  - 显示名优先用患者编号。
  - 上传时文件名看起来像姓名就提醒。
  - 导出和讲解模式提供「隐藏病例名」。
- 对外演示和论文配图都用得到。
- 成本：低到中。

**U20 离线报告没在医生的设备上验证过**

- 单文件 4.7–6.2 MB，传输没有问题。
- 没验证过的环境：医院办公电脑（旧浏览器、没有独立显卡）、手机微信内置浏览器。
- 建议：列进 P0 的 `file://` 验证清单（Q12）。

**U21 「审阅签字」里混了两件事**

- 一件是操作者核对输入、出口命名和质量；另一件是读者认可结果。现在是同一个按钮。
- 建议：先在文案上分开，操作者这一步叫「技术复核」。要不要医生签字由你定。

### 15.4 做法与验收

- 三项都落在文案和分析层。不碰模型、几何、采样和预测数组。
- 分三次提交：措辞、界值与叙述、验证数据。和界面迁移分开。
- 升分析版本，历史任务重建。重建不重跑模型。
- 验收：
  - 全套测试通过。
  - 黄金回归通过，预测数值逐位不变。
  - 截图套件 0 个错误，人工看一遍新文案有没有被截断或换行。
- 上线：
  - 线上服务就从这个仓库目录运行，静态文件按请求从磁盘读（已核对 `server.py` 和 `service.json`）。
  - 所以前端文件一改，线上页面马上就会变，而后端还是旧的。
  - 做法：在仓库副本里改和测，演练通过以后再合回来，由你执行 `service upgrade`。
