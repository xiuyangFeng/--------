## 0. 界面重做（09-30 下午，第二轮）

**第一版为什么看着像 AI 做的：**
- **灰底平涂加黑色描边**：血管像示意图，没有立体感。
- **说明文字太多**：色条下挂三行说明，方位标下写「从前方看 / 前后为推断」，每块后面跟一句口径说明。处处加注、处处留余地，本身就是 AI 腔。
- **没有主次**：检查器是一格格等权的细线表格。
- **视口太挤**：病例栏加检查器占去约 600 px，血管比旧报告还小。

**这一轮改成「影像工作站」的样子：**

| 部分 | 现在 |
|---|---|
| 视口 | 默认深色渐变背景（可一键换浅色）；血管柔和打光、带高光，默认不描边；工具条浮在视口上：字段切换和色标在上方，其余工具竖排在左侧 |
| 色条 | 细条加刻度；说明文字全部收进 ⓘ 悬停提示 |
| 方位 | 左下角方位立方体，点一个面就转到那个标准视角；推断的方向用虚线边、浅色字，悬停可看说明 |
| 检查器 | 顶部 4 个关键数字（旁边的色块就是它在血管上的颜色；占比带小进度条）；分区改成一张按数值上色的血管分区示意图（悬停时血管上只保留该分区的颜色，其余变淡；点一下看这个数的来源）；发现改成紧凑列表；结论默认折叠成三行 |
| 首页 | 病例卡片墙：每例一张彩色血管缩略图（按该结果的 TAWSS 或 WSS 上色）、病例名、扫描信息和各结果的状态小标签；上方一条「需要处理」提醒 |
| 色标默认 | 峰值 WSS、TAWSS、RRT、ECAP 的「本例自适应」默认对数（线性另有选项）。线性时瘤体是一片深蓝，正是你最初指出的「看不清」 |
| 视觉 | 深青色强调色、8 px 圆角、浮层用半透明磨砂；文字只留名称和数字 |

**需要你确认的一点（和 09-24 的裁定有关）：**
- 09-24 裁定过「浅色界面，不做暗色」。
- 这一轮界面本身（顶栏、病例栏、检查器、对话框）仍是浅色，只有三维视口默认用深色背景。深色背景上血管的颜色最醒目，这也是医学影像软件的通行做法。
- 如果你还是要浅色：右上角头像菜单或视口的图层菜单里选「浅色视口」，会记住这个选择。截图 20 是浅色效果。
- 验收时告诉我默认用哪个，我改默认值。

**没变的：**
- 预测数值、统计口径和所有接口都没变。
- 读数一律取数据值，不从屏幕颜色反推。光照只影响观感，要精确读色可按 L 切回平涂。

## 3. 讨论稿 §8.2 的五项任务在新界面里怎么走

| 任务 | 步骤 |
|---|---|
| 找一个低 WSS 区并说出当前显示 | 打开结果 →「按问题看」→「低值区域在哪里」（3 步）。问题条和色条写明字段、单位、窗和「观察阈值，非临床界值」 |
| 同一位置看 TAWSS 与 OSI | 「按问题看」→「同一位置的 TAWSS 与 OSI」，在血管上点一下（3 步）。读数页列出此点的 TAWSS、OSI、峰值帧 WSS，RRT 和 ECAP 标「派生」 |
| 查看无覆盖或低支撑处 | 点一个值，读数页的「支撑」分三行写（2 步）；图层菜单也能开斜纹。开发病例的未覆盖比例是 0%，这一项演示得不充分 |
| 比较两份结果 | 「比较」→ 选结果（2 步）。先出条件表，再选「同尺度」或「各自增强」；视角同步只有同一输入几何时才默认打开 |
| 书签 → 换例 → 返回 → 导出 → 离线恢复 | 按 B 存书签 → 按 J/K 换例 → 回来时阅读位置自动恢复 → 导出「离线阅读」并勾「带上书签」→ 在离线文件的书签页点「打开」（约 6 步） |

## 6. 已知问题和没做的

- 讲解模式、展开图、拉直视图、随访逐点差值、阈值刷选（P4 或以后）。

**新工作区的小问题**：
- 首页缩略图只给已完成或已有预览的任务画；失败的任务显示占位圆圈。
- 缩略图第一次打开时逐张绘制，每张约零点几秒，之后在本页缓存。
- 病例栏里同名结果的时间会被截断，悬停可以看全名。
- 手机宽度下工具栏要横向滑动。
- 点分区的数只进透镜，不会在三维里圈出这个区域。

## 7. 验收通过后怎么上线（由你执行）

线上服务直接读主目录的静态文件，合并那一刻前端就会变。所以合并、升级、生成示例要连着做：

```bash
cd /public/newhome/cy/Digital_twin/GNN
PY=/public/newhome/cy/.conda/envs/GNN/bin/python
# 1. 记下合并前的提交（回退用），再快进合并
PRE=$(git rev-parse HEAD); echo "$PRE"
git merge --ff-only wss-ui-v2
# 2. 升级：会自动重建分析版本较旧的任务（新分区、新发现规则、新叙述；预测数值不变）
PYTHONPATH=. $PY -m wss_deploy.cli service upgrade
# 3. 在服务机上生成两个示例文件（不入库；放在升级之后，示例报告才是新口径）
PYTHONPATH=. $PY -m wss_deploy.v2_examples \
  --stl outputs/wss_deploy_golden/20260920_baseline/20260920_144135_673ccd0e36b1/input.stl \
  --job-dir outputs/wss_deploy_jobs/20260929_230442_a7273f1670e4
```

- **回退**：`git reset --keep $PRE`（第 1 步打印的那个提交）之后再执行一次 `service upgrade`。
  - `--keep` 只退回这几个提交改过的文件，主目录里其他未提交的改动（文档、训练代码）内容会保留；已暂存（git add 过）的改动会变回未暂存，内容不丢。
  - **不要用 `--hard`**，它会把那些未提交的改动一起抹掉。
  - 重建过的任务保留新的分析结果，但预测数值没有变，旧页面照常能看。
- **验收期间**：预览服务（8766）一直开着。验收结束后停掉它：
  - 用 `ss -ltnp | grep 8766` 找到进程号后 `kill`；
  - 或者告诉我去停。
