## 3. 工程结构与门

| 阶段 | 做什么 | 门 |
|---|---|---|
| profile | 只读库内 .cas/UDF → `reference_profile.json` | — |
| surface | STL + 平面盖 + 直线延伸 → Fluent 边界网格（界面为 internal 型） | 6 个区域各自闭合流形、延伸段与壁面/彼此无碰撞 |
| mesh | Fluent Meshing（Slurm，4 核，约 40 s） | 解剖区单元/四面体/体积/边界层/四面体尺寸与原始的相对差在容差内 |
| finalize | 求解器：按邻接把区域改名 blood/bloodN，mesh check | Fluent 无报错、mesh check 通过 |
| setup | 参考 .cas 副本（库路径全部改写到工作目录）+ replace-mesh + UDF | settings_diff 非预期差异 = 0 |
| smoke | 读最终 case（UDF 重编） | 7 个 UDF 钩子全部加载 |
| run | 2.jou + fluent.slurm（库内脚本：64 核、相同清理与归档）、空 `ascii/` | `ascii/` 非空则拒绝（Fluent 不覆盖同名导出） |

## 4. Fluent 2023R1 批处理的坑（都已写进代码）

- TUI 菜单懒加载：读入网格/算例之前 `/mesh`、`/file/replace-mesh`、`/file/read-settings` 等都不存在。
- 日志里的空行被跳过、不是"取默认值"；每个提示都必须显式给值；列表提示用括号 `(a b c)`。
- 求解器 `extrude-face-zone-delta` 只能串行，且单次超过约 10 层即失败（20 层失败）→ 放弃求解器拉伸，改为在表面阶段建延伸段、Fluent Meshing 一次划 6 个区域。
- 边界网格里的两侧界面必须用 `internal`（类型码 15），`interior`（2）会被 read-boundary-mesh 丢掉。
- `auto-mesh` 的 "merge cell zones?" 选 yes：每个区域的棱柱并入本区域四面体，边缘四边形并回盖面，免去求解器里再合并。
- **读任何 .cas 时 Fluent 会在该 .cas 所在目录自动编译 libudf**。2026-09-27 21:49 一次菜单探针直接读了库内 QIN_SI_FU.cas.gz，结果在库内目录重生成了 `libudf/Makefile`、两个同目标软链，并覆盖了旧编译日志 `log`；`.cas`、`ascii/`、`ascii_in/`、`processed/`、UDF 源码（md5 不变）、`libudf.so`/`.o`（未重编）均未改动。此后规则：Fluent 只读工作目录里的副本，`guard` 拒绝任何指向 `data/`、`data_new/` 的日志路径。
- replace-mesh 按区名套用设置，并把区编号改回参考 case 的编号；新增的 interior 区给默认设置（无影响）；壁面的 `parallel-collimated-beam?`（辐射束标志）被重置为 #f，辐射模型未开、所有 rp 变量相同，记为预期差异。
- 报告文件 `vf-*`/`p-*` 定义在 interior 界面上，界面法向取决于 c0 在哪一侧：新网格与原始相反，**流量报告符号相反**（入口负、出口正）。UDF 的 RCR 用的是末端 BC 面（法向恒指向域外），不受影响；比对用 UDF 每步打印的 `Q_ave_out*`。库内只有 `wall_phys1d_v1` 读 QIN_SI_FU 原始 `vf-in` 作波形（只读原文件），不受影响。

| P6b | 出口压力最大相对差（步 1162） | 14.7–15.9 kPa | — | +0.83% | ±3% | 过 |

**P5a 不过的原因**：压力空间分布几乎完全相同，只差一个整体平移。原始壁面压力均值 16343 Pa、空间标准差只有 450 Pa；新建整体高 +120 Pa（0.73%），逐点差值的标准差仅 7.1 Pa；各自减均值后 R² = 0.9998、Pearson 0.9999。空间方差小，整体平移在原始值 R² 里被放大——这是预登记时判据定得不当（应比较中心化压力或绝对误差），按原口径如实记为不过，不事后改线。项目的压力标签按病例均值中心化（09-05 冻结合同），该平移不进标签；平移在 81 帧里介于 −52…+273 Pa，来源是出口 RCR 压力水平的微小差异（峰值时四出口 −6…+126 Pa），与出口流量份额 le −0.006 / re +0.004 同源，成因未定位（候选：延伸段截面小 1–3%，见 §7）。

**次要指标**：TAWSS R² 0.9989（均值 +0.3%）；OSI R² 0.997、MAE 0.004（均值 0.153 对 0.153）；逐帧 WSS R² 中位 0.979、最差 0.843（步 1138，低流量相位，平均 WSS 0.53 Pa，对峰值帧 3.2 Pa）；解剖区体场速度 R² 0.994、体场压力 R² 0.965（同一平移）；WSS 按距开口距离分段 R² 0–10 mm 0.996、10–20 mm 0.998、20–40 mm 0.998、> 40 mm 0.999，开口附近没有集中偏差。压力减均值后逐帧 R²：空间标准差 > 100 Pa 的 38 帧最低 0.73；其余帧压力近乎均匀（空间标准差 9–21 Pa），R² 无意义。

**结论**：训练用标签（峰值帧 WSS、TAWSS、OSI）与原始 CFD 的差异远小于模型误差（WSS R² 0.9988 对模型折外约 0.76），这套流程产出的数据可按"与库内同口径"对待；绝对压力水平有约 0.7% 的整体偏移，用绝对压力的场合要注意。

### 11.3 新数据怎么走（用法）

批次文件（例：`_orch_validation/batch.json`）里一个新病例只需：

```json
"AAA/new/<病例>": {"mode": "stl", "stl": "/绝对路径/<病例>.stl"}
```

单元号以队列开头（AAA / ILO / AG）；模板（AAA → YU_TIAN_HAI P 族，ILO → XUE_YOU_TANG-0/before P 族，AG → QIN_SI_FU T 族）、表面密度参照、命名方法（部署自动命名 + 置信度门 0.95）、延伸规则（入口 AG 200 / AAA·ILO 100 mm，出口 10.2 D，方向 auto）都取协议默认，可逐项覆盖。`python -m cfd_auto.orchestrate run <batch.json>` 用 nohup 挂着即可，随时 `status`；命名置信度不够的单元停在 needs_confirmation（看 `naming.png`，`confirm --accept` 或 `--keys`），设置检查不过的停在 blocked，其他全自动走到 checked / flagged。每个单元产出 `MANIFEST.json`（STL sha256、协议、代码指纹、方案、作业号、各门结果）。

对输入 STL 的要求（为避免旧数据那样的命名/路径错误，入口处统一校验）：一个病例一个 STL、单位 mm；入口与出口已平面切开（开口数 = 协议的 5 个），其余封闭、流形；局部自交可自动修（≤ 0.5 mm）；文件名与目录名不参与任何判断——病例身份只来自批次文件的单元号，开口名只来自几何命名。

### 11.4 能不能「STL 直接到结果」，能不能推广到脑血管

**本协议内（AAA / ILO / AG 这类腹主动脉 + 双髂 4 出口几何）：能，已经是全自动。** 从 STL 到检查过的 81 帧导出，人只在两处介入：① 自动命名置信度 < 0.95（或多种命名方法不一致）时看 `naming.png` 确认一次；② 设置检查报 fail（协议对这例不适用，如小出口 R2 ≤ 0）时决定规则。其余（封口、延伸、网格与修复、边界条件、提交、发散降级、重排队、算后检查）都由编排器完成。旧数据的「命名错误、路径错误」在新流程里没有落脚点：病例身份只来自批次文件的单元号，开口名只来自几何命名并经置信度门，所有路径由流程生成，每例留 `MANIFEST.json` 可追溯。

**推广到其他血管床（如脑血管）：一半已经通用，另一半每个血管床要一次性建一个「协议」。**

| 层 | 现状 | 换血管床要做的 |
|---|---|---|
| 编排、续跑、只导出所需帧、requeue、发散梯子、算后布局 | 与血管床无关 | 只改协议文件数值（步长、步数、周期、导出帧） |
| 表面：封口、延伸（含斜切口沿轴线）、自交修复、区域检查 | 与开口数无关 | 延伸长度规则改参数 |
| 网格：边界层 + 四面体；曲率重划 + 密度标定 | 通用，但尺寸是绝对值、密度以库内病例为参照 | 尺寸按血管半径定（脑血管 1–5 mm → 约 0.1–0.3 mm）；没有库内参照时做一次网格无关性研究定密度 |
| 开口切割 | 要求 STL 已切开 | 分割得到的闭合面要先垂直切开口：vessel_geom 的 TopCoW final5 已有「垂直平面切口」，接进来即可 |
| 开口命名 | 部署命名只认主动脉-双髂 5 开口 | 该床的命名器（如按 TopCoW 的 13 类血管标签或中心线拓扑） |
| 边界条件 + 求解设置 | 库内 UDF 模板（写死 4 个 RCR 出口）+ 库内 .cas 作设置模板（replace-mesh） | **一次性工作**：N 出口 BC 生成器（入口波形按面积/流量缩放；出口 Murray 分流、零压或 N 个 RCR）+ 从零写设置的 journal（层流、瞬态、Carreau、材料、报告定义、自动导出），不再依赖库内 .cas |
| 算后检查 | 左右 50/50、同侧 Murray 是本床特有 | 换成该床的门：入流比、各出口份额 vs 设计、周期性等通用项照用 |
| 验证 | 本床有库内原解可逐点比对 | 新床没有原解：网格/步长无关性 + 文献基准算例 |

所以「只改几个参数」对上面前三层成立；边界条件、命名、切口这三层，每个新血管床需要先建一次协议（估计几天开发 + 一次验证研究），之后该床的新数据就和现在一样全自动。若要走这条路，下一步是把「设置模板 + UDF」改为由协议生成（BC 生成器 + 从零设置 journal）——这一步同时也让本床不再依赖库内 .cas 模板；还需要先定脑血管的 BC 口径（入口波形与流量缩放规则、出口条件）和数据来源。
