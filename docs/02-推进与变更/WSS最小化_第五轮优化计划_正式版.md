## 1. 本轮定位

第五轮的核心不是继续扩大调参矩阵，而是先确定当前精度上限由什么决定，再针对主要瓶颈做受控优化。

最终需要回答：

1. 现有 PointNeXt 是否具备足够的训练集拟合能力。
2. 2000 点训练与约 1.5 万点完整壁面推理之间的密度错位，是否是主要误差来源。
3. 增加同分布 AG 病例数是否仍有稳定收益。
4. 局部表面表示、全局条件信息或 CFD 标签波动是否构成更高精度的限制。
5. 在不混入其他队列的前提下，AG 内部精度能否达到工程目标。

---

## 2. 冻结边界

### 2.1 队列与数据

- 主实验队列仅为 **AG（腹主动脉瘤生长速度队列）**。
- AAA 破裂队列、ILO 队列与 AG 分开管理，不直接混池训练，不用于反向选择 AG 模型。
- 其他队列中输入、WSS、配准、方向、边界条件或 `vf-in` 数量级异常的单元，暂时移出 active pool，但保留原始数据、异常原因和可恢复状态。
- 第五轮不重跑 CFD，不将 excluded 病例未审核恢复到正式集合。

### 2.2 学习任务

- 输入：患者血管几何，以及经验证可在未来部署时获取的条件。
- 输出：峰值收缩期逐点 **WSS 标量场**。
- 模型形式：单任务、单头，`out_dim=1`。
- 本轮不做 WSS 三分量，不增加 mean/p99 等多任务监督头，不扩展到 TAWSS、OSI 或 RRT。

### 2.3 应用边界

当前工程用途是快速生成供医生参考的 WSS 初筛图。模型不直接预测动脉瘤生长速度、破裂风险或诊疗结局，不得表述为自动诊断或治疗决策系统。

## 3. 当前基线与已知问题

当前开发锚点为 `r4_dev1_b1_tgtw_fixedq`：`xyz+geom`、FPS-2000、固定 train-only target-weight 阈值、PointNeXt-S。

第四轮多 seed 结果显示：

- 2000 点配置的 val `R²_field` 约为 `0.339±0.020`。
- val `R²_casemean` 约为 `0.188±0.025`。
- 1000 与 2000 点的 field 指标基本持平，仅 casemean 稳定略偏向 1000，因此默认锚点仍为 2000。
- 稀疏与完整点云的同索引预测存在系统差异，说明模型对推理密度敏感。
- 高 WSS 区域仍有明显峰值低估，因此全场 R² 提升不能以过度平滑高 WSS 为代价。

当前结果与 `0.70` 目标存在结构性差距，不适合仅靠学习率、loss 系数或训练轮数做局部调整。

## 4. 评价与选模协议

所有指标在 denormalize 后的原始 WSS 空间计算，正式评价使用完整 CFD 壁面点。

### 4.1 共同主指标

| 指标 | 含义 | 工程目标 |
|---|---|---:|
| `R²_field_raw` | 将所有病例的完整壁面点 pooled 后计算 | `>=0.70` |
| `R²_casemean` | 逐病例计算 R² 后等权平均 | `>=0.70` |

两项为共同主目标。不得只根据 pooled field R² 宣称工程达标，也不得只优化 casemean 而忽略全场误差。

### 4.2 强制辅助指标

- `R²_field_casebalanced`；
- 逐病例 R² 的 median、P10、负 R² 病例数和失败率；
- MAE / RMSE；
- high-WSS R²、top10 ratio、top10 IoU；
- 逐病例预测图与失败病例清单。

### 4.3 开发 Gate

- 对 control 的指标变化在 `±0.02` 内视为无实质差异。
- 只有两项主 R² 同时改善、且高 WSS 护栏无明显劣化，才进入多 seed 确认。
- dev1 用于单 seed Gate，通过后再做三 seed；dev2/dev3 仅用于开发划分稳定性。
- 开发期严格 val-only，`legacy test16` 不参与任何模型选择。

### 4.4 checkpoint 原则

best、last 和 top-k checkpoint 可用于诊断早停与容量问题，但不得使用 train 指标反向选择正式模型。正式 checkpoint 规则必须在运行前预注册。

## 5. 优化路线

### 5.1 阶段 A：能力与密度诊断

#### A0｜训练集拟合能力

1. 对 B1 三 seed 的 best、last 和已有 top-k checkpoint，评估 train/val × canonical-2000/full 四种组合。
2. 固定 4 个训练病例做 micro-overfit sanity，目标为 train `R²_field` 和 `R²_casemean` 均达到 `0.95`。
3. micro-overfit 失败时，先检查标签对齐、normalization、loss、相对位置和模型实现，暂停 learning curve 和大规模 sweep。

#### A1｜密度与表面映射

1. 在当前 B1/v2_dev1 三 seed 上重做同索引 canonical/full 密度对照与邻域 cap 审计。
2. 检查 STL 三角面与 CFD wall 的坐标、单位、距离、覆盖和多对一关系。
3. 使用稀疏真值回插完整壁面，建立插值 oracle 上限。oracle 未通过时，不进入稀疏预测回插或 ensemble。
4. 即使采用回插，正式定量指标仍在完整 CFD wall 真值上计算。

### 5.2 阶段 B：证据驱动的单变量优化

阶段 A 完成后只启动证据支持的分支：

| 诊断结果 | 优先分支 |
|---|---|
| micro-overfit 失败或 canonical train-fit 较低 | 修复数据/实现；再比较逐点 MLP、表面特征和 PointNeXt 相对位置半径归一化 |
| canonical 明显优于 full，且映射 oracle 通过 | 稀疏预测回插、密度一致推理或受控 ensemble |
| train 较高、val 较低，密度差异不主导 | AG learning curve |
| 几何拟合良好但跨病例不可辨识 | 先完成 BC 审计，再决定是否做条件信息探针 |

候选顺序默认为：逐点 MLP 对照 → STL/表面特征 → PointNeXt 相对位置归一化 → 单输出 global context。每次只改一个主变量，不默认并行所有方向。

本轮默认不重启已判 No-Go 的 loss 扩参，也不在 BatchNorm 和 batch size 未隔离时把 full-density train 称为纯密度消融。

### 5.3 阶段 C：AG learning curve

在模型基础链通过且密度/表示协议冻结后，执行三条独立嵌套链：

- `R=3`；
- 每条 `LC13 ⊂ LC26 ⊂ LC40 ⊂ LC53`，53 例为公共终点；
- case-drop seed 与 model seed 分离；
- fast/slow × train-only WSS 三分位为硬分层；
- 分别报告病例选择、模型 seed 和 dev split 三类波动。

learning curve 只用于判断增加同分布 AG 数据是否仍有收益，不得自动外推为“增加数据必然达到 0.70”，也不自动触发 AAA/ILO 混训。

### 5.4 阶段 D：边界条件可辨识性（条件分支）

该分支仅在基础容量、密度和表示问题不足以解释精度上限时启动。

训练前必须先交付可复跑 BC 审计资产：

- 逐病例入口 UDF 系数与分母、RCR、监测完整性和 peak flow split；
- 数据 scope、缺失规则、源路径、生成脚本和摘要元数据；
- 至少 5 个病例的人工与单位核对。

出口面积可作可部署几何候选。CFD RCR 或流量分配只能作 oracle，必须标记 `oracle_non_deployable=true`，不参与可部署模型的选择。加入 BC 后的提升只解释为相同协议下的预测增量，不解释为因果效应或全部可解释方差。

## 6. CFD 与医工可信性审计

第五轮结案前必须对以下问题给出可复核结论：

1. CFD 网格密度、近壁处理和求解收敛性是否在病例间一致。
2. 峰值收缩期的取法是否一致，单时相 WSS 是否足以支撑当前工程用途。
3. 高 WSS 尖峰是真实物理结构、网格/边界效应，还是局部数值噪声。
4. 相邻或近重复几何在不同 CFD 设定下的 WSS 差异，是否超出纯几何模型的可辨识范围。
5. 误差是否集中于医学上更重要的分叉、瘤体、狭窄或高 WSS 区域。

这些审计用于界定模型可达上限和医学适用边界，不代替正式 OOF 定量评估。

## 7. 最终内部验收

开发阶段完成后，冻结代码、配置、特征、loss、密度、推理协议、stats 规则和 seeds，再进行全 61 例 5-fold grouped cross-fitting。

### 7.1 OOF 协议

1. 61 个开发病例每例恰好一次作为 OOF val。
2. 同病人或近重复几何整组进入同一 fold。
3. 各 fold 的 normalization stats 与 loss quantiles 只使用对应 fold train。
4. 每 fold 运行 seeds `{1234,7,2025}`，先报告单 seed，再用三 seed ensemble mean 生成工程候选预测。
5. OOF 开始后不得根据某个 fold 的结果修改配置；任何修改都使整套 OOF 声明作废。

dev1/dev2/dev3 的 val 去重并集仅覆盖 20/61 个病例，因此仅用于开发 Gate，不能支撑 `R²>=0.70` 的最终工程声明。

### 7.2 legacy test16

OOF 完成后，锁定模型最多评估一次 `legacy test16`，仅作历史弱确认，不用于返回开发或代替新 AG 前瞻性验证。

## 8. 完成标准

### 8.1 第五轮科学结案

同时满足：

- 训练集拟合能力已明确；
- 密度迁移与 STL/CFD 映射上限已明确；
- 数据量、局部表示、边界条件和 CFD 标签上限均有可复核裁决；
- 所有开发分支按预注册 Gate 完成或明确 No-Go；
- 最终候选完成全 61 例 OOF；
- 脚本、split、stats、config、seed、checkpoint 和报告均可追溯。

即使 R² 未达 0.70，只要上述机制问题得到可复核结论，第五轮仍可科学结案。

### 8.2 内部工程达标

只有锁定配置在 61 例 OOF ensemble 上同时满足：

- `R²_field_raw >= 0.70`；
- `R²_casemean >= 0.70`；
- 完整报告 median、P10、负 R² 病例、失败率和 high-WSS 护栏。

如两项主 R² 未同时达标，结论必须明确写为“未达内部工程目标”。

### 8.3 对外/临床确认

当前没有未参与开发的新 AG 病例，因此本轮不作“临床可用”或“生产可用”声明。后续仍需独立前瞻性病例验证。

---

## 9. 正式执行顺序

1. 实现统一指标、indifference band、共同 Gate 和 val-only/test guard。
2. 完成 B1 多 checkpoint 只读诊断。
3. 完成 4 病例 micro-overfit sanity。
4. 完成当前 B1 密度对照、邻域 cap、STL mapping QA 和真值插值 oracle。
5. 根据前四步做第一次分支裁决。
6. 只执行证据触发的单变量优化或 BC 审计。
7. 在协议冻结后执行三链 AG learning curve。
8. 停止开发决策，锁定代码、config、stats、特征、seed 和推理协议。
9. 执行全 61 例 5-fold OOF × 3 seeds，形成内部工程验收报告。
10. 最多运行一次 legacy test16，输出科学结论、工程状态、失败病例和适用边界。

具体任务 ID、依赖、产物路径、并行边界和回填模板统一见[第五轮执行计划](WSS最小化_第五轮执行计划.md)。
