# WSS 最小化路线全链路基础检查报告

> 检查日期：2026-07-12
> 检查对象：`pipeline_wss_min/`、`training_wss_min/`、`data_wss_min/`、WSS-min split / stats / QA / 既有 run 产物
> 检查边界：本轮检查并形成报告，不改预处理或训练实现，不读取新的 test16 指标，不启动新训练。

## 1. 结论先行

当前 **WSS 标量主线没有发现会让既有全部实验失效的坐标—标签错位、非正交旋转、压缩错位或 train/val/test 名单交叉问题**。77 个 included bundle 的实际数值复核显示：

- 77/77 bundle 存在，train/val/test 为 53/8/16，三者病例名无交叉；
- 每例 `max(abs(wall_coords_norm))=1.0`；
- 旋转矩阵 `det(R)` 为 `0.9999999999999997–1.0000000000000007`，最大正交误差 `max|RᵀR-I|=4.44e-16`；
- 从归一化坐标逆变换回毫米坐标的最大误差约 `7.17e-05 mm`（float32 落盘精度量级）；
- 坐标、节点 ID、几何特征、WSS 标签数组长度全部一致；
- 训练 FPS-2000 后，坐标与 `y_norm` 对原 bundle 同索引复核误差均为 0；2000 个索引全部唯一；
- 77/77 `report.json` 的 `nodenumber_alignment_ok=True`，跨时间步坐标不一致病例为 0，单位异常病例为 0；
- WSS 统计是 train-only、peak-only、53 例；没有把 val/test 混入标准化统计。

因此，现阶段 `R²≈0.31` 不能用“基础管线整体写错”解释。更可信的主因是：**逐病例尺度归一化与固定归一化邻域的耦合、点密度迁移、训练目标与 raw-WSS R²/峰值幅值错位、病例级信息缺失和小验证集高方差**。

但基础层仍有必须在下一批 WSS 主矩阵前收紧的风险：

1. 3 个 included 病例的左右轴符号仍为 `roll_sign_reliable=False`，当前 QA gate 没有把它们纳入告警；
2. PointNeXt ball-query 半径是在逐病例归一化坐标中固定，**并非固定毫米物理半径**；
3. 预留近壁速度路径还没有壁面 WSS 路径同等级的 cell ID、跨时间步重排和裁剪同步守卫；
4. WSS 标量与 WSS 矢量模长并非逐点完全相等，进入矢量 WSS/physics loss 前必须确认 Fluent 导出定义；
5. `coord_scope="global"` 的配置注释称会在样本阶段做全局缩放，但当前代码没有实现该缩放，不能直接把此开关当作严格尺度实验。

## 2. 三个坐标问题的直接回答

### 2.1 空间如何固定到 `[-1,1]`

当前不是逐轴 min-max，也不是把每个轴分别拉满到 `[-1,1]`。实际顺序是：

1. 原始 Fluent 坐标逐病例换算到 mm；
2. 用 flow-divider/分叉原点做平移；
3. 用同一个正交矩阵做刚性旋转，主轴对到 `+Z`，左右轴固定；
4. 可选主干横向刚性平移和未描入口段裁剪；
5. 在壁面对齐坐标中计算单个标量
   `scale = max(abs(x), abs(y), abs(z))`；
6. 三个轴统一除以同一个 `scale`。

所以它保证所有壁面点落在立方体 `[-1,1]^3` 内，并至少有一个坐标分量达到 ±1；它不会保证 x、y、z 三个轴都各自覆盖完整 `[-1,1]`。这种各向同性缩放保持角度和长宽比，是正确的保形做法；代价是病例绝对尺寸被移除。第六轮 B−A 已直接证明该绝对尺度对 WSS 有用。

### 2.2 是否做了笛卡尔积的正交化

需要区分两个概念：

- **做到了正交笛卡尔坐标基**：代码用 Gram-Schmidt 构造互相垂直的三个单位基，并强制 `det(R)=+1`；77 例实际最大正交误差为 `4.44e-16`。
- **没有也不应把血管表面变成笛卡尔积规则网格**：壁面仍是不规则采样的三维曲面点云，不是 `X×Y×Z` 网格。将曲面强行体素化/笛卡尔积化会引入插值和离散误差，并非本任务的必要条件。

所以，对“坐标轴是否实实在在互相正交”的回答是 **是**；对“点云是否变成规则笛卡尔积”的回答是 **否，而且当前 PointNeXt 路线不需要这样做**。

### 2.3 压缩/稀疏化是否让坐标和数据偏离

当前 WSS 标量主线没有发现偏离：

- `np.savez_compressed` 是无损压缩，不改变数组行序或数值语义；
- 预处理先按 `nodenumber` 把每个时间步重排到首步顺序，再堆叠 WSS；节点集合、重复 ID、跨步坐标变化均有硬守卫；
- 裁剪时同一个 `wall_keep` 同步作用于坐标、节点 ID、WSS、pressure、WSS vector；
- FPS 只返回索引，不做插值；训练集用同一个 `idx` 同步选择 `pos/features/y/y_raw`；实测索引对齐误差为 0；
- 训练代码直接读 bundle，评估直接使用同一 bundle 的完整点云，避免了另存 sample 引起的口径漂移。

需要强调：FPS-2000 是**有损的空间取样**，虽然不会错位，却可能漏掉小面积高 WSS 尖峰；而完整点云推理相对稀疏训练又存在密度分布变化。既有 A5 诊断已观察到同点预测随输入密度发生 `0.03–0.07σ` 系统漂移。因此“没有配准错位”不等于“稀疏化没有信息损失”。

### 3.2 需要收紧的基础风险

#### P1：3 个 included 病例左右轴仍不可靠，QA gate 未覆盖

- train：`fast/ZHANG_XIU_WEN`，`|cos|=0.1362`；
- train：`slow/CHENG_GUANG_SEN`，`|cos|=0.0917`；
- test：`fast/CHEN_SHI_MING`，`|cos|=0.0317`。

`preprocess_audit_latest.json` 已记录这 3 例，但 `qa_gate.py` 当前只检查 WSS、点数、单位、裁剪、非有限值、ID/坐标守卫，没有检查 `transform_roll_sign_reliable`、`origin_kind` 或 `main_axis_source`。这不会制造单病例内坐标—标签错位，但可能让跨病例 canonical frame 出现左右翻转，削弱只靠 XYZ 学习的模型。

建议：在下一次全量 preprocess 前逐例定夺 override / 保留 / excluded；QA gate 至少将 `roll_sign_reliable=False` 设为显式 warning，并将非预期 origin fallback 列入审计。若改变配准，必须按项目规则全量重跑 preprocess，不能混用新旧 bundle。

#### P1：固定 ball-query 半径不是固定物理尺度

当前 `coord_scale` 范围约 `127.59–261.95 mm`。因此 SA 半径 `(0.05,0.10,0.20,0.40)` 对应的病例物理邻域范围分别约：

- `6.38–13.10 mm`；
- `12.76–26.19 mm`；
- `25.52–52.39 mm`；
- `51.04–104.78 mm`。

同一个网络半径在最大/最小病例之间相差约 2.05 倍。B 组把 `coord_scale` 作为点特征只能告诉网络“病例多大”，却不会改变 FPS、ball-query 或相对坐标本身，所以 B 不是严格物理尺度实验。

建议：C 组使用 **train-only 共享毫米尺度** 变换坐标，并让 FPS、SA、InvResMLP 邻域全部使用该 metric coordinate；同时保留当前 per-case normalized 坐标作为 display/canonical feature，形成受控双坐标输入，而不是简单把 mm 值直接塞进现有半径配置。

#### P2：WSS 标量与矢量模长需做定义核对

77 例 peak step 上，`|norm(wss_vec)-wall_shear|/wall_shear` 的病例内 p95 中位数约 4.90%，最差约 12.63%。当前标量任务直接使用 Fluent 的 `wall-shear` 列，因此这不是现有标量标签错位证据；但进入矢量 WSS、多任务或 physics loss 前，必须确认三分量列与标量列是否是同一时刻、同一参考系、同一 Fluent 定义及单位，不能默认“标量=三分量欧氏模长”。

#### P2：预留速度路径的对齐守卫不够

壁面路径按 `nodenumber` 对齐；`read_interior_fields()` 当前没有读取 `cellnumber`，近壁速度跨时间步直接按数组行号取值。若未来开启 `store_near_wall_timeseries=True`，还需保证入口裁剪后的内部索引同步映射回原始 interior fields。当前 included 77 例没有触发裁剪且该开关为 False，所以没有污染既有 WSS 结果；Track B/速度 adapter 上线前必须补齐。

#### P2：两个配置行为不能按注释直接使用

- `coord_scope="global"` 时 preprocess 只把 `scale=1`，但 build-samples 没有执行注释所说的全局缩放；严格尺度 C 不能只切这个开关。
- `train.py` 在配置指定的 stats 文件不存在时会静默回退到默认 WSS stats。对 WSS 尚可作为兼容逻辑，对 pressure/velocity 是危险行为；多目标训练应 fail-fast，并校验 `target/method/stats provenance` 一致。

## 4. 训练代码审计

### 4.1 模型与激活函数

当前激活配置总体合理：

- stem、局部 MLP、残差块、FP 解码和 head 使用 GELU；对连续场回归比硬阈值激活更平滑；
- 最后一层是线性层，没有 ReLU 截断标准化目标；这对 `log_z` 回归是正确的；
- WSS 反归一化通过 `exp` 保证物理空间近似非负，评估再做非负 clip；
- 残差块、AdamW、warmup+cosine、梯度裁剪、AMP、完整点云 val、top-k checkpoint 和 early stop 的实现均未发现明显错误；
- 17 个现有 sampler / loss / metric / test-lock 单元测试全部通过，`compileall` 通过。

不建议把下一轮主变量放在 ReLU/GELU/SiLU 的替换上。现有 A0D 已证明模型能把小样本 train 拟合到较高 R²，说明“激活导致完全学不动”不成立。更值得加的安全项是：反归一化 `exp` 前做与 train 标签范围相关的 log-domain clamp/监控，避免极端预测溢出；这属于稳定性保护，不是主要提分手段。

### 4.2 邻域、采样与密度

当前结构最需要调整的是邻域口径，而非单纯增宽网络：

- 训练默认固定 FPS-2000；`resample_each_epoch=True` 对 `sampling="fps"` 实际不会换子集，这是有意的 fixed-FPS 协议，不是动态重采样；
- SA 内部 FPS 在 `model.train()` 下使用随机起点，仍存在层级采样随机性；
- ball-query 固定归一化半径，且最多 16 邻居；不同病例物理半径和不同输入点密度下，邻域占用分布会变化；
- A5 已证明 2000 点输入与完整点云输入存在密度敏感；点数曲线也没有显示“堆点数即可稳定提分”。

建议在 C/E 之前先输出逐 stage 的邻居数分布（空邻域率、cap=16 命中率、p10/p50/p90），按病例尺度和点数分层。随后比较：共享毫米尺度半径、半径随局部 spacing 自适应、radius+kNN 混合兜底、训练期多密度输入。不要在未做 occupancy QA 时只改 `sa_radius` 数值。

### 4.3 loss 与选模

当前 B1 是 `log_z` 空间 MSE + 高目标固定分位加权，能改善中高段，但与最终关心的 raw-WSS `R²_field/R²_casemean` 并不完全同目标；现有 top10 预测/真值比约 0.38–0.47，表明峰值幅值仍系统性低估。普通 Huber 历史上无稳定收益，不能据此否定“raw-space + case balance”的新组合。

建议 L1/L2 严格保持 D 输入、split、采样、模型、seed 不变，仅比较：

1. B1：现有 log-MSE target weight；
2. log 主损失 + 缩放后的 raw-space Huber 辅助；
3. 病例等权 raw robust（每病例先求均值，再跨病例平均），可叠加小权重 log 稳定项。

选模同时报告 field、case-balanced field、case-mean、top10 ratio、IoU 和负 R² 病例数。不要让 WSS tail penalty 复用于 pressure/velocity 目标。固定 8 例 val 已被大量实验反复使用，后续候选应采用 grouped repeated validation / grouped K-fold；只有预注册胜者才进入一次性锁定评估，避免验证集层面的长期过拟合。

### 4.4 参数是否合理

`width=32`、4 层 SA、约 0.05→0.40 半径、`batch_cases=8`、`lr=1e-3`、AdamW `weight_decay=1e-4`、10 epoch warmup、160 epoch 上限、每 10 epoch 完整 val、patience=6，作为小型 baseline 是合理起点。A/B/D 九个 run 的 best epoch 从 9 到 89，且多数被 early stop，说明调度器和停止机制能工作，但 seed/val 方差很大；这不支持继续把 epoch 或宽度当作首要杠杆。

优先级应为：**尺度/邻域口径 → loss/病例平衡 → 密度鲁棒性 → global-local 条件融合 → 最后才是宽度、block 数、dropout、激活函数微调**。

## 5. 建议的预处理改进

### 5.1 必须先做的基础加固

1. 新增 pipeline invariant test：`RᵀR`、`det(R)`、逆变换、`max_abs`、数组同长、ID 集合、坐标跨步一致性、stats split provenance。
2. QA gate 纳入 `roll_sign_reliable/origin_kind/main_axis_source`，先解决 3 个 included 左右轴病例。
3. 给每次 preprocess/stats 写入配置摘要或 hash；训练启动时核对 bundle version、split、stats provenance，防止历史 bundle/统计混用。
4. 多目标 stats 路径不存在时 fail-fast，不允许跨 target 静默回退。
5. Track B 先补 cell ID 对齐、裁剪同步和速度矢量随 `R` 旋转的端到端测试，再生成任何训练标签。

### 5.2 更可能提升可辨识性的特征/表示

在现有 `xyz + abscissa_norm + local_radius + curvature` 上，优先做可解释、可消融的特征：

- 共享毫米尺度坐标或显式 metric coordinate；
- `distance_to_flow_divider` 的 normalized + mm 双版本；
- 中心线局部坐标：轴向 `s`、归一化径向 `r/R`、周向 `sinθ/cosθ`；
- 局部切向/法向或稳定局部 frame（必须先过符号连续性 QA）；
- `radius_gradient`、分支/主干类别、到入口/出口的测地距离；
- 表面面积权重或近似 Voronoi 权重，用于采样和可选 area-weighted 指标；
- 可部署且确有病例差异的边界条件；当前审计显示入口流量模板基本相同，出口 RCR 属 oracle，必须明确部署边界。

不建议对 x/y/z 分别 z-score 或 PCA whitening 后直接作为 canonical 坐标，因为会破坏各向同性和解剖比例。曲率继续使用 train-only robust transform/clip；所有新增特征只用 train 统计标准化。
